# Icod.Terminal 1.22.0 release notes

This release adds acknowledged bounded composition between already known animation frames of one current persistent raster resource. `TerminalRasterAnimation.ComposeFrameAsync(...)` accepts opaque source and destination frame tokens, a zero-based `TerminalRasterSourceRectangle`, a destination pixel origin, and an alpha-blend or replacement mode. It does not create a frame or alter timing, selection, placement, or playback. Same-frame regions must not overlap.

The operation uses the existing serialized graphics transaction path. Invalid local geometry and foreign tokens fail before output. A correlated success confirms the mutation; a definite protocol rejection does not invent a new frame. `ENOENT` conservatively invalidates resource ownership because it may describe a missing image or frame. If output committed but the acknowledgement is lost, destination pixels are uncertain and callers must avoid blind replay; the known frame sequence remains locally known. `PersistentRasterAnimation` capability selection alone does not assert independent support for this composition command.

The animation sample demonstrates one bounded root-to-appended-frame replacement. On a fresh session it verifies persistent raster graphics, then attempts acknowledged animation operations; initially unknown animation support is not treated as a failed passive probe. The same composition step runs in a scripted-terminal test and in a fresh-package consumer on .NET 8, 9, and 10. The package consumer owns the choice of a two-by-two tile frame and leaves placement and presentation policy outside Terminal.

The production TermInfo dependency and optional Inspection integration move to `Icod.TermInfo 1.17.0`; `Icod.Timing 1.0.0` remains unchanged. The public API is additive to 1.21, with identical normalized snapshots across `net8.0`, `net9.0`, and `net10.0`. See [the API baseline](../Public-API-Baseline-1.22.md), [the ownership contract](../Persistent-Raster-Ownership.md), and [the compatibility policy](../Compatibility-and-Versioning.md).

The stable implementation candidate passed the nine-job Windows, Linux, macOS, package, and artifact matrix at `d589aca1a9146fe7b371885c5fe767c8264057e8`.
