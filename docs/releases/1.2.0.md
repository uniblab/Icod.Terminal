# Icod.Terminal 1.2.0

`Icod.Terminal 1.2.0` is the second additive minor release on the stable 1.x contract. It adds typed, bounded urxvt-style OSC 777 titled desktop notifications while preserving the existing OSC 9 notification API and all prior 1.x behavior.

## OSC 777 titled notifications

The new public operation is:

```csharp
ValueTask SendTitledNotificationAsync(
	string title,
	string message,
	CancellationToken cancellationToken = default
);
```

It emits:

```text
OSC 777 ; notify ; title ; message ST
```

using canonical ST termination and strict UTF-8.

The existing:

```csharp
ValueTask SendNotificationAsync(
	string message,
	CancellationToken cancellationToken = default
);
```

continues to emit legacy OSC 9. `Icod.Terminal` does not silently route between OSC 9 and OSC 777 and does not infer notification-protocol support from terminal identity.

## Validation and framing

OSC 777 title/body fields are semicolon delimited. Because the protocol does not define a broadly interoperable escape grammar for embedded semicolons, `Icod.Terminal` rejects semicolons rather than silently rewriting caller text.

Both fields:

- may be empty;
- must be well-formed Unicode;
- are encoded as strict UTF-8;
- reject C0, DEL, and C1 controls;
- are validated before output commitment.

The complete OSC payload is bounded to 4,096 encoded bytes, including the `777;notify;` prefix and field separator.

## Session behavior

OSC 777 participates in the normal `TerminalSession` shared output-serialization domain. The complete frame is encoded before waiting for the output gate. Caller cancellation is honored before commitment; once committed, the frame is written in one non-cancellable output write and is not implicitly flushed.

Known redirected/non-terminal output is rejected.

Successful completion proves only complete frame emission. Terminal/desktop/user policy may ignore or suppress the notification, including when the terminal window is focused.

## Security and privacy

Notification titles and bodies can leave the terminal window and appear in desktop notification services, notification history, lock screens, screen sharing, remote/multiplexed logs, or other OS/UI surfaces.

Publication is therefore explicit caller intent. `Icod.Terminal` does not:

- invent notifications from process/application state;
- read shell history or command output automatically;
- redact secrets heuristically;
- invoke host notification tools;
- add notification actions, IDs, activation callbacks, urgency, icons, or timeout semantics.

The release also does not expose a generic raw OSC 777 writer or arbitrary command-name dispatcher.

## Compatibility

`1.2.0` preserves the stable 1.0 compatibility floor and all intentional 1.1 additions. The only public API addition is `TerminalSession.SendTitledNotificationAsync(...)`.

The exact normalized cross-TFM public API fingerprint for 1.2 is:

```text
dabfaf0231743136a57d4f5632209e14d9c545638e3b8a08205ae5d14faaae26
```

The 1.0 and 1.1 baseline files remain retained unchanged as compatibility evidence.

The package continues to target:

```text
net8.0
net9.0
net10.0
```

and continues to depend on:

```text
Icod.TermInfo 1.10.0
Icod.Timing   1.0.0
```

The permanent compatibility rules remain in [`docs/Compatibility-and-Versioning.md`](../Compatibility-and-Versioning.md).

## Validation

The 1.2 validation program adds:

- byte-exact OSC 777 encoder/writer tests;
- strict UTF-8 and malformed-Unicode coverage;
- semicolon/control-character rejection coverage;
- exact encoded-byte payload-bound coverage;
- pre-cancelled and one-write/no-flush output tests;
- public `TerminalSession` ordering, redirected-output, and OSC 9 coexistence tests;
- fresh NuGet-only compile/runtime consumers on `net8.0`, `net9.0`, and `net10.0`;
- generated XML-documentation verification for `SendTitledNotificationAsync(...)`;
- the frozen machine public-API baseline above.

All retained 1.0/1.1, historical package, hardening, stable 1.x release-line, and current downstream compatibility gates continue to run.
