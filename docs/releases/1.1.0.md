# Icod.Terminal 1.1.0

`Icod.Terminal 1.1.0` is the first additive minor release on the stable 1.x contract. It adds typed, bounded VS Code OSC 633 shell integration without changing the meaning or ownership semantics of any existing 1.0 API.

## OSC 633 VS Code shell integration

OSC 633 is treated as a distinct vendor protocol family. It is not emitted by the existing OSC 133 methods and is not presented as a portable alias for OSC 133.

The new public `TerminalSession` operations are:

```csharp
ValueTask BeginVsCodePromptAsync(
	CancellationToken cancellationToken = default
);

ValueTask BeginVsCodeCommandInputAsync(
	CancellationToken cancellationToken = default
);

ValueTask BeginVsCodeCommandOutputAsync(
	CancellationToken cancellationToken = default
);

ValueTask FinishVsCodeCommandAsync(
	int exitCode,
	CancellationToken cancellationToken = default
);

ValueTask AbortVsCodeCommandAsync(
	CancellationToken cancellationToken = default
);

ValueTask PublishVsCodeCommandLineAsync(
	string commandLine,
	string? nonce = null,
	CancellationToken cancellationToken = default
);

ValueTask PublishVsCodeCurrentDirectoryAsync(
	string currentDirectory,
	string? nonce = null,
	CancellationToken cancellationToken = default
);

ValueTask PublishVsCodeIsWindowsAsync(
	bool isWindows,
	CancellationToken cancellationToken = default
);

ValueTask PublishVsCodeRichCommandDetectionAsync(
	bool hasRichCommandDetection,
	CancellationToken cancellationToken = default
);
```

The marker methods map to the documented VS Code shell-integration forms:

```text
A       prompt start
B       prompt end / command-input start
C       pre-execution / command-output start
D       status-less command finish / abort
D;n     command finish with signed decimal exit code
E;...   exact command-line publication
P;...   typed shell-integration properties
```

The public `P` surface is limited to the currently documented properties `Cwd`, `IsWindows`, and `HasRichCommandDetection`.

## Encoding and framing

OSC 633 frames use canonical ST termination:

```text
ESC ] 633 ; ... ESC \
```

Command-line and `Cwd` message values use the VS Code serialization rules:

- backslash is escaped as `\\`;
- semicolon is escaped as `\x3b`;
- ASCII U+0000 through U+0020 are escaped as lowercase `\xAB` byte values;
- other well-formed Unicode text is encoded as strict UTF-8.

The complete OSC payload is bounded to 65,536 bytes. Optional nonces are caller supplied, bounded, printable ASCII tokens and are never generated, discovered, or persisted by `Icod.Terminal`.

## Session and lifecycle behavior

OSC 633 operations use the normal `TerminalSession` output serialization domain. Arguments are validated and complete frames are encoded before waiting for the shared output gate where practical. Caller cancellation is honored before commit; a committed frame is written as one non-cancellable write and is not implicitly flushed.

OSC 633 is ephemeral shell-integration metadata. It adds no lifecycle participant, no restoration lease, no automatic replay after resume, and no synthetic completion during disposal.

Successful completion proves only that the frame was written to an interactive terminal output endpoint. `Icod.Terminal` does not infer VS Code support from `TERM`, environment variables, operating system, terminal brand, or version strings.

## Security and privacy

Command-line and current-directory publication are explicit caller actions. Both may disclose secrets, credentials, tokens, paths, host information, or other sensitive data. The library does not inspect process arguments, shell history, or the process current directory automatically, and it does not attempt heuristic secret redaction.

The optional nonce is transported only because the caller supplied it. The library does not claim that the nonce encrypts or makes the command line confidential.

The release deliberately does not expose:

- a public generic `WriteOsc633Async(...)` or arbitrary selector/property API;
- automatic shell/startup-file modification;
- automatic command-line or environment capture;
- the unfinalized `F` continuation marker;
- private/undocumented `EnvJson` publication.

## Compatibility

`1.1.0` preserves all existing stable 1.0 public members and documented behavioral guarantees. The new API is additive and is accompanied by an intentional 1.1 public-API baseline update; the 1.0 fingerprint remains retained as historical compatibility evidence.

The package continues to target:

```text
net8.0
net9.0
net10.0
```

and continues to depend on:

```text
Icod.TermInfo 1.10.0
Icod.Timing   1.0.0
```

## Validation

The 1.1 gate adds:

- byte-exact OSC 633 encoder/writer tests;
- exhaustive protocol-shape and escaping edge coverage;
- session output-ordering, cancellation, validation, and redirected-output tests;
- fresh NuGet-only compile/runtime consumers on `net8.0`, `net9.0`, and `net10.0`;
- generated XML-documentation checks for every new public method;
- an intentional machine public-API baseline update.

All retained 1.0, historical package, hardening, and current downstream compatibility gates continue to run.
