# Icod.Terminal 1.25.0-alpha.4

This prerelease corrects Primary Device Attributes (DA1) compatibility during
Kitty graphics verification. It includes the alpha.3 Unix byte-input correction,
alpha.2 Sixel write coalescing and alpha.1 cursor-planning correction.

## Kitty DA1 compatibility

Kitty 0.32.2 emits `CSI ?62;c`: a device code followed by an empty optional
attribute-list field. Terminal previously required a number in that field and
threw `FormatException` while completing its graphics-support probe, even when
the independently correlated Kitty graphics response had arrived. This caused
DCurses to select text fallback after reporting a raster-verification failure.

DA1 parsing now accepts exactly a numeric device code followed by one empty
optional attribute-list field and returns an empty attribute collection. The
rule applies to valid device codes generally; it does not recognize terminal
brands or infer graphics support from a device code. Kitty verification still
requires its separate correlated response, and Sixel requires its own evidence.

Shared CSI numeric parsing remains strict. Missing device codes, multiple or
interior empty fields, subparameters and oversized values are still rejected.
Cursor-position, secondary device-attribute, device-status and geometry response
validation is unchanged. Explicit numeric zero attributes remain explicit.

## Compatibility and verification

Public API and production dependencies are unchanged. Targets remain `net8.0`,
`net9.0`, and `net10.0` on Windows, Linux and macOS. See
[Compatibility and Versioning](../../Compatibility-and-Versioning.md).

Regression coverage exercises 7-bit and C1 DA1 responses through public queries,
ordinary graphics verification with and without a correlated Kitty response,
malformed-response rejection, and preservation of unrelated CSI validation.
The existing runtime and package qualification gates remain required.

After publication, update DCurses and repeat the WSL2/kitty frame and atlas
checks. This parser correction does not establish physical graphics acceptance
or independently resolve the earlier graphics payload-size report.

Merge, tag, GitHub release and NuGet publication remain maintainer actions.
