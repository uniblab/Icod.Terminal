# Icod.Terminal 1.3.0

`Icod.Terminal 1.3.0` is the third additive minor release on the stable 1.x contract. It adds a typed, bounded iTerm2 OSC 1337 shell-integration and semantic-history metadata surface while preserving all existing portable and vendor-specific APIs.

## Typed iTerm2 OSC 1337 shell integration

The new public operations are:

```csharp
ValueTask SetITerm2MarkAsync(
	CancellationToken cancellationToken = default
);

ValueTask PublishITerm2CurrentDirectoryAsync(
	string currentDirectory,
	CancellationToken cancellationToken = default
);

ValueTask PublishITerm2RemoteHostAsync(
	string userName,
	string hostName,
	CancellationToken cancellationToken = default
);

ValueTask SetITerm2UserVariableAsync(
	string name,
	string value,
	CancellationToken cancellationToken = default
);

ValueTask PublishITerm2ShellIntegrationVersionAsync(
	int version,
	string shellName,
	CancellationToken cancellationToken = default
);

ValueTask ClearITerm2CapturedOutputAsync(
	CancellationToken cancellationToken = default
);
```

They map to the reviewed iTerm2 OSC 1337 shell-integration/semantic-history forms:

```text
SetMark
CurrentDir=<path>
RemoteHost=<user>@<host>
SetUserVar=<name>=<base64-value>
ShellIntegrationVersion=<version>;shell=<shell>
ClearCapturedOutput
```

## Encoding and framing

The 1.3 OSC 1337 implementation uses:

- canonical ST termination;
- strict UTF-8;
- complete-frame prevalidation;
- a 65,536-byte complete OSC payload ceiling;
- bounded protocol-delimited fields;
- Base64 encoding for strict-UTF-8 user-variable values;
- shared `TerminalSession` output serialization;
- pre-commit caller cancellation and one non-cancellable committed frame write;
- no implicit flush.

Known redirected/non-terminal output is rejected.

## Portable-protocol relationship

OSC 1337 remains a separate iTerm2-specific namespace.

- OSC 7 remains the preferred portable current-location API.
- OSC 133 remains the portable prompt/command-region API.
- OSC 633 remains the typed VS Code shell-integration family.
- Calling an OSC 1337 method never silently emits OSC 7, OSC 133, or another fallback protocol.

The library does not infer iTerm2 support from terminal identity or environment variables.

## Security and privacy

The new metadata operations are explicit because they can disclose paths, user/host identity, shell identity/version, and application-provided user variables. `Icod.Terminal` does not automatically read process current directory, user name, host name, shell history, process arguments, environment variables, or shell startup files to populate these values.

Base64 user-variable encoding protects the OSC field grammar; it does not provide confidentiality.

`ClearITerm2CapturedOutputAsync(...)` is explicitly destructive to the current iTerm2 semantic-history captured-output record and is never emitted automatically.

## Deliberate OSC 1337 exclusions

OSC 1337 also contains commands with substantially broader host or terminal side effects. Version 1.3 does not expose a generic raw OSC 1337 writer or public operations for:

- profile switching or profile-property mutation;
- focus stealing;
- URL/browser opening;
- pasteboard access through OSC 1337;
- file upload/download or inline-file transfer;
- custom script control sequences;
- arbitrary color mutation already covered by typed color APIs;
- cursor-shape duplication;
- Unicode-version mutation;
- Touch Bar key-label state;
- arbitrary variable-reporting queries.

These operations require separate security/ownership contracts rather than admission through a generic vendor-command escape hatch.

## Compatibility

`1.3.0` preserves the stable 1.0 compatibility floor and all intentional 1.1 and 1.2 additions. The complete public API delta is exactly the six `TerminalSession` methods above.

The exact normalized cross-TFM public API fingerprint for 1.3 is:

