# Icod.Terminal 1.10.0-alpha.1

`1.10.0-alpha.1` begins the 1.10 semantic capability-inspection and planning release line.

This prerelease is a development checkpoint, not the final 1.10 release. The stable compatibility floor remains `1.0.0`.

## Included in this checkpoint

- removes duplicated exact `Icod.TermInfo` and `Icod.Timing` version assertions from active package verification;
- keeps direct runtime-dependency version declarations authoritative in `Icod.Terminal.csproj` rather than duplicating them throughout tests, samples, and tools;
- treats successful restore/build as dependency compatibility evidence;
- adds the C101 semantic capability vocabulary and API regret-gate design record;
- adds the first public, protocol-neutral capability planning value model;
- establishes a current 1.10 development API fingerprint while preserving the final 1.9 baseline unchanged.

## Public capability model

This checkpoint adds a deliberately curated `TerminalCapability` vocabulary for higher-level planning:

```text
ClipboardRead
ClipboardWrite
CursorStyle
SynchronizedOutput
KeyboardReporting
MouseReporting
FocusReporting
BracketedPaste
RasterGraphics
```

It also adds:

```text
TerminalCapabilitySupport
TerminalCapabilityEndpointAvailability
TerminalCapabilityEvidenceKind
TerminalCapabilityStatus
```

The model keeps support, endpoint availability, and evidence lifetime separate.

Public evidence is dependency- and protocol-neutral:

```text
None
StaticDescription
LiveObservation
```

It does not expose `Icod.TermInfo`, OSC, CSI, DCS, APC, concrete backends, routing scores, terminal brands, or raw capability names as public planning vocabulary.

## Not yet included

This checkpoint does not yet add the public `TerminalSession` inspection operation, live capability verification/preparation, or the later lifecycle/downstream/hardening closure work. Those remain C103 and later tranches in `Icod.Terminal-1.10.0-Development-Roadmap.md`.
