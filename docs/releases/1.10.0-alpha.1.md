# Icod.Terminal 1.10.0-alpha.1

`1.10.0-alpha.1` begins the 1.10 semantic capability-inspection and planning release line.

This prerelease is a development checkpoint, not the final 1.10 release. The stable compatibility floor remains `1.0.0`.

## Included in this checkpoint

- removes duplicated exact `Icod.TermInfo` and `Icod.Timing` version assertions from active package verification;
- keeps direct runtime-dependency version declarations authoritative in `Icod.Terminal.csproj` rather than duplicating them throughout tests, samples, and tools;
- treats successful restore/build as dependency compatibility evidence;
- adds the C101 semantic capability vocabulary and API regret-gate design record;
- adds the public, protocol-neutral capability planning value model;
- adds side-effect-free `TerminalSession.InspectCapability(...)` inspection;
- adds explicit bounded `TerminalSession.VerifyCapabilityAsync(...)` verification using only reviewed live probe paths;
- maintains a current 1.10 development API fingerprint while preserving the final 1.9 baseline unchanged.

## Public capability model

This checkpoint adds a deliberately curated `TerminalCapability` vocabulary for higher-level planning:

```text
ClipboardRead
ClipboardWrite
CursorStyle
SynchronizedOutput
KeyboardReporting
MouseReporting
FocusReporting
BracketedPaste
RasterGraphics
```

It also adds:

```text
TerminalCapabilitySupport
TerminalCapabilityEndpointAvailability
TerminalCapabilityEvidenceKind
TerminalCapabilityStatus
```

The model keeps support, endpoint availability, and evidence lifetime separate.

Public evidence is dependency- and protocol-neutral:

```text
None
StaticDescription
LiveObservation
```

It does not expose `Icod.TermInfo`, OSC, CSI, DCS, APC, concrete backends, routing scores, terminal brands, or raw capability names as public planning vocabulary.

## Session inspection and verification

`TerminalSession.InspectCapability(...)` is synchronous and side-effect free. It reports only the semantic capability knowledge already held by the session and does not emit terminal bytes or perform hidden live queries.

`TerminalSession.VerifyCapabilityAsync(...)` is explicit and bounded. It may strengthen the current answer only where `Icod.Terminal` already has a reviewed bounded support probe. The current verification path reuses the existing query coordinator and does not expose raw protocol or dependency-specific parameters.

Capabilities without an approved live support probe retain their current inspection result rather than causing speculative terminal traffic.
