# Icod.Terminal 1.25.0

Icod.Terminal 1.25.0 adds complete raster images to ordered screen-output
transactions and incorporates the input, cursor, parsing and transfer corrections
qualified during the 1.25 prereleases. It preserves the stable 1.0.0 compatibility
floor and every 1.24.1 public signature and enum value.

## Ordered complete raster output

`TerminalScreenOutputTransaction.WriteRaster(TerminalRasterImage image)` adds an
immutable image in caller-supplied order with semantic cursor plans and text.
Verify `TerminalCapability.RasterGraphics` before constructing the transaction.
Terminal prefers verified ordinary Kitty Graphics, then verified Sixel.
Persistent image identities are not required for this operation.

The transaction prepares and validates images against the 64 MiB aggregate
application-text and encoded-raster ceiling before output, then rechecks current
backend evidence and output epoch. It never probes while holding the output gate.
Null images fail when added; unavailable raster semantics, encoded overflow and
stale evidence fail before commitment. A committed transport failure is surfaced
with cleanup, without replay or automatic backend switching.

A successful return establishes local writes and flush, not physical rendering.
Callers own placement, current source pixels, full-frame repaint, text fallback
and resize policy. Plan a subsequent cursor move from an unknown position before
placing text. No portable clipping, scrolling, pixel placement, alpha-compositing
or atomic remote display is promised.

## Prerelease corrections included

- Excludes CR/LF-bearing relative cursor routes that can introduce host-dependent
  column drift; safe advertised relative/absolute alternatives remain available.
- Combines each prepared Sixel transaction image into one bounded transport write,
  reducing avoidable progressive redraw without promising physical atomicity.
- Reads interactive stdin as immediate bytes on Linux/macOS, avoiding the managed
  console line reader's Enter buffering and echo. Native mode ownership,
  cancellation, restoration and reopening remain explicit.
- Accepts a DA1 device code followed by an empty optional attribute list, including
  Kitty 0.32.2's `CSI ?62;c`, while preserving strict malformed-response rejection
  and independently correlated graphics evidence.
- Gives persistent resource uploads, animation appends and partial-frame edits a
  bounded size-aware allowance at 512 KiB/s plus a one-second ACK window, capped
  at one minute. Control-only transactions retain one-second deadlines.

## Known graphics limits and development hold

Further graphics development and Kitty live qualification are **on hold**.

In the maintainer's WSL2 / Ubuntu 24.04 / Kitty 0.32.2 test, the documented chunked
animation-frame final continuation creates a frame without returning its ACK.
The transfer deadline bounds the wait but does not fix the missing response.
Persistent ATLAS live acceptance remains deferred. The downstream DCurses default
sample falls back to ordinary FRAME; FRAME input/display work, with command-driven
flicker. Forced TEXT works. No Kitty identifier workaround is included.

Ordinary raster capability selection is separate from persistent ownership.
A failed Kitty write is not automatically replayed through Sixel, and Sixel does
not emulate persistent resources, placeholders or animation. Applications own
fallback and recovery from possibly committed errors.

Windows Terminal/Contour FRAME performance, help restoration, resize recovery and
exit observations were accepted on alpha.2; those observations do not establish
universally flicker-free output. Contour briefly retains an image strip during
active resize. Automated protocol fixtures do not prove live terminal rendering.

See [the graphics hold](../Graphics-Development-Hold.md) for the reproducer and
upstream bug-report evidence. Filing was blocked by HTTP 403; no Kitty issue was
created. Newer-Kitty/clean-config reproduction and animation-control ACK assumptions
remain unqualified. These are disclosed limitations, not resolved bugs.

## Compatibility and validation

Targets: `net8.0`, `net9.0`, `net10.0` on Windows, Linux and macOS.
Production dependencies remain `Icod.TermInfo 1.17.0` and `Icod.Timing 1.0.0`;
optional Inspection is outside the production graph. No new dependency or runtime
change is introduced by stable promotion.

The sole additive 1.25 API is `WriteRaster(TerminalRasterImage)`; the frozen
cross-framework fingerprint is
`886a617d961af7eed37feaed026d83bbf06ec508ba248a4ca492baaf7e528146`.
The exact stable-source runtime, API, XML, fresh-package consumer and downstream
qualification is recorded in [PR #78](https://github.com/uniblab/Icod.Terminal/pull/78)
and [the closure record](../T2508-1.25-Stable-Source-Closure.md).

See [Compatibility and Versioning](../Compatibility-and-Versioning.md),
[the API baseline](../Public-API-Baseline-1.25.md),
[screen-output guidance](../Screen-Output.md) and
[the changelog](../../CHANGELOG.md). No consumer migration is required for the
additive member; applications should continue to handle capability and lifecycle
uncertainty under their existing policies.
