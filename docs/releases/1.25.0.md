# Icod.Terminal 1.25.0 Release Candidate Notes

**Status:** Alpha implementation in [PR #71](https://github.com/uniblab/Icod.Terminal/pull/71). Stable qualification, merge, tag, GitHub release, and NuGet publication remain separate.

## Ordered complete raster output

`TerminalScreenOutputTransaction.WriteRaster(TerminalRasterImage image)` adds one immutable, complete raster to the existing one-shot screen transaction. The caller may place semantic cursor plans and application text before or after it. The selected ordinary `RasterGraphics` backend is Kitty Graphics when currently verified, otherwise Sixel when currently verified. Persistent Kitty support and persistent image identity are independent and are not needed for this operation.

Call `await session.VerifyCapabilityAsync(TerminalCapability.RasterGraphics)` before creating a raster transaction. A transaction never probes while holding the output gate. It prepares and validates every image, including framing, against the 64 MiB aggregate application-text plus encoded-raster ceiling before any output. A null image fails when added; an unavailable verified backend or unsupported image semantics fail before output. A changed capability generation/backend or stale session output epoch rejects commitment before its first byte.

Every raster transfer is written in item order under the existing output lease. Once writing starts, cancellation cannot split a frame. A transport failure attempts normal transaction cleanup/flush, reports the failure, and never retries or silently switches backend. A successful return reports local writes and flush only; it cannot prove physical rendering. No backend-independent cursor, pixel placement, clipping, scrolling, alpha compositing, or cell geometry is promised after display. Plan a subsequent cursor move from an unknown position before placing text.

The sample submits a complete RGB24 image after capability verification. DCurses owns its frame buffer, layout, resize/repaint policy, overlay, and text fallback; Terminal owns only the verified protocol transfer and transaction serialization. Sixel physical alignment and resize behavior require a separate real-terminal witness.

The intended additive public API fingerprint is `886a617d961af7eed37feaed026d83bbf06ec508ba248a4ca492baaf7e528146` across net8.0/net9.0/net10.0. Production dependencies remain `Icod.TermInfo 1.17.0` and `Icod.Timing 1.0.0`; the stable 1.0 compatibility floor remains in force.
