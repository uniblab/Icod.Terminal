# Icod.Terminal 1.28.0-alpha.1 Release Notes

**Status:** Development prerelease implementing the approved published-spec Kitty
Graphics transaction work. Publication and live support are not implied;
exact-head closure, live qualification, merge, tag, GitHub release, and NuGet
publication remain separately gated.

## Mutation-confirmation contract

This alpha establishes an additive vocabulary for successful terminal mutations:

- `Unspecified` preserves the behavior of existing local/native mutations and the
  existing public `TerminalControlMutationResult.Success()` factory;
- `OutputCommitted` means the complete command crossed Terminal's serialized
  write and flush boundary without claiming a correlated protocol response; and
- `ProtocolAcknowledged` means Terminal parsed a correlated protocol success
  response for the owning mutation.

`Succeeded` remains status-based. Existing animation method return types remain
unchanged, including the opaque frame token returned by an acknowledged
`AddFrameAsync` transfer. Failed, unsupported, and unavailable results carry
`Unspecified`.

The action-specific policy is:

- frame transfer and regional edit (`a=f`) retain a required correlated response;
  successful completion is `ProtocolAcknowledged`, while committed silence is
  ambiguous and an append publishes no frame token;
- timing, selection, stop, loading, and playback (`a=a`) use `q=2`, install no
  success waiter, and report `OutputCommitted` after the complete serialized write
  and flush; and
- composition (`a=c`) keeps the default response level, reports correlated `OK`
  as `ProtocolAcknowledged`, reports correlated error definitively, and reports
  bounded committed silence as `OutputCommitted` without protocol evidence.

Kitty 0.49.2 loses response identity on the documented final multi-chunk `a=f`
continuation. Icod.Terminal preserves that published grammar and records the
result as an exact implementation deviation; it does not repeat the private image
id as a workaround or branch on terminal name/version. The upstream correction
postdates 0.49.2 and remains a separate live-qualification target.

Bounded late-response ownership, lifecycle revalidation, generation-scoped
evidence, sequence/pixel uncertainty, deterministic cleanup, and the no-blind-retry
rule remain in force. `OutputCommitted` and `ProtocolAcknowledged` do not claim
visible rendering or remote atomicity.

## Sample and evidence

The raster-animation sample prints operation, status, successful confirmation,
fallback reason, and cleanup without exposing private ids. Its
`--headless-transcript` mode opens no terminal and leaves live rendering `NotRun`.
The existing two-frame tile witness remains caller-owned policy assembled from
public primitives, not a Terminal-owned atlas API.

The [1.28 transaction compatibility record](../Kitty-Graphics-Transaction-Compatibility-1.28.md)
pins the protocol source, Kitty 0.49.2 deviation, post-release fix commit, action
matrix, evidence lanes, and required live-report provenance. Live Kitty and
downstream Icod.DCurses ATLAS results remain separately gated.

## Compatibility

The package continues to target .NET 8, 9, and 10 on managed Windows, Linux, and
macOS. Production dependencies remain `Icod.TermInfo 1.17.0` and
`Icod.Timing 1.0.0`; the stable 1.x compatibility floor and all existing public
enum values remain unchanged.

The additive API snapshot is byte-identical across all three target frameworks at
SHA-256 `0cad933938bf9d52ecd568323f05fdc9079597e6ed3029755a74fffead7c0fcc`;
see the [1.28 public API baseline](../Public-API-Baseline-1.28.md).
