# Icod.Terminal 1.8.0

`Icod.Terminal 1.8.0` is the APC/Kitty Graphics and multi-backend raster-routing release for the stable 1.x line.

It builds directly on the 1.5 control-language normalization, 1.6 complete-CSI foundation, and 1.7 DCS/Sixel raster implementation. The public raster contract introduced in 1.7 remains the compatibility anchor; 1.8 adds a second internal backend beneath that semantic API.

## Initial 1.8 contract

The common caller-facing operation remains:

```text
TerminalSession.DisplayRasterAsync(...)
```

with the existing `TerminalRasterImage`, `TerminalRasterColor`, and `TerminalRasterPixelFormat` types.

Kitty Graphics is implemented as an APC dialect rather than as a new public graphics abstraction. Initial 1.8 work prefers direct raw pixel transmission (`t=d`) using RGB24 or RGBA32 data and protocol-defined Base64 chunking. Indexed8 input is adapted internally to a Kitty-supported raw representation.

The initial release deliberately excludes file, temporary-file, and shared-memory transmission, image-file decoding, persistent image/placement ownership, z-order, Unicode placeholders, deletion, and animation until those features receive separate semantic/security review.

## Capability and routing policy

Kitty Graphics support is established through the protocol-defined query/barrier mechanism rather than terminal identity. The intended probe combines a Kitty query APC with a following Primary DA CSI request. A correlated Kitty response provides positive protocol evidence; a Primary DA barrier arriving first can provide reviewed negative evidence for the concrete Kitty backend. Silence alone remains unknown.

Once both raster backends exist, routing remains evidence-driven:

```text
RasterGraphics
    -> verified Kitty Graphics / APC
    -> verified Sixel / DCS
```

No backend retry occurs after a graphics transfer has committed bytes and then failed.

## Compatibility

Version 1.8 retains the stable `1.0.0` compatibility floor and the 1.7 public raster API. The current 1.7 public API fingerprint remains the expected baseline unless a later 1.8 tranche demonstrates a necessary, reviewed, additive public change.

The package continues to target:

```text
net8.0
net9.0
net10.0
```

and retains the dependency floor:

```text
Icod.TermInfo 1.10.0
Icod.Timing   1.0.0
```
