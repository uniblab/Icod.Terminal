# Icod.Terminal 1.8.0

`Icod.Terminal 1.8.0` is the APC/Kitty Graphics and multi-backend raster-routing release for the stable 1.x line.

It builds directly on the 1.5 control-language normalization, 1.6 complete-CSI foundation, and 1.7 DCS/Sixel raster implementation. The public raster contract introduced in 1.7 remains unchanged; 1.8 adds Kitty Graphics as a second internal backend beneath that semantic API.

## What changed

The public caller-facing operation remains:

```text
TerminalSession.DisplayRasterAsync(...)
```

with the existing:

```text
TerminalRasterPixelFormat
TerminalRasterColor
TerminalRasterImage
```

Version 1.8 now routes that semantic operation through two verified backends:

```text
RasterGraphics
    -> verified Kitty Graphics / APC
    -> verified Sixel / DCS
```

Verified Kitty Graphics is preferred. Verified Sixel remains the fallback. Backend selection is internal and evidence-driven; callers do not construct APC/DCS graphics strings or select a protocol backend directly.

## APC and Kitty Graphics foundation

A180 adds the internal canonical bounded APC writer. Canonical library output uses seven-bit framing:

```text
ESC _ <application payload> ESC \
```

The APC layer is deliberately dialect-neutral. Kitty-specific `G...` syntax is implemented above it rather than being baked into generic APC framing.

A181 adds the reviewed Kitty Graphics control-data and response grammar used by common raster display and capability probing. Generated fields have deterministic ordering, numeric fields are bounded, duplicate/invalid control data is rejected, and correlated replies are parsed through typed Kitty response semantics rather than a public arbitrary key/value dictionary.

No generic public APC or Kitty Graphics writer is introduced.

## Raw raster adaptation

A182 maps the public raster formats to Kitty's direct raw representations:

```text
Rgb24    -> f=24, byte-exact RGB
Rgba32   -> f=32, byte-exact RGBA
Indexed8 -> RGB24 when every referenced palette color is opaque
            otherwise RGBA32 preserving palette alpha
```

The conversion preserves byte values and straight alpha. There is no hidden matte/background composition, gamma transformation, or image-file transcoding.

Fractional alpha (`1..254`) is therefore preserved when Kitty Graphics is used. The common raster model remains more expressive than Sixel; when only Sixel can be selected, fractional alpha still returns controlled unsupported rather than being silently flattened.

## Direct Base64 chunking

A183 implements lazy direct-transfer encoding for Kitty Graphics. Raw raster bytes are Base64 encoded into deterministic payload chunks whose encoded image-data portion never exceeds 4096 bytes.

Non-final chunks use the protocol continuation flag and the final chunk closes the logical transfer. Large images do not require one complete Base64-image allocation.

Initial 1.8 Kitty support is deliberately limited to direct transmission (`t=d`). The release does not introduce hidden file, temporary-file, or shared-memory graphics transport merely for performance.

## Committed multi-frame output

A184 treats the complete Kitty direct transfer as one logical session-output transaction even though the protocol uses multiple independently terminated APC frames.

The existing session output gate is held from the first committed APC frame through the final frame and flush. Caller cancellation is honored before commitment. After the first frame has committed, ordinary caller cancellation cannot intentionally strand an incomplete multi-chunk image.

Transport failure after commitment is surfaced to the caller. The library does not replay the failed transfer, retry an uncertain frame, switch to Sixel after partial Kitty output, or guess how much terminal-side state was applied.

Session teardown waits for a committed graphics transfer before output-state restoration proceeds.

## Live capability evidence

A185 integrates the protocol-defined Kitty Graphics support probe with the existing authoritative input/query architecture. The support test sends a correlated one-pixel Kitty query followed by Primary Device Attributes as a synchronization barrier.

Evidence semantics are explicit:

- a correlated Kitty response verifies `ApcKittyGraphics` support;
- Primary DA arriving first supplies reviewed negative protocol-response evidence for this concrete backend;
- silence/timeout without an authoritative response remains unknown;
- cancellation does not manufacture negative evidence;
- terminal brand, `TERM`, OS identity, environment variables, and caller preference are not capability proof.

The probe creates no second input reader.

## Multi-backend routing

A186 connects `DisplayRasterAsync(...)` to both available graphics backends while preserving the public 1.7 operation.

When both backends are verified, Kitty Graphics is preferred. When Kitty is unsupported or remains unverified and Sixel is verified, Sixel remains usable. When evidence is unresolved, bounded probing occurs in deterministic order.

Fallback is only a pre-commit routing decision. A committed failure on one backend is never silently converted into a retry on another backend.

## Raster semantic parity

A187 freezes the common semantic boundary across Kitty Graphics and Sixel:

- raster width/height remain intrinsic source pixel dimensions;
- Kitty preserves fractional alpha while Sixel reports controlled unsupported for it;
- all-transparent input has defined backend-specific handling without inventing opaque pixels;
- 1.8 does not promise backend-neutral placement, scaling, clipping, persistent image identity, z-order, source rectangles, Unicode placeholders, deletion, or animation;
- no new cursor-normalization control is exposed;
- the existing internal terminal/cell pixel geometry substrate is not promoted into a new public graphics-placement API.

This keeps the public raster model stable rather than forcing Kitty-specific concepts into it prematurely.

## APC/Kitty hardening

A188 qualifies the live APC/Kitty path under hostile framing and fragmentation.

The hardening includes:

- successful seven-bit and accepted eight-bit APC replies at every meaningful read split point;
- strict ownership of correlated responses interrupted by CAN/SUB or malformed termination;
- the existing 4096-byte normal response-frame ceiling retained for Kitty replies;
- bounded draining of an oversized correlated APC through string termination before normal response routing resumes;
- a correlated but unterminated response treated as malformed instead of being mislabeled as mere silence;
- unrelated APC/OSC/DCS/CSI traffic prevented from satisfying the active Kitty probe;
- late Kitty traffic prevented from corrupting a subsequent CSI query;
- deterministic expiration of generation-scoped live Kitty evidence.

The resulting security rule is: **correlation grants bounded transaction ownership; it does not grant trust.**

## Resource bounds

The public raster bounds introduced in 1.7 remain unchanged:

```text
maximum dimension          16,384
maximum pixels             16 Mi
maximum owned pixel data   64 MiB
maximum indexed palette    256 entries
```

Relevant protocol bounds include:

```text
normal terminal response frame       4,096 bytes
Kitty Base64 payload per APC chunk    4,096 bytes
small complete APC frame              8,192 bytes
```

The Kitty implementation remains streaming/bounded and does not allocate one complete encoded transfer for large raster input.

## Compatibility

Version 1.8 adds **no public API**. The authoritative public baseline remains the 1.7 raster baseline and fingerprint:

```text
847441fb4a8cdc89979aca9e96178f939895b93ec19a973232210af09716f700
```

The current baseline files remain:

```text
docs/Public-API-Baseline-1.7.md
docs/Public-API-Baseline-1.7.sha256
```

No redundant 1.8 baseline is created because there is no public-surface delta.

The stable `1.0.0` compatibility floor remains in force. Existing 1.0–1.7 public members, enum values, query ownership, restoration/lifecycle behavior, security semantics, Sixel behavior, and package contracts remain compatible.

The permanent compatibility authority is `docs/Compatibility-and-Versioning.md`.

The package continues to target:

```text
net8.0
net9.0
net10.0
```

and retains:

```text
Icod.TermInfo 1.10.0
Icod.Timing   1.0.0
```

## Deliberate exclusions

Version 1.8 does not expose or implement as part of the common raster contract:

- generic public APC construction;
- generic public Kitty Graphics key/value dispatch;
- explicit public Kitty/Sixel backend selection;
- file (`t=f`), temporary-file (`t=t`), or shared-memory (`t=s`) Kitty transfer;
- PNG/JPEG/GIF decoding or transcoding;
- persistent image or placement ownership;
- arbitrary source rectangles;
- z-order/layering;
- Unicode placeholder placement;
- deletion or animation APIs;
- backend-neutral scaling/placement options that have not been separately specified;
- terminal-brand automatic activation.
