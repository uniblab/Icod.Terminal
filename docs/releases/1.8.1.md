# Icod.Terminal 1.8.1

`Icod.Terminal 1.8.1` is a maintenance release for the stable 1.8 line. It does not add a terminal protocol, public API, package dependency, or new runtime semantic contract. The release focuses on making the repository and package documentation accurately reflect the published 1.8 state and on giving consumers better executable examples of the existing public surface.

## What changed

### Documentation polish

- Corrects stale wording which still described `1.8.0` as being in A189 pre-merge/release qualification after the release had already been merged, tagged, and published.
- Reworks the root README into a concise consumer/contributor entry point instead of duplicating the development qualification diary.
- Reworks the current development roadmap so it distinguishes the published `1.8.0` result, the `1.8.1` maintenance line, and candidate future development tracks.
- Reorganizes `samples/README.md` around consumer goals and adds an at-a-glance guide for choosing an example.

### Sample coverage

`1.8.1` adds two focused sample applications using only released public APIs:

- `Icod.Terminal.RasterGraphics.Sample` — generates an RGB24 raster in memory and calls the backend-neutral `DisplayRasterAsync(...)` API. It does not select Sixel or Kitty Graphics, emit raw DCS/APC traffic, inspect terminal branding, load image files, or introduce an image-decoder dependency.
- `Icod.Terminal.VsCodeShellIntegration.Sample` — demonstrates the typed VS Code OSC 633 shell-integration surface, including rich-command-detection metadata, current-directory publication, prompt/input/output boundaries, explicit command-line publication, and successful command completion.

The raster sample closes the most visible sample gap left after the 1.7 Sixel and 1.8 Kitty Graphics releases. The VS Code sample brings OSC 633 coverage in line with the already-focused OSC 133 and iTerm2 OSC 1337 examples.

Both samples are restored and built on `net8.0`, `net9.0`, and `net10.0` during repository validation.

## Compatibility

No public API change is intended in `1.8.1`.

The authoritative current public API fingerprint remains the 1.7/1.8 value:

```text
847441fb4a8cdc89979aca9e96178f939895b93ec19a973232210af09716f700
```

The release retains:

- the stable `1.0.0` compatibility floor;
- `net8.0`, `net9.0`, and `net10.0`;
- `Icod.TermInfo 1.10.0`;
- `Icod.Timing 1.0.0`;
- one authoritative terminal input reader;
- existing query/correlation/resource bounds;
- existing reversible-state and lifecycle semantics;
- the 1.7/1.8 backend-neutral raster contract and verified Kitty/Sixel routing behavior.

## Security and behavior boundaries

The new samples do not widen the runtime security surface.

- The raster sample generates pixels locally and uses the existing semantic raster API. It does not decode files or use hidden filesystem/shared-memory graphics transports.
- The VS Code sample requires metadata to be supplied explicitly and warns that paths and command lines may contain sensitive information. It does not inspect process state, shell history, environment variables, or the process current directory automatically.
- Successful sample execution proves that the relevant Icod.Terminal operation completed according to its documented contract; it does not imply that a terminal necessarily rendered a raster or recognized vendor-specific metadata unless the underlying protocol supplies explicit evidence.
