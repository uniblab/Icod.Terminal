# Icod.Terminal 1.29.0-alpha.1

This development candidate adds bounded, opt-in larger OSC 52 clipboard transfers.

- `TerminalSessionOptions.ClipboardOptions` supplies independent, immutable read
  and write budgets. Defaults remain 65,536 decoded bytes; each budget accepts
  1 through 16,777,216 bytes, inclusive.
- Text is counted in strict UTF-8 bytes. Oversized writes fail before output;
  direct base64 encoding avoids an intermediate encoded string. Existing write
  ordering and post-commit cancellation semantics remain unchanged.
- Explicit larger reads use a lazily grown, query-owned accumulator after exact
  selection-prefix correlation. Ordinary input and unrelated protocol limits stay
  unchanged. Malformed and oversized replies never return partial results.
- Bounded terminator recovery preserves trailing input. Unresolved recovery or
  expired late ownership fails the input coordinator closed instead of decoding
  the rest of a correlated clipboard string as keys.
- Samples require explicit clipboard actions, support generated fixtures and
  independent limits, and report counts rather than clipboard contents. The
  compatibility sample adds a consented 131,072-byte round-trip scenario.
- Fresh-package smoke checks exercise defaults and separate 1 MiB read/write
  budgets using public APIs on .NET 8, 9 and 10. Production dependencies are unchanged.

These are local resource budgets. OSC 52 has no standard capacity negotiation or
write acknowledgement; emission does not establish remote acceptance. Query
timeout does not establish unsupported functionality. Applications own internal
clipboard fallback and user messaging.

See the [usage guide](../Clipboard-Transfers.md), [API baseline](../Public-API-Baseline-1.29.md),
and [qualification record](../Clipboard-Transfer-Qualification-1.29.md).
Live clipboard environments remain NotRun until exact observations are supplied.
Stable promotion, merge, tagging and publication remain maintainer actions.
