# Icod.Terminal 1.23.0 Release Notes

**Status:** Implementation candidate in PR #68. Merge, tag, release, and package publication remain maintainer actions.

## Partial animation frame replacement

`TerminalRasterAnimation.UpdateFrameRegionAsync(...)` replaces a bounded rectangle in one known frame from immutable caller-owned RGB24 or RGBA32 pixels. It creates no frame token, retains no pixel or delta cache, and shares the existing animation output gate and correlated acknowledgement path.

Invalid formats, geometry, ownership, disposal, stale generation, and precommit cancellation fail before bytes. Definite rejection preserves known frame ownership; `ENOENT` invalidates the resource conservatively. If output commits but acknowledgement is lost, exact affected pixels are uncertain and callers should recreate the resource before retrying.

## Rich-input completion

The current Kitty phase-bearing legacy numeric set now includes Menu (`CSI 29;modifier:phase ~`) with press, repeat, release, and modifier identity. A consumed malformed modern-keyboard frame at end of input now recovers as `EndOfInput` instead of reaching fallback with an empty buffer. Existing CSI-u, traditional terminfo, focus, bracketed paste, mouse, one-reader routing, and reversible lease behavior remain unchanged.

## Compatibility and qualification

- Existing public enum values and 1.0 compatibility floor are preserved.
- The only public API addition is `UpdateFrameRegionAsync(...)`; normalized .NET 8/9/10 API fingerprint: `47ce550ebe58219a46bb711b789608592c3cad34c3c3607ffc7aaf054c8c5358`.
- Production dependencies remain `Icod.TermInfo 1.17.0` and `Icod.Timing 1.0.0`; Inspection remains outside the production graph.
- Samples and fresh-package consumers exercise partial replacement, frame composition, negotiated rich input, fallback, cleanup, and privacy guidance.
- Physical-terminal behavior is not claimed without direct observation.
