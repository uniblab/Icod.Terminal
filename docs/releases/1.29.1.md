# Icod.Terminal 1.29.1

This patch repairs input problems exposed by the Icod.Widgets menu gallery.
Legacy Alt+F now arrives as one Alt-modified character. The same rule preserves
fragmented non-control Unicode Alt characters. Windows console input
uses `ReadConsoleW` so Ctrl+Z remains a control key on hosts where `ReadFile`
interprets it as end-of-input, even in raw mode.

## Input behavior

Known terminfo keys and control-family introducers retain their existing decoding
and recovery paths. A valid non-control UTF-8 scalar following Escape within the
configured ambiguity interval becomes one `TerminalKey.Character` event with
the Alt modifier. An isolated Escape still resolves after the bounded interval.

The default Windows session opens a separate owned `CONIN$` handle. `ReadConsoleW`
provides UTF-16 input, which the transport incrementally converts to UTF-8 for
the shared decoder. Ctrl+Z therefore remains data rather than end-of-input, and
surrogate pairs remain intact across native reads and small caller buffers.

Applications can intercept both Ctrl+C and Ctrl+Z by opening the session with
`TerminalInputMode.Raw` and handling their Control-modified Character events
through `ReadEventAsync(...)`. `CBreak` continues to preserve host signal and
processed-input behavior. This input-mode contract is unchanged; 1.29.1 repairs
the Windows transport so Ctrl+Z can satisfy it reliably.

## Ownership and compatibility

The reader preserves Unicode across native read boundaries and owns a separate
console handle. Cancellation waits for the native read to finish before closing
the handle. Process input/output encodings are not changed.

No public APIs or production dependencies change. Targets remain `net8.0`, `net9.0`, and `net10.0`.
See [compatibility policy](../Compatibility-and-Versioning.md).
Existing clipboard budgets and keyboard protocol reporting remain available.
Ambiguous control-family introducers retain their existing sequence behavior.

## Validation

Decoder and transport tests cover fragmented Alt input, standalone Escape,
control sequences, Ctrl+Z, small UTF-8 buffers, split surrogate pairs,
cancellation, reuse, and disposal. The PR Windows job runs an isolated native
console smoke with injected key records through the real session reader.

The Rich Input sample now uses raw input and prompts a fallback Alt+F check plus
Ctrl+C/Ctrl+Z-followed-by-input checks. Linux and macOS PTY smokes verify both
control shortcuts in raw mode; the isolated native Windows smoke verifies them
through the real Windows session reader.

After publishing, the Widgets/DCurses dependency chain must consume this patch
before the Widgets gallery's physical Alt+F and Windows Ctrl+Z retest.
