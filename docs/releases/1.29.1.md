# Icod.Terminal 1.29.1

This patch repairs input problems exposed by the Icod.Widgets menu gallery.
Legacy Alt+F now arrives as one Alt-modified character. Windows console input
uses `ReadConsoleW` so Ctrl+Z remains a control key on hosts where `ReadFile`
interprets it as end-of-input, even in raw mode.

The reader preserves Unicode across native read boundaries and owns a separate
console handle. Cancellation waits for the native read to finish before closing
the handle. Process input/output encodings are not changed.

No public APIs or production dependencies change. Targets remain `net8.0`, `net9.0`, and `net10.0`.
See [compatibility policy](../Compatibility-and-Versioning.md).
Existing clipboard budgets and keyboard protocol reporting remain available.
Ambiguous control-family introducers retain their existing sequence behavior.

## Validation

Decoder and transport tests cover fragmented Alt input, standalone Escape,
control sequences, Ctrl+Z, small UTF-8 buffers, split surrogate pairs,
cancellation, reuse, and disposal. The PR Windows job runs an isolated native
console smoke with injected key records through the real session reader.

After publishing, the Widgets/DCurses dependency chain must consume this patch
before the Widgets gallery's physical Alt+F and Windows Ctrl+Z retest.
