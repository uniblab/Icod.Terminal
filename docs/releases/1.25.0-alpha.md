# Icod.Terminal 1.25.0-alpha Release Notes

**Status:** Prerelease for downstream integration and terminal testing. This alpha adds immediate raster output to screen transactions; stable 1.25.0 qualification is still in progress.

## Ordered raster output

`TerminalScreenOutputTransaction.WriteRaster(TerminalRasterImage image)` adds a complete immutable image to the same ordered commit as semantic cursor plans, application text, hyperlinks, and raster placeholder cells. Call `VerifyCapabilityAsync(TerminalCapability.RasterGraphics)` before constructing the transaction. Terminal prefers current verified ordinary Kitty Graphics evidence and uses verified Sixel when Kitty is unavailable. Persistent Kitty image identity is a separate capability and is not required for this operation.

All raster payloads are encoded and validated before transaction output. Application text and encoded raster frames, including APC/DCS framing, share the existing 64 MiB transaction ceiling. Commit rechecks backend evidence and the session output epoch before writing. Missing verified support, unsupported image semantics, and encoded overflow reject the transaction before its first byte.

Once writing starts, the transaction preserves output order under one session lease. Cancellation does not intentionally truncate a committed raster object. Transport failures propagate through the existing cleanup and flush handling; Terminal does not retry a partially written raster or switch graphics backend after output begins. Success reports local writes and flush, not physical display acknowledgement.

## Compatibility and migration

This is an additive API change. Existing 1.24.1 public signatures, enum values, and `DisplayRasterAsync` behavior remain available, with the stable 1.0 compatibility floor preserved. The package targets .NET 8, 9, and 10 on Windows, Linux, and macOS. Production dependencies remain `Icod.TermInfo 1.17.0` and `Icod.Timing 1.0.0`.

DCurses consumers must explicitly integrate the new transaction item to enable full-frame raster fallback. Updating a package reference alone does not activate that rendering path. DCurses and applications retain ownership of complete frame pixels, placement, clipping, overlays, repaint, resize recovery, and text fallback. Plan a subsequent cursor movement from an unknown position before positioning text after raster output.

## Known limitations

- The current sample uses absolute positions on the main screen and can overwrite earlier prompt text. Sample presentation cleanup remains open.
- DCurses full-frame fallback integration and its resize, scrolling, alignment, overlay, and exit checks remain open.
- No portable graphics clipping, post-raster cursor position, scaling, alpha compositing, or physical display acknowledgement is promised.
- Sixel does not gain persistent resources, placeholders, animation-frame updates, or hidden replay through this API.
