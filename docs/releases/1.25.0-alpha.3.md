# Icod.Terminal 1.25.0-alpha.3

This prerelease corrects process-standard-input handling on Linux and macOS.
It includes alpha.1 newline-safe cursor planning and alpha.2 bounded Sixel
screen-write coalescing.

## Immediate Unix input

The default session previously adapted `Console.OpenStandardInput()` as a byte
stream. On interactive Unix terminals, .NET routes that stream through its own
line reader. Consequently, keys waited for Enter, typed characters were echoed
over application output, and terminal responses could be interpreted as keyboard
input before reaching Terminal's protocol decoder.

The default Linux/macOS session now owns a separate nonblocking descriptor for
the terminal observed on stdin. Bytes go directly to the existing decoder,
without managed line editing, character conversion, or echo. Empty nonblocking
reads wait asynchronously with cancellation and a bounded polling interval.
The existing native mode policy still controls Canonical/CBreak/Raw and echo.
The process stdin descriptor is neither closed nor switched to nonblocking mode.
Session disposal and initialization failure release the owned descriptor.

## Compatibility and verification

No public API or dependency changes are introduced. The Windows default input
path and caller-supplied borrowed input/output services retain their contracts.
Private POSIX I/O supports both Linux and macOS; it is not a terminal-brand
workaround. Targets remain .NET 8, 9, and 10.

A real pseudo-terminal regression exercises the process-standard-input overload
on Linux and macOS: keys without Enter, fragmented UTF-8, exact query responses,
no unwanted echo, cancelled waits, restored terminal modes, and reopening after
a pending read. Existing runtime and package qualification also remain required.

After publication, update DCurses and repeat the WSL2/kitty text and raster
checks. Automated pseudo-terminal acceptance does not establish physical kitty
rendering acceptance or independently resolve the previously logged graphics
parser errors.

Merge, tag, GitHub release, and NuGet publication remain maintainer actions.
