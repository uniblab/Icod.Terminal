# Icod.Terminal 1.4.0

`Icod.Terminal 1.4.0` is the fourth additive minor release on the stable 1.x contract. It adds typed, bounded Kitty OSC 99 desktop notifications while preserving the legacy OSC 9 path, the OSC 777 titled-notification path, and every prior 1.x semantic/ownership contract.

## Kitty OSC 99 notifications

The primary new operation is:

```csharp
ValueTask SendKittyNotificationAsync(
	string title,
	string body = "",
	KittyNotificationOptions? options = null,
	CancellationToken cancellationToken = default
);
```

`KittyNotificationOptions` provides typed control over:

- stable notification IDs and update/replacement semantics;
- application name and notification-type filtering metadata;
- activation focus suppression;
- display occasion (`Always`, `Unfocused`, `Invisible`);
- urgency (`Low`, `Normal`, `Critical`);
- expiration policy;
- sound name;
- ordered icon names;
- bounded PNG/JPEG/GIF icon transfer and cache identifiers.

An identified notification can be explicitly closed with:

```csharp
ValueTask CloseKittyNotificationAsync(
	string identifier,
	CancellationToken cancellationToken = default
);
```

The existing:

```csharp
SendNotificationAsync(...)
SendTitledNotificationAsync(...)
```

continue to emit OSC 9 and OSC 777 respectively. The library does not silently select, negotiate, or fall back among the three protocols.

## Encoding and chunking

Kitty OSC 99 uses:

```text
OSC 99 ; metadata ; payload ST
```

Version 1.4 uses canonical ST termination.

Title/body text is encoded as strict UTF-8 and then RFC 4648 Base64 with Kitty `e=1`. This allows arbitrary well-formed Unicode to remain data rather than raw OSC control bytes.

Large payloads are automatically split into Kitty-compatible chunks. Each encoded payload chunk is at most 4,096 bytes. Multi-frame requests use `d=0` until the final `d=1` frame and share an identifier so the terminal can reassemble the request.

When a caller explicitly supplies an identifier it can later be reused for update or close operations. When a multi-frame request needs an identifier but none was supplied, the library generates an internal safe identifier only for chunk association.

## Resource bounds

The release freezes explicit resource ceilings:

```text
title UTF-8 bytes              65,536
body UTF-8 bytes               65,536
encoded payload chunk           4,096
metadata text value             4,096 UTF-8 bytes
notification-type entries          16
icon-name entries                  16
transmitted icon bytes         262,144
encoded OSC frame               16,384
notification identifier            128 ASCII characters
alive-query returned IDs            256
support/alive response payload   4,096 bytes
```

All outbound notification frames are completely validated/encoded before the shared output gate is committed.

## Explicit support observation

Version 1.4 adds:

```csharp
ValueTask<KittyNotificationSupport> QueryKittyNotificationSupportAsync(
	TimeSpan timeout,
	CancellationToken cancellationToken = default
);
```

The query reuses the existing authoritative terminal input/response router and generates a unique query identifier for exact correlation.

`KittyNotificationSupport` exposes terminal-advertised support for focus/report actions, close reports, title/body/close/icon/alive/buttons, expiration, occasions, urgencies, and sounds.

A timeout remains a timeout; it is not converted into a permanent unsupported claim merely because a response was absent.

## Alive-notification observation

Version 1.4 also adds:

```csharp
ValueTask<IReadOnlyList<string>> QueryKittyAliveNotificationsAsync(
	TimeSpan timeout,
	CancellationToken cancellationToken = default
);
```

This returns a bounded live observation of notification identifiers still reported by the terminal. The result is not maintained as library-owned notification state.

## Output and query behavior

Send/update/close operations:

- require an interactive terminal output endpoint;
- participate in the shared `TerminalSession` output-ordering domain;
- validate the complete request before waiting for the output gate;
- honor caller cancellation before commitment;
- complete committed frame sequences without caller cancellation splitting them;
- do not implicitly flush.

Support/alive queries use the existing terminal query transaction manager, including its authoritative reader, ambiguity serialization, response correlation, timeout, cancellation, late-response ownership, and query flush semantics.

## Security and privacy

OSC 99 may publish:

- title/body content;
- stable identifiers;
- application/filtering metadata;
- urgency/expiry/sound policy;
- icon names;
- caller-supplied image bytes.

Base64 protects framing but provides no confidentiality. The terminal, multiplexer, remote transport, desktop notification service, notification history, lock screen, screen sharing, or logs may expose decoded values.

`Icod.Terminal` does not automatically harvest process arguments, shell history, command output, environment variables, filesystem paths, or application state for notifications.

Transmitted icons are limited to bounded PNG/JPEG/GIF data and are never fetched or loaded from disk automatically.

## Deliberately deferred interactive forms

Kitty OSC 99 also defines buttons and unsolicited activation/close reports. Version 1.4 deliberately does **not** expose those forms.

Those reports are application input, not query responses. Supporting them correctly requires a separate reviewed extension to the authoritative `TerminalEvent` routing path so they can coexist with ordinary terminal input and active queries without stealing bytes or opening a competing raw reader.

The capability query can still report that a terminal advertises these features; this release simply does not request or surface their unsolicited events.

There is no generic raw OSC 99 selector/metadata API.

## Compatibility

`1.4.0` preserves:

- the stable 1.0 compatibility floor;
- all 1.1 OSC 633 additions;
- the 1.2 OSC 777 addition;
- all 1.3 OSC 1337 additions;
- existing public enum numeric values;
- `net8.0`, `net9.0`, and `net10.0` package targets;
- `Icod.TermInfo 1.10.0` and `Icod.Timing 1.0.0` dependencies.

## Validation

The 1.4 validation program adds:

- byte-exact OSC 99 framing tests;
- Base64 metadata/payload verification;
- automatic 4,096-byte encoded-payload chunking tests;
- identifier/update/close validation;
- icon format/resource-bound validation;
- support/alive query framing, correlation, and parser tests;
- fresh NuGet-only compile/runtime consumers on `net8.0`, `net9.0`, and `net10.0`;
- generated XML-documentation verification for the complete new public surface;
- an intentional machine public-API baseline update.

All retained historical package, OSC 633/777/1337, semantic/hardening, stable 1.x release-line, and current downstream compatibility gates continue to run.
