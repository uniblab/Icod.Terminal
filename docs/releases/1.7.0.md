# Icod.Terminal 1.7.0

`Icod.Terminal 1.7.0` is the DCS/Sixel graphics release for the stable 1.x line.

It builds directly on the 1.5 control-language normalization and 1.6 complete-CSI foundation. The release establishes canonical DCS construction, reconciles the existing DCS query families, implements Sixel as the first raster graphics backend, and defines the first backend-neutral raw raster-display contract intended to be shared with Kitty Graphics in 1.8.

## D170 DCS foundation

D170 adds an internal canonical seven-bit DCS writer for small bounded frames:

```text
ESC P
<parameter bytes>
<intermediate bytes>
<final selector>
<payload>
ESC \
```

D170 validates structural DCS byte classes, rejects payload bytes that would abort or terminate the control string, and bounds complete small-frame encoding to 4,096 bytes. It deliberately does not expose a public raw DCS writer and does not use one giant complete-frame allocation as the future large-Sixel output design.

D170 passed the complete pull-request Staging matrix on exact head `7d338fe5a1de122738d4573093db90e1500003a1`, workflow `34399549931`.

Permanent contract: `docs/D170-DCS-Construction-Contract-and-Reference-Freeze.md`.

## D171 existing DCS reconciliation

D171 removes the remaining hand-built DCS request framing from the two released DCS query families while preserving their exact bytes.

DECRQSS remains:

```text
ESC P $ q <request-identifier> ESC \
```

XTGETTCAP remains:

```text
ESC P + q <uppercase-hex-capability-name> ESC \
```

Both delegate only outer control-family construction to `DcsWriter`. Dialect-owned validation, request identifier/name encoding, response parsing/correlation, seven-bit/eight-bit input compatibility, timeout/cancellation semantics, and one-reader ownership remain unchanged.

Permanent contract: `docs/D171-Existing-DCS-Reconciliation.md`.

## D172 Sixel grammar and codec

D172 freezes the first canonical internal Sixel dialect policy:

```text
DCS 0;1;0 q
"1;1;<width>;<height>
<palette definitions>
<pixel commands>
ST
```

The header uses `Pa=0` so explicit raster attributes own pixel shape, `Pb=1` so zero-bit positions retain their existing color, and ignored `Ph=0`. The internal codec covers sixel values `0..63`, bounded repeat commands, `$`/`-` graphics movement, color-register selection `0..255`, and RGB definitions with protocol components `0..100`.

Every generated image will define every Sixel color register it uses and will not depend on pre-existing register contents. Version 1.7 does not claim exact restoration of external Sixel palette state and does not silently enable xterm private-color-register mode 1070.

Permanent contract: `docs/D172-Sixel-Grammar-and-Codec-Contract.md`.

## D173 backend-neutral raw raster model

D173 adds an internal immutable-owned raster snapshot shared by the Sixel implementation and the future Kitty Graphics backend:

```text
Rgb24      tightly packed R G B
Rgba32     tightly packed R G B A
Indexed8   one-byte palette indices + RGBA8 palette
```

Caller pixel/palette memory is copied at construction so later asynchronous output cannot observe caller mutation. Rows are exactly tightly packed; RGB24 is implicitly opaque; RGBA32 and indexed palettes preserve straight/unpremultiplied alpha exactly.

The model bounds dimensions to 16,384, total pixels to 16 Mi, owned pixel storage to 64 MiB, and indexed palettes to 256 entries. It performs no image-file decoding, gamma conversion, color management, premultiplication, or implicit compositing.

Permanent contract: `docs/D173-Common-Raw-Raster-Model.md`.

## D174 deterministic Sixel palette and quantization

D174 converts the D173 snapshot into a bounded Sixel-ready indexed image without exposing quantizer policy publicly.

The conversion provides:

- palette ceilings from 1 through 256;
- exact byte-for-byte passthrough for opaque Indexed8 input when its palette already fits;
- a lossless exact-color path ordered by first row-major appearance when distinct opaque colors fit the ceiling;
- explicit binary Sixel alpha behavior: alpha `0` is transparent/untouched, alpha `255` is opaque, and fractional alpha `1..254` is rejected rather than silently flattened;
- a separate transparent-pixel mask so transparency consumes no Sixel color register;
- valid all-transparent rasters with an empty palette;
- a fixed 32×32×32 RGB histogram for bounded high-entropy work memory;
- deterministic weighted median-cut reduction with explicit stable tie-breaking;
- rounded weighted RGB palette representatives;
- deterministic nearest-palette remapping using squared RGB distance and lower-index ties;
- no dithering, hidden matte color, gamma conversion, color management, or hash-order-dependent behavior.

This remains an internal Sixel conversion layer. D174 does not emit Sixel commands; D175 owns register definitions, RGB8-to-0..100 conversion, six-row band traversal, run-length policy, and payload generation.

Permanent contract: `docs/D174-Deterministic-Sixel-Palette-and-Quantization.md`.

## Compatibility

Version 1.7 retains the stable 1.x architecture and compatibility floor:

- one authoritative `TerminalSession` input reader;
- bounded parser/query/control-string/raster state;
- existing 1.0–1.6 public APIs and exact documented wire behavior remain compatible;
- DECRQSS and XTGETTCAP request bytes remain frozen;
- terminal identity is not capability proof;
- timeout is not automatically unsupported truth;
- no generic public raw DCS/Sixel writer;
- image-file decoding remains outside the core terminal package;
- D170–D174 add no public API.

The package continues to target:

```text
net8.0
net9.0
net10.0
```

and retains the dependency floor:

```text
Icod.TermInfo 1.10.0
Icod.Timing   1.0.0
```

The permanent stable compatibility policy remains documented in `docs/Compatibility-and-Versioning.md`.
