# Icod.Terminal 1.7.0

`Icod.Terminal 1.7.0` is the DCS/Sixel graphics release for the stable 1.x line.

It builds directly on the 1.5 control-language normalization and 1.6 complete-CSI foundation. The release establishes canonical DCS construction, reconciles the existing DCS query families, implements Sixel as the first raster graphics backend, and defines the first backend-neutral raw raster-display contract intended to be shared with Kitty Graphics in 1.8.

## D170 foundation

D170 adds an internal canonical seven-bit DCS writer for small bounded frames:

```text
ESC P
<parameter bytes>
<intermediate bytes>
<final selector>
<payload>
ESC \
```

D170 validates structural DCS byte classes, rejects payload bytes that would abort or terminate the control string, and bounds complete small-frame encoding to 4,096 bytes. It deliberately does not expose a public raw DCS writer and does not use one giant complete-frame allocation as the future large-Sixel output design.

D170 passed the complete pull-request Staging matrix on exact head `7d338fe5a1de122738d4573093db90e1500003a1`, workflow `34399549931`: Windows, Linux, macOS, package candidate, all four package shards, and the validated artifact.

The permanent D170 contract is maintained in `docs/D170-DCS-Construction-Contract-and-Reference-Freeze.md`.

## D171 existing DCS reconciliation

D171 removes the remaining hand-built DCS request framing from the two released DCS query families while preserving their exact bytes.

DECRQSS remains:

```text
ESC P $ q <request-identifier> ESC \
```

XTGETTCAP remains:

```text
ESC P + q <uppercase-hex-capability-name> ESC \
```

Both now delegate only the outer control-family construction to the D170 `DcsWriter`. Their dialect-owned validation, request identifier/name encoding, response parsing, response correlation, seven-bit/eight-bit input compatibility, timeout/cancellation semantics, and one-reader ownership remain unchanged.

D171 adds protocol-level byte-exact tests for all twelve DECRQSS request identifiers plus representative XTGETTCAP names and round-trip structural verification through `TerminalControlFrameStructure`.

The permanent D171 contract is maintained in `docs/D171-Existing-DCS-Reconciliation.md`.

## Sixel direction

Sixel is treated as a DCS dialect rather than as a new terminal-control family. The planned wire form is the DEC/xterm model:

```text
DCS Pa ; Pb ; Ph q <sixel data> ST
```

The implementation will separate raw raster data, deterministic palette/quantization policy, Sixel band/RLE encoding, capability evidence, and committed terminal output ownership.

The first raster model will consume raw pixel/index data rather than making PNG/JPEG/GIF decoding a dependency of `Icod.Terminal`.

## Compatibility

Version 1.7 retains the stable 1.x architecture and compatibility floor:

- one authoritative `TerminalSession` input reader;
- bounded parser/query/control-string state;
- existing 1.0–1.6 public APIs and exact documented wire behavior remain compatible;
- DECRQSS and XTGETTCAP request bytes remain frozen through D171 consolidation;
- terminal identity is not capability proof;
- timeout is not automatically unsupported truth;
- no generic public raw DCS/Sixel writer;
- image-file decoding remains outside the core terminal package.

The package continues to target:

```text
net8.0
net9.0
net10.0
```

and retains the dependency floor:

```text
Icod.TermInfo 1.10.0
Icod.Timing   1.0.0
```

The permanent stable compatibility policy remains documented in `docs/Compatibility-and-Versioning.md`.
