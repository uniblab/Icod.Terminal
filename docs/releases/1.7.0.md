# Icod.Terminal 1.7.0

`Icod.Terminal 1.7.0` is the DCS/Sixel graphics release for the stable 1.x line.

It builds on the 1.5 control-language normalization and 1.6 complete-CSI foundation. Version 1.7 establishes canonical DCS construction, reconciles the existing DCS query families, implements Sixel as the first raster graphics backend, adds evidence-based Sixel capability routing, and introduces the first backend-neutral public raster-display API intended to remain usable when Kitty Graphics is added later.

## Canonical DCS construction

D170 adds an internal canonical seven-bit DCS writer for small bounded frames:

```text
ESC P
<parameter bytes>
<intermediate bytes>
<final selector>
<payload>
ESC \
```

Structural byte classes and framing controls are validated, and complete small-frame encoding is bounded to 4,096 bytes. The generic writer remains internal and dialect-neutral.

D171 migrates DECRQSS and XTGETTCAP request framing onto that substrate while preserving exact released bytes:

```text
DECRQSS    ESC P $ q <request-identifier> ESC \
XTGETTCAP  ESC P + q <uppercase-hex-capability-name> ESC \
```

Existing seven/eight-bit DCS response compatibility, typed parsing, query correlation, cancellation, timeout, late-response ownership, and one-reader semantics remain unchanged.

Permanent contracts:

- `docs/D170-DCS-Construction-Contract-and-Reference-Freeze.md`
- `docs/D171-Existing-DCS-Reconciliation.md`

## Sixel grammar and codec

D172 freezes the canonical internal Sixel dialect:

```text
DCS 0;1;0 q
"1;1;<width>;<height>
<palette definitions>
<pixel commands>
ST
```

The header uses `Pa=0`, `Pb=1`, and `Ph=0`. Raster attributes explicitly own pixel geometry. The codec supports sixel values `?` through `~`, bounded repeat commands, `$`/`-` graphics movement, RGB color-register selection/definition, and a self-contained image rule in which every generated image defines every register it uses.

Version 1.7 does not claim exact restoration of external Sixel palette state and does not silently enable xterm private-color-register mode 1070.

Permanent contract: `docs/D172-Sixel-Grammar-and-Codec-Contract.md`.

## Backend-neutral raw raster model

D173 establishes the raw raster representation shared by Sixel and future raster backends:

```text
Rgb24      tightly packed R G B
Rgba32     tightly packed R G B A
Indexed8   one-byte palette indices + RGBA8 palette
```

Caller pixel/palette storage is copied at construction so later asynchronous work cannot observe caller mutation. RGB24 is implicitly opaque; RGBA32 and indexed palettes preserve straight/unpremultiplied alpha.

Bounds are explicit:

```text
maximum dimension       16,384
maximum pixels          16 Mi
maximum owned bytes     64 MiB
maximum palette entries 256
```

The raster layer performs no image-file decoding, gamma conversion, color-profile processing, premultiplication, or hidden compositing.

Permanent contract: `docs/D173-Common-Raw-Raster-Model.md`.

## Deterministic palette and quantization

D174 converts raw raster data into a bounded Sixel-ready indexed representation.

The conversion provides:

- palette ceilings from 1 through 256;
- exact opaque Indexed8 passthrough when the existing palette fits;
- lossless exact-color mapping when distinct opaque colors fit;
- explicit binary Sixel alpha semantics (`A=0` transparent/untouched, `A=255` opaque);
- controlled rejection of fractional alpha by the Sixel conversion rather than silent flattening;
- a separate transparency mask;
- a fixed `32 x 32 x 32` RGB histogram for bounded high-entropy work state;
- deterministic weighted median-cut reduction and stable tie-breaking;
- deterministic nearest-palette remapping;
- no dithering, hidden matte color, gamma conversion, color management, or hash-order-dependent behavior.

Permanent contract: `docs/D174-Deterministic-Sixel-Palette-and-Quantization.md`.

## Deterministic bounded Sixel encoder

D175 converts the indexed representation into lazy bounded Sixel payload segments rather than one complete encoded image allocation.

The encoder provides:

- six-row band traversal and correct partial-final-band behavior;
- deterministic used-register palette definitions;
- explicit register selection for each color pass;
- stable RGB8-to-`0..100` conversion;
- correct leading/interior/trailing zero handling;
- `$` between color passes and one `-` between bands;
- deterministic empty/transparent-band progression;
- repeat syntax only when strictly shorter than raw output;
- reusable bounded work state;
- hand-verifiable golden vectors.

D179 additionally includes both maximum-width highly-compressible and deliberately low-compressibility segment-bound witnesses.

Permanent contract: `docs/D175-Sixel-Encoder.md`.

## Committed streaming graphics output

D176 emits Sixel through the existing `TerminalSession` output serialization boundary without allocating one giant encoded frame.

The transaction semantics are:

- caller cancellation is honored before commitment;
- the first canonical Sixel DCS prefix write is the commit point;
- after commitment, caller cancellation cannot truncate the DCS;
- the shared session-output gate remains held across prefix, every payload segment, final ST, and one flush;
- ordinary session output cannot interleave inside a committed Sixel frame;
- successful output receives exactly one final seven-bit ST;
- transport failure is surfaced without retry or speculative terminator recovery;
- teardown drains committed output before output-state restoration proceeds.

Permanent contract: `docs/D176-Committed-Streaming-Graphics-Output.md`.

## Sixel capability evidence

D177 integrates `DcsSixel` with the normalized 1.5 capability/evidence model.

For Primary Device Attributes:

```text
attribute 4 present
    -> DcsSixel
    -> Verified
    -> ProtocolResponse
```

A valid Primary DA response without attribute `4` records only `Unknown / ProtocolResponse`. Absence is not automatically treated as authoritative unsupported evidence. Probe timeout records `Unknown / LiveProbe`; caller cancellation propagates without manufacturing negative evidence.

Successful public `QueryPrimaryDeviceAttributesAsync(...)` calls opportunistically update the same Sixel evidence after typed parsing. Live evidence remains generation-scoped and expires through the existing invalidation path.

No `TERM`, terminal-name, operating-system, emulator-brand, registry-order, or caller-preference heuristic is used as capability proof.

Permanent contract: `docs/D177-Sixel-Capability-Evidence-and-Live-Observation.md`.

## Public raster-display API

D178 intentionally adds the first public raster surface:

```csharp
public enum TerminalRasterPixelFormat {
	Rgb24,
	Rgba32,
	Indexed8
}

public readonly record struct TerminalRasterColor;
public sealed class TerminalRasterImage;

public ValueTask<TerminalControlMutationResult> DisplayRasterAsync(
	TerminalRasterImage image,
	CancellationToken cancellationToken = default
);
```

`TerminalRasterImage` provides bounded owned snapshots for RGB24, RGBA32, and Indexed8+palette input. The API describes **what image to display**, not how to construct Sixel commands.

In 1.7, `DisplayRasterAsync(...)` routes only through verified Sixel support. When no verified raster backend is available it may perform the bounded D177 probe; unresolved support returns a controlled unavailable result instead of blindly emitting graphics. Fractional alpha remains valid backend-neutral raster data, but the Sixel backend returns controlled unsupported when it cannot preserve that semantic content.

Transport errors remain transport errors and are not disguised as capability results.

Version 1.7 deliberately does not freeze public placement/scaling options, palette-register controls, raw DCS/Sixel writing, or an explicit Sixel backend selector.

Permanent contract: `docs/D178-First-Semantic-Raster-Display-Operation.md`.

## Package and release qualification

D179 adds release-oriented qualification for the public raster API:

- generated XML documentation is verified from the packed NuGet on all three TFMs;
- a fresh package-only consumer restores against the freshly built local NuGet and constructs every raster format;
- the consumer compile-binds `DisplayRasterAsync(...)` without repository project references;
- the consumer verifies enum values and snapshot/value semantics;
- package exclusion checks ensure raw DCS/Sixel writers and direct raster backing-memory exposure remain nonpublic;
- the raster verifier is part of the semantic package-contract shard and therefore runs in PR, main, distribution, and release package validation;
- retained `Icod.DCurses` package-boundary integration remains part of the Stable 1.x release-line shard.

Permanent closure record: `docs/D179-1.7.0-Hardening-Package-and-Documentation-Closure.md`.

## Compatibility

Version 1.7 retains the stable `1.0.0` compatibility floor and existing 1.0–1.6 public members and documented behavior. It also retains:

- one authoritative `TerminalSession` input reader;
- bounded parser/query/control-string/raster state;
- DECRQSS and XTGETTCAP exact request bytes;
- timeout as uncertainty rather than automatic unsupported truth;
- terminal identity as context rather than capability proof;
- no generic public raw CSI/DCS/OSC/APC/Sixel writer;
- no image-file decoding dependency in the core package;
- existing lifecycle/restoration/output-ownership semantics.

The package targets:

```text
net8.0
net9.0
net10.0
```

and retains:

```text
Icod.TermInfo 1.10.0
Icod.Timing   1.0.0
```

The permanent compatibility policy is `docs/Compatibility-and-Versioning.md`.

## Out of scope

Version 1.7 does not implement:

- Kitty Graphics;
- ReGIS;
- PNG/JPEG/GIF decoding;
- public raw DCS/Sixel dispatch;
- terminal-brand automatic graphics activation;
- filesystem/shared-memory graphics transport;
- animation;
- persistent image identifiers/placements;
- generalized graphics scene management.

Kitty Graphics and multi-backend raster routing were subsequently added in 1.8 using the same semantic raster contract.
