# Icod.Terminal 1.5.0

`Icod.Terminal 1.5.0` is the control-language normalization release for the stable 1.x line.

It prepares the architecture for complete CSI support, DCS/Sixel, APC/Kitty Graphics, and future terminal protocol families without changing the meaning or public signatures of the existing 1.0–1.4 wire-specific APIs.

## Release scope

The complete 1.5 program is:

```text
N150  terminology and layer-ownership freeze
N151  generalized control-family framing
N152  one bounded incremental control-language state machine
N153  structural CSI/DCS/string frame model
N154  multi-family query transactions
N155  capability support/evidence model
N156  semantic backend registry
N157  deterministic routing policy
N158  existing protocol and TermInfo reconciliation
N159  acceptance/package/documentation closure
```

Version 1.5 is intentionally infrastructure-heavy. It adds no public automatic-routing API and does not silently reroute any existing explicit API.

## N150 — terminology and ownership

The release freezes five distinct internal concepts:

```text
semantic operation
protocol backend
control family
support state
evidence source
```

These concepts remain separate so protocol number, terminal brand, capability truth, and routing preference cannot become interchangeable shortcuts.

Layer ownership remains:

```text
Icod.TermInfo
    immutable/static capability descriptions and expansion

Icod.Terminal
    live terminal conversation, framing, probing, routing,
    output serialization, lifecycle, and effective evidence

Icod.DCurses / applications
    semantic UI/application intent
```

## N151–N153 — normalized control-language framing

The common family vocabulary is:

```text
CSI  ESC [
DCS  ESC P
OSC  ESC ]
APC  ESC _
PM   ESC ^
SOS  ESC X
ST   ESC \
```

One bounded incremental scanner now recognizes these families while preserving family-specific termination rules and keeping dialect parsing separate.

The structural frame model preserves:

- CSI parameter bytes;
- CSI intermediate bytes;
- CSI final selectors;
- omitted/empty parameters and colon subparameters;
- DCS header structure separately from payload;
- opaque OSC/APC/PM/SOS payload bytes;
- introducer/terminator form.

Existing CSI/DCS/OSC query behavior remains compatible while later Sixel and Kitty Graphics implementations can reuse the same family and structural layers.

Sixel is classified as a DCS dialect. Kitty Graphics is classified as an APC dialect. APC itself remains an application-defined string family rather than being treated as inherently key/value based.

## N154 — multi-family query transactions

The query router can now represent one logical active query with a bounded set of accepted response families and explicit completion/barrier rules while preserving:

- one authoritative input reader;
- existing query serialization;
- timeout/cancellation semantics;
- bounded late-response ownership;
- unrelated application input.

A synthetic APC completion plus CSI barrier transaction proves the transaction model does not require Kitty-specific special casing in the input reader.

## N155 — capability support and evidence

Support state is now distinct from evidence source.

Support states:

```text
Unavailable
Unsupported
Unknown
Advertised
Verified
```

Evidence sources:

```text
TermInfo
BuiltInProfile
LiveProbe
ProtocolResponse
```

Important release rules include:

- endpoint unavailability is an effective state, not stored capability evidence;
- static TermInfo/profile advertisement is retained independently of live probes;
- decisive live evidence can override static advertisement;
- inconclusive live evidence does not erase stronger evidence;
- query timeout is not automatically unsupported truth.

## N156–N157 — semantic backend registry and routing

Every reviewed semantic operation has explicit internal backend candidates. Examples include:

```text
DesktopNotification
    OSC 9
    OSC 777
    OSC 99

ClipboardWrite
    TermInfo capability
    OSC 52

RasterGraphics
    Sixel / DCS
    Kitty Graphics / APC
```

Backend selection is deterministic and separate from registry declaration order. Automatic internal routing considers endpoint availability, verified live evidence, exact TermInfo implementation evidence, advertised backend evidence, reviewed safe fallbacks, and aggregate unknown/unsupported state.

Caller preference is routing policy, not capability evidence.

## N158 — existing protocol and TermInfo reconciliation

Existing 1.0–1.4 capabilities were audited against the new evidence and routing layers before any new public protocol family was added.

Exact TermInfo implementation evidence is recognized only for complete reviewed contracts:

```text
ClipboardWrite   Ms
CursorStyle      Ss
PaletteColor     can_change_color + initc
```

Existing CSI semantic backends receive TermInfo `Advertised` evidence only from complete metadata contracts:

```text
FocusReporting   fe + fd + kxIN + kxOUT
BracketedPaste   BE + BD + PS + PE
MouseReporting   XM + xm + recognized KeyMouse/kmous prefix
```

Partial overlap is not treated as semantic equivalence. In particular, `Cs`/`Cr` describe text-cursor color only and therefore do not advertise the entire OSC 10–19 dynamic-color semantic family.

The existing OSC 99 support query now feeds precise live evidence:

```text
successful correlated support response
    -> Osc99KittyNotification
    -> Verified / ProtocolResponse
```

Timeout/cancellation does not record a false negative.

The existing Kitty keyboard negotiation also feeds the same evidence broker:

```text
Kitty flags response
    -> CsiKittyKeyboard
    -> Verified / ProtocolResponse

Primary-DA barrier without Kitty flags
    -> CsiKittyKeyboard
    -> Unsupported / ProtocolResponse

probe timeout
    -> CsiKittyKeyboard
    -> Unknown / LiveProbe
```

`TerminalSession.InvalidateState()` advances the live-evidence generation. Live probe/protocol-response conclusions therefore expire across explicit out-of-band invalidation and managed resume, while immutable TermInfo/profile advertisement survives.

## Security and ownership

Version 1.5 does not introduce a generic raw public CSI/DCS/OSC/APC/PM/SOS writer.

It also preserves:

- one authoritative `TerminalSession` input reader;
- bounded parser/query state;
- existing output serialization and cancellation rules;
- explicit separation of terminal identity from capability proof;
- no interpretation of timeout as unsupported truth;
- existing explicit metadata/privacy behavior;
- exact/terminal-policy/scoped restoration semantics from the stable 1.x contract.
