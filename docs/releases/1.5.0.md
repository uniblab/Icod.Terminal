# Icod.Terminal 1.5.0

`Icod.Terminal 1.5.0` is the control-language normalization release for the stable 1.x line.

The release prepares the architecture for complete CSI support, DCS/Sixel, APC/Kitty Graphics, and future protocol families without changing the meaning of existing 1.0–1.4 wire-specific APIs.

## N150 foundation

The first tranche freezes five distinct internal concepts:

```text
semantic operation
protocol backend
control family
support state
evidence source
```

These concepts are intentionally separate so protocol number, terminal brand, and capability truth cannot become interchangeable shortcuts.

N150 introduces internal strongly typed vocabulary for:

- `TerminalSemanticOperation`;
- `TerminalProtocolBackend`;
- `TerminalControlFamily`;
- `TerminalCapabilitySupportState`;
- `TerminalCapabilityEvidenceSource`.

No public API addition is required by N150.

## Control-family vocabulary

The normalized string/control families are:

```text
CSI  ESC [
DCS  ESC P
OSC  ESC ]
APC  ESC _
PM   ESC ^
SOS  ESC X
ST   ESC \
```

The release documentation explicitly records that:

- CSI preserves parameter bytes, intermediate bytes, and a final byte rather than being treated as only a decimal parameter list;
- Sixel is a DCS dialect;
- APC is an application-defined string family, not inherently a key/value protocol;
- Kitty Graphics is an APC dialect;
- one terminal/vendor name can span unrelated control families, so a generic `SupportsKitty` flag is not a valid capability model.

## Layer ownership

The stable layering is retained:

```text
Icod.TermInfo
    immutable/static capability descriptions and expansion

Icod.Terminal
    live terminal conversation, framing, probing, routing,
    output serialization, lifecycle, and effective evidence

Icod.DCurses / applications
    semantic UI/application intent
```

Higher-level consumers should not construct raw OSC/CSI/DCS/APC frames or open competing terminal readers.

## Compatibility

Version 1.5 preserves every existing explicit wire contract, including:

```text
SendNotificationAsync            -> OSC 9
SendTitledNotificationAsync      -> OSC 777
SendKittyNotificationAsync       -> OSC 99
PublishCurrentLocationAsync      -> OSC 7
VS Code shell-integration APIs   -> OSC 633
iTerm2 shell-integration APIs    -> OSC 1337
```

Automatic semantic routing, if introduced later in the 1.5 program, will use new APIs or internal high-level consumers rather than silently changing these existing methods.

The package continues to target all three stable 1.x consumer frameworks:

```text
net8.0
net9.0
net10.0
```

The existing dependency floor remains `Icod.TermInfo 1.10.0` and `Icod.Timing 1.0.0`.

The 1.4 public API baseline remains the current public-surface fingerprint at the N150 stage because N150 adds only internal architecture. Any later intentional public addition in 1.5 will receive a separately reviewed 1.5 baseline before release closure.

The permanent compatibility policy remains in [`docs/Compatibility-and-Versioning.md`](../Compatibility-and-Versioning.md).

## Validation

N150 acceptance requires:

- unique internal vocabulary enum values;
- explicit family classification for every declared protocol backend;
- Sixel classified as DCS;
- Kitty Graphics classified as APC;
- TermInfo capability output explicitly outside the raw control-family classification;
- no public API drift;
- all retained runtime/package compatibility gates remaining green.

These curated notes will be expanded as N151–N159 are implemented.
