# Icod.Terminal 1.28.0 Release Notes

**Status:** Stable `1.28.0` is prepared for maintainer review. Merge, tag, GitHub Release creation, and NuGet publication remain separate maintainer-authorized actions.

## Published-spec Kitty Graphics transactions

Version 1.28 adds `TerminalControlMutationConfirmation` with stable values `Unspecified = 0`, `OutputCommitted = 1`, and `ProtocolAcknowledged = 2`. The read-only `TerminalControlMutationResult.Confirmation` property lets callers distinguish a completed local write-and-flush boundary from a correlated successful protocol response. Existing `Success()` calls remain source compatible and return `Unspecified`.

Persistent animation operations now follow action-specific response policy derived from the published Kitty Graphics protocol:

- full-frame append and regional frame replacement retain required bounded correlated acknowledgement;
- animation timing, selection, loading, stop, and playback controls use documented no-response transactions and report `OutputCommitted` after serialized write and flush;
- frame composition accepts an optional correlated success response, treats a correlated error as definitive, and reports `OutputCommitted` when committed output remains silent;
- protocol-response evidence is recorded only when a matching response was actually observed.

The published multi-chunk `a=f` continuation grammar is unchanged. No repeated-image-id workaround, terminal-brand/version branch, hidden replay, or automatic backend retry is introduced. Bounded late-response ownership, lifecycle revalidation, sequence and pixel uncertainty, generation-scoped evidence, and deterministic cleanup remain in force.

Neither `OutputCommitted` nor `ProtocolAcknowledged` claims that pixels were visible, that a multi-command update was atomic, or that animation was gapless.

## Exact Kitty evidence

Unmodified Kitty 0.49.2 remains a documented negative lane for the final continuation of a multi-chunk animation-frame transfer: the published command is accepted without the required acknowledgement. Terminal retains the bounded timeout and committed-uncertainty behavior rather than emitting implementation-specific syntax.

A source-built Kitty tree at `96693f4c090e9477b51ffa46aed4abdcef52d037`, containing upstream correction `b493a63` while still reporting version 0.49.2, supplied positive operator-visible evidence for the Terminal raster-animation witnesses. The corrected 8×8 placeholder atlas displayed changing colors, completed acknowledged 1/4/16/64 RGB24 regional workloads, reported output-committed frame selections, cleaned up, and exited successfully. The [transaction compatibility record](../Kitty-Graphics-Transaction-Compatibility-1.28.md) preserves the exact observations and their provenance limits.

These results qualify the exercised transactions in those exact source and transport environments. They do not convert one Kitty implementation's optional response into a protocol requirement or establish universal Kitty Graphics support.

## Downstream Icod.DCurses ATLAS qualification

The Icod.DCurses 2.3 development branch `2.3.0-raster-atlas-roadmap` at `d9ae518f0ba075f5e264acaeb14de2c9e8bc2c3d` consumes published `Icod.Terminal 1.28.0-alpha.1` and implements the intended compose-publish flow: copy the visible frame to a scratch frame, apply bounded regional changes, then select the completed frame. Full-coverage damage is coalesced into one regional transfer; sparse damage remains bounded per tile.

Its exact-head [workflow 37940789076](https://github.com/uniblab/Icod.DCurses/actions/runs/37940789076) passed all seven Windows, Linux, macOS, x64, ARM64, and package jobs. The complete .NET 10 unit suite passed 1,366 tests locally.

In the corrected source-built Kitty lane, the public raster-atlas sample selected `ATLAS`, displayed the maintainer-supplied opaque 16×16 water, grass, forest, road, and player artwork, and completed the interactive movement and scrolling workload responsively after the full-coverage coalescing correction. The maintainer accepted the result on 2026-10-09. `FRAME` and `TEXT` remain explicit controlled alternatives; ordinary raster and text behavior are not replaced by persistent ATLAS.

This downstream observation qualifies that exact sample, Terminal package, DCurses source, Kitty source, and operator-visible workload. It is not a promise of atomic or gapless remote presentation, nor a blanket claim for untested terminals.

## Compatibility and distribution

Version 1.28 preserves all existing public signatures and enum numeric values. The confirmation enum and property are additive. The public API fingerprint remains identical across `net8.0`, `net9.0`, and `net10.0`.

Production dependencies remain:

- `Icod.TermInfo 1.17.0`;
- `Icod.Timing 1.0.0`.

The managed Windows, Linux, and macOS target matrix is unchanged. Existing ordinary Kitty Graphics and Sixel routing remains available. Applications continue to own cells, layout, damage, fallback, repaint, and any claim about visible rendering.

See the [compatibility and versioning policy](../Compatibility-and-Versioning.md), [1.28 public API baseline](../Public-API-Baseline-1.28.md), [persistent raster ownership guide](../Persistent-Raster-Ownership.md), and [changelog](../../CHANGELOG.md) for the permanent contract and release history.

## Release gate

The stable release branch must pass the complete exact-head pull-request matrix before merge. After merge, the resulting `main` commit must pass the Release validation workflow. Only that validated commit may be tagged `v1.28.0`; the tag-controlled release workflow performs the final rebuild, verification, NuGet.org and GitHub Packages publication, checksums, and GitHub Release creation.
