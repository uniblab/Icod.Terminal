# Icod.Terminal 1.25.0-alpha.2

This prerelease reduces avoidable transport fragmentation when a screen-output
transaction presents an immediate Sixel image. It includes the newline-safe
cursor correction from 1.25.0-alpha.1.

## Sixel screen output

Each Sixel image is fully encoded and checked against the existing transaction
byte limit before output begins. Its DCS prefix, raster attributes, palette,
color passes, band separators, and terminator are combined into one transport
write. Previously, each encoder fragment was written separately, including
one-byte separators. Downstream Windows Terminal recordings showed progressive
horizontal-band redraw while the old image had already been cleared.

Coalescing preserves the exact protocol bytes and their position relative to
text and cursor plans. Capability generation and output epoch are rechecked at
commitment. Cancellation, allocation, or size failure during preparation emits
nothing. Committed failures still do not retry or switch graphics backends, and
synchronized-output cleanup remains in force.

One transport call does not promise atomic presentation: the operating system,
PTY, transport, or terminal may still split or progressively render the data.
The temporary contiguous copy is bounded by the existing encoded-payload limit;
preparation can briefly retain both fragments and their combined copy.

## Compatibility and acceptance

No public API, dependency, protocol-selection, native-call, or terminal-name
changes are introduced. Kitty chunking and the separate streaming
`DisplayRasterAsync` path are unchanged. Targets remain .NET 8, 9, and 10.

Regression coverage checks literal multi-band Sixel bytes, one image write,
ordered surrounding text, and synchronization cleanup after transport failure.
Repeat DCurses live rendering tests after consuming this package. The separate
WezTerm text-glyph shaping observation is not claimed fixed by this change.

Merge, tag, GitHub release, and NuGet publication remain maintainer actions.
