## 1. Purpose

T20A performs the final regret and package-only consumer review before assigning
stable version `0.2.0`.

No new terminal protocol or new input loop is introduced. The rich-input
behavior under review is the T14-T18 implementation already accepted through
DCurses in T19.

---

## 2. T19 closure

T19 is accepted.

The downstream `Icod.DCurses` `0.1.0` line retains one Terminal-backed event
stream for text, keys, mouse, focus, and paste, delegates protocol acquisition
to Terminal, and contains no parallel rich-input parser or protocol-state
manager.

DCurses PR #7 passed at commit:

```text
a95d10b9e0e578be29796ebfdf0e7ff0ee3c80ea
```

with GitHub Actions run:

```text
33131225189
```

T20 therefore evaluates the Terminal package itself rather than reopening the
downstream architecture.

---

## 3. Public API regret review

The reviewed 0.2 delta is published in:

```text
docs/Public-API-Baseline-0.2.md
```

No public rich-input type or member requires removal, renaming, or signature
change before stable 0.2.

The review accepts:

- typed mouse/focus/paste payloads;
- zero-based mouse cell coordinates;
- framed bounded paste;
- per-session decoder policy;
- reversible input-protocol leases;
- stronger-request mouse nesting;
- existing `TerminalKey` / `TerminalKeyModifiers` representation for traditional
  modified keyboard input.

Two stale XML comments are corrected without behavior or signature changes:
paste chunking is no longer described as future T16 work, and `TerminalKey` is
no longer described as belonging only to the 0.1 contract.

## 5. Package-only rich-input consumer

`tools/package-smoke` remains outside `Icod.Terminal.sln` and is restored against
only the packed artifact plus declared NuGet dependencies.

T20A extends that consumer so each of `net8.0`, `net9.0`, and `net10.0`
validates:

1. ordinary text;
2. focus input;
3. bracketed-paste Begin/Data/Data/End with a deliberately small chunk policy;
4. SGR mouse decoding and zero-based coordinates;
5. traditional Control+Up normalization;
6. capability-driven acquisition of paste/focus/button-mouse reporting;
7. explicit release of the rich-input protocol lease;
8. the existing session mode, output, TermInfo, serialization, and restoration
   checks.

The consumer uses injected control/input/output transports and therefore never
requires an interactive CI terminal.

## 7. Validation gate

T20A is accepted when:

1. `git diff --check` is clean;
2. Debug/Staging/Release repository builds remain clean;
3. the complete unit-test suite passes;
4. the isolated package consumer passes for all three target frameworks;
5. Staging package verification passes on Windows, Ubuntu, and macOS;
6. Source Link, XML documentation, symbols, and dependency closure remain green;
7. no new DCurses-side terminal protocol implementation is required.

After this gate passes, T20B may set:

```xml
<Version>0.2.0</Version>
<AssemblyVersion>0.2.0.0</AssemblyVersion>
<PackageVersion>0.2.0</PackageVersion>
```

and perform the final tag-controlled release.

## 8. T20B publication rule

Stable publication remains tag-controlled.

After the stable T20B commit is merged to `main` and its ordinary main
validation is green:

```text
git tag -a v0.2.0 -m "Icod.Terminal 0.2.0"
git push origin v0.2.0
```

The existing release workflow must verify that the tagged commit is contained in
`main`, rerun the complete Release matrix, publish the canonical package to
NuGet.org and GitHub Packages, create checksums, and create the GitHub Release.

No stable package is published from the Alpha-8 patch itself.
