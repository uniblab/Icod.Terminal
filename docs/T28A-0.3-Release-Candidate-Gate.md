# T28A — 0.3 Release-Candidate Gate

**Project:** `Icod.Terminal`
**Development line:** `0.3.0`
**Development version:** `0.3.0-alpha.8`
**Tranche:** T28A — public API, package, and release-candidate hardening
**Reference branch:** `0.3.0`
**Reference commit before tranche:** `58d943f3bd31fb1d6e54cca40a8de8bdefcc5248`
**Status:** Implementation complete; release matrix and downstream acceptance pending

---

## 1. Purpose

T28A performs the final API-regret and package-only consumer review before
stable version `0.3.0` may be assigned.

No new terminal protocol, response family, transaction manager, or production
query behavior is introduced by this tranche.

---

## 2. T27 prerequisite state

T27 implementation is present in the reference commit.

Its execution gate remains a prerequisite until the repository matrix and the
downstream DCurses regression are confirmed green. T28A does not conceal or
waive that prerequisite.

---

## 3. Public API regret review

The reviewed delta is published in:

```text
docs/Public-API-Baseline-0.3.md
```

No new 0.3 public type or member requires removal, renaming, or signature change
before stable release.

The review accepts typed CSI results, one-based CPR, a closed DECRQSS request
enum, byte-preserving XTGETTCAP observations, explicit timeouts, ordinary
cancellation, hidden response routing, passive session opening, and no aggregate
probe or arbitrary protocol-registration API.

---

## 4. README query contract

The README now demonstrates explicit CSI, DECRQSS, and XTGETTCAP operations and
documents cancellation, timeout, late-response ownership, the one-reader
invariant, one-based CPR, byte-valued XTGETTCAP results, and absence of automatic
probing.

---

## 5. Package-only query consumer

`tools/package-smoke` remains outside the solution and restores against only the
packed artifact plus declared dependencies.

T28A extends it through every public 0.3 query operation:

1. Primary Device Attributes;
2. Secondary Device Attributes;
3. standard Device Status Report;
4. Cursor Position Report;
5. DECRQSS SGR;
6. XTGETTCAP `TN`.

Responses are injected only after the corresponding request write is observed.

---

## 6. XML/package gate

The package verifier now requires XML documentation entries for all seven public
0.3 query contract types and all six public query methods.

It continues to validate package contents, assembly identity, exact dependency
closure, portable symbols, and Source Link.

Expected runtime dependencies remain:

```text
Icod.TermInfo 1.3.0
Icod.Timing   1.0.0
```

---

## 7. Dedicated Release candidate workflow

T28A adds `.github/workflows/release-candidate-validation.yaml`.

On pushes to `0.3.0` and by manual dispatch it runs Release clean/restore/build,
tests, pack, structural package verification, and the package-only consumer on:

```text
windows-latest
ubuntu-latest
macos-latest
```

with:

```text
net8.0
net9.0
net10.0
```

The Windows job uploads the validated candidate package and symbols as a
temporary workflow artifact.

---

## 8. Acceptance gate

T28A closes only when:

1. `git diff --check` is clean;
2. alpha.8 Release build/test passes for all supported TFMs;
3. package verification passes on Windows, Ubuntu, and macOS;
4. the isolated package consumer passes all six query operations for all TFMs;
5. Source Link, XML documentation, symbols, package contents, assembly identity,
   and dependency closure remain green;
6. the T27 downstream DCurses regression is confirmed against the 0.3 candidate;
7. no public API regret remains.

At patch-preparation time these execution checks are intentionally not recorded
as successful.

---

## 9. T28B publication rule

After T28A is accepted, T28B may set:

```xml
<Version>0.3.0</Version>
<AssemblyVersion>0.3.0.0</AssemblyVersion>
<PackageVersion>0.3.0</PackageVersion>
```

without changing production behavior unless alpha.8 validation discovered a
release-blocking defect.

The stable commit must be merged to `main`, pass ordinary `main` Release
validation, and only then receive the annotated `v0.3.0` tag used by the release
workflow.

No stable package is published from alpha.8 itself.
