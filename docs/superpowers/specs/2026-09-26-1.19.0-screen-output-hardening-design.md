# Icod.Terminal 1.19.0 Screen-output Hardening Design

The approved release scope is Option 1 + Option 2 + Option 4 + Option 10. The [implementation roadmap](../../../Icod.Terminal-1.19.0-Development-Roadmap.md) supplies the tranche sequence and release gates. This document records T190's implementation decisions.

## Baseline and compatibility

Start from released 1.18.0, commit `3e150377db990141aa6903631a8b95cb2c41116e`. Planning head `8d47c06a3a4260c0b0ad8c9ac7c1b5923fccd99c` passed PR workflow run `36288163471`. Preserve C# 13, net8.0/net9.0/net10.0, production TermInfo 1.15.0 and Timing 1.0.0, all public signatures and enum values, and the existing opaque-plan/session-transaction boundary.

The implementation begins as `1.19.0-alpha.1`. Stable identity follows qualification, not planning approval.

## Planner expansion

Extend `PlanCursorMove(TerminalScreenPosition? current, TerminalScreenPosition target)` with two additional candidates:

1. Home, relative down to the target row, relative right to the target column. Home establishes a known origin even when `current` is unknown. Omit zero-distance segments through the existing zero-byte relative-axis plan.
2. For a known current row equal to the target row, carriage return followed by relative right to the target column. Carriage return establishes column zero; it cannot establish an unknown row.

Each candidate requires every nonzero movement segment. Reuse existing capability expansion, padding, cost, count bounds, and opaque segment composition. Compare complete candidates only. Append new routes after all existing candidates so existing discovery order wins equal-cost ties. A missing or oversized repeated segment makes that route unavailable while retaining any independently usable candidate. No raw ANSI fallback, terminal-brand heuristic, extra physical-state cache, or public API addition is needed.

The caller continues to supply meaningful screen coordinates and the same terminal coordinate/mode assumptions as existing absolute/home/relative planning. Terminal does not clamp coordinates or own screen dimensions for layout.

## Cursor visibility decision

Defer `PlanCursorVisibility(...)`. Presentation leases already own visibility and restore it across lifecycle transitions. A composable visibility plan would need an explicit ownership and restoration integration contract beyond the existing opaque-byte-plan model. The release's required planner expansion is the two cursor routes above; no new competing visibility owner is introduced.

## Executable downstream boundary

Keep the controlled `tools/dcurses-screen-contracts-acceptance/Source` consumer free of TermInfo source usage and directly dependent only on the candidate Terminal package. Its renderer entry accepts a `TerminalSession` from its host. It must actually be invoked by a separate executable harness, with output assertions performed against a recording transport.

The separate test harness may use TermInfo 1.15.0 solely to create synthetic descriptions and implement the legacy `ITerminalControlProvider.GetSize` fixture signature. This is the same test-fixture exception already used by the DCurses readiness suite. The harness references the consumer project, never the Terminal source project; both resolve Terminal from the candidate package. The existing consumer boundary verifier remains in force over the complete controlled consumer source tree.

Baseline restoration is mandatory before treating physical rendition as default. A missing baseline rejects the refresh before commitment. Optional erase is omitted when unavailable; glyph fallback uses ordinary application text. Execute exact ordering, repeated refresh, intervening-output rejection, and recovery. A separate published DCurses 2.2.0 package witness exercises the decoupled renderer and keeps the legacy DCurses 1.6.0 witness intact.

## Transaction hardening

Preserve 65,536 retained items, 64 MiB payload, the planner's 1,048,576 repeated-source character bound, single-caller mutation, single-use commit, epoch validation, and existing reservation order. Cancellation before commitment emits nothing. Once output commitment starts, cleanup uses uncancelled tokens, failures retain attempt order, and emitted bytes cannot be rolled back or replayed automatically.

Existing tests already cover most admission, cancellation, foreign ownership, stale raster state, manager conflict, mixed cleanup, and serialization cases. Extend only uncovered interactions: new composed plans at admission/epoch boundaries and a complete mixed refresh/recovery path. Preserve existing tests as acceptance evidence. Any production transaction change requires a demonstrated regression.

## Consumer documentation and sample

Add a guide explaining profile inspection, unavailable versus zero-byte plans, unknown-state baseline recovery, transaction construction/commit, and caller-owned physical-state uncertainty. Add a small interactive sample with a noninteractive smoke path using the separate fixture harness. Keep production/sample screen logic Terminal-only; synthetic capability construction remains test tooling.

## Review and release evidence

Run the full unit and integration suites on all target frameworks, fresh-package witnesses, sample smoke, API/XML/dependency/license verification, and the existing platform workflows. Preserve the 1.18 API fingerprint if the reviewed surface is unchanged and record a 1.19 baseline explicitly. Record exact source and artifact identities; pending remote jobs are not accepted evidence.
