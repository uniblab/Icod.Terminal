# Icod.Terminal 1.24.0 Raster Geometry and Planning Design

## Purpose

`Icod.Terminal 1.24.0` will expose the geometry, local planning limits, and live operation evidence needed by an `Icod.DCurses` tile renderer. It does not implement a tile renderer or game abstraction.

The immediate consumer is an Ultima IV-style presentation: the application supplies logical tile and actor state; DCurses owns viewport, clipping, damage, overlays, retained raster cells, and refresh policy; Terminal owns live queries, persistent raster resources, placeholder identities, animation frames, acknowledged mutations, and lifecycle certainty.

## Release shape

Only 1.24 is committed. A possible 1.25 bounded frame-edit execution release is conditional on measurements from a real DCurses workload. The 1.24 release must be useful and complete without 1.25.

The 1.24 tile-atlas witness records workloads with one, four, sixteen, and sixty-four region changes. After DCurses consumes 1.24, those measurements decide whether a later batch abstraction or Indexed8 regional transfer has enough value to justify another public contract.

## Boundaries

Terminal owns:

- bounded terminal and cell pixel queries;
- exact pixel derivation;
- intrinsic persistent-resource geometry;
- stable local ceilings and advisory current local counts;
- operation-specific live evidence;
- protocol-private encoding, correlation, acknowledgement, lifecycle, and cleanup.

DCurses owns:

- raster-cell retention and tile-to-cell mapping;
- windows, pads, panels, viewports, screen coordinates, clipping, scrolling, and damage;
- overlays and presentation order;
- front/back frame-selection policy;
- text fallback selection.

The game or rules engine owns:

- maps, terrain, actors, collision, visibility, time, animation policy, scheduling, persistence, and rules;
- asset identities and semantic tile identities.

Image decoding, scaling policy, atlas packing, and palette policy belong to DCurses, the application, or a sibling asset library. They do not enter Terminal.

## Public pixel geometry

The existing internal `TerminalPixelSize` becomes the public immutable `TerminalPixelDimensions` value:

```csharp
public readonly record struct TerminalPixelDimensions {
    public TerminalPixelDimensions(int width, int height);
    public int Width { get; }
    public int Height { get; }
}
```

Both values must be positive. The existing internal query methods become public semantic methods:

```csharp
public ValueTask<TerminalPixelDimensions> QueryTerminalPixelDimensionsAsync(
    TimeSpan timeout,
    CancellationToken cancellationToken = default);

public ValueTask<TerminalPixelDimensions> QueryCellPixelDimensionsAsync(
    TimeSpan timeout,
    CancellationToken cancellationToken = default);
```

They retain existing query conventions: bounded caller timeout, the authoritative query/input coordinator, correlated response matching, late-response ownership, cancellation, `TimeoutException` for no reply, `FormatException` for a correlated malformed reply, and `InvalidOperationException` when the session cannot perform an active query. A timeout is not unsupported evidence. No result is cached as authoritative terminal state.

Exact derivation becomes public:

```csharp
public static class TerminalPixelGeometry {
    public static bool TryDeriveCellDimensions(
        TerminalDimensions terminalDimensions,
        TerminalPixelDimensions terminalPixelDimensions,
        out TerminalPixelDimensions cellPixelDimensions);
}
```

Derivation succeeds only when both pixel axes divide exactly by the corresponding positive character-cell axes and produce positive results. It never rounds or guesses. This explicit surface lets consumers prefer the direct cell query and then deliberately fall back to terminal pixels plus `GetDimensions()` without Terminal hiding two I/O operations behind one timeout.

## Persistent-resource geometry

`TerminalRasterResource` gains:

```csharp
public int PixelWidth { get; }
public int PixelHeight { get; }
```

The values come from the existing immutable resource state. Access performs no I/O. They remain the resource's intrinsic geometry after local certainty is lost or the public handle is disposed; they do not prove the resource still exists remotely.

## Raster planning snapshot

`TerminalSession.GetRasterPlanningSnapshot()` returns a side-effect-free value:

```csharp
public readonly record struct TerminalRasterPlanningSnapshot {
    public int MaximumImageDimension { get; }
    public int MaximumPixelCount { get; }
    public int MaximumOwnedPixelBytes { get; }
    public int MaximumPaletteEntries { get; }
    public int MaximumResources { get; }
    public int MaximumPlacements { get; }
    public int MaximumRelativePlacementDepth { get; }
    public int MaximumPlaceholderExtent { get; }
    public int MaximumAnimationFrames { get; }
    public int OwnedResourceCount { get; }
    public int OwnedPlacementCount { get; }
    public int AllocatedAnimationFrameCount { get; }
}

public TerminalRasterPlanningSnapshot GetRasterPlanningSnapshot();
```

The fixed fields publish current library admission ceilings. The count fields describe current local registry ownership. `OwnedPlacementCount` combines physical and virtual placements because they share the same admission ceiling. `AllocatedAnimationFrameCount` includes known frames and in-flight append reservations because both consume the frame ceiling.

The persistent registry captures resource and placement counts under one lock. The animation registry captures its allocated count under its own lock. The combined public value is advisory rather than an atomic cross-registry reservation. Concurrent activity may make it stale immediately; creation and append results remain authoritative.

The snapshot says nothing about remote terminal storage, remote eviction, or whether a future allocation will be accepted.

## Raster-operation evidence

Broad `PersistentRasterAnimation` capability evidence cannot distinguish base animation support from later composition and regional-update operations. Version 1.24 adds a focused surface instead of adding format variants to `TerminalCapability`:

```csharp
public enum TerminalRasterOperation {
    FrameComposition,
    FrameRegionUpdateRgb24,
    FrameRegionUpdateRgba32
}

public readonly record struct TerminalRasterOperationStatus {
    public TerminalRasterOperation Operation { get; }
    public TerminalCapabilitySupport Support { get; }
    public TerminalCapabilityEndpointAvailability EndpointAvailability { get; }
    public TerminalCapabilityEvidenceKind EvidenceKind { get; }
    public bool IsUsable { get; }
}

public TerminalRasterOperationStatus InspectRasterOperation(
    TerminalRasterOperation operation);
```

Inspection performs no I/O. Initial support is `Unknown`. A terminal output endpoint makes an unknown operation usable as an explicitly attempted safe semantic operation. A successful acknowledged composition records `Verified` for `FrameComposition`. A successful acknowledged regional update records `Verified` only for the corresponding RGB24 or RGBA32 operation.

The evidence ledger receives semantic-operation entries distinct from backend entries. A successful Kitty animation operation may continue to verify the broad backend/capability, but it cannot verify every focused raster operation. Lifecycle generation advance clears focused live evidence with all other live evidence.

No passive verification method is added. Generic negative replies, missing resources, malformed replies, timeout, cancellation, transport loss, and ambiguous committed failure do not prove operation-wide lack of support and therefore do not record `Unsupported`. A future release may record unsupported evidence only if a reviewed response unambiguously proves it.

## Tile-atlas witness

The existing raster-animation sample gains a protocol-neutral tile-atlas scenario using only public APIs. Its cells are numbered or colored test art, not game assets.

The scenario:

1. Inspects raster capabilities and planning limits.
2. Acquires direct cell pixels or explicitly attempts exact derivation from terminal pixels and character dimensions.
3. Creates a bounded atlas and reads its geometry from `TerminalRasterResource`.
4. Creates a placeholder grid and retains opaque cell tokens.
5. Creates or reuses two known animation frames.
6. Applies damage to the unselected frame and awaits each acknowledged result.
7. Selects the completed frame and reuses the previous front frame for the next update.
8. Reports text fallback when geometry or placeholders are unavailable.

The scripted package witness runs one-, four-, sixteen-, and sixty-four-region cases and reports operation count, updated pixels, encoded bytes where the public/test harness can observe them, CPU, allocations, acknowledgement latency, and total latency. It must not assert physical rendering from scripted protocol responses.

## Error and lifecycle behavior

- Invalid public arguments fail before terminal output.
- Pixel query timeout remains timeout, not unsupported evidence.
- Correlated malformed or oversized replies fail with the existing bounded query behavior.
- Resize can make an earlier geometry observation stale; no geometry is cached or automatically replayed.
- Resource dimensions are intrinsic and survive local ownership loss as descriptive values.
- Planning counts are advisory snapshots and never reserve capacity.
- Focused operation evidence is scoped to the current live generation.
- Existing composition and partial-update certainty rules remain unchanged.
- No lifecycle transition silently recreates resources, frames, placements, or placeholders.

## Compatibility and dependencies

The release is additive to 1.23 and preserves the stable 1.0.0 compatibility floor. Existing enum numeric values do not change. Public API snapshots must be identical across `net8.0`, `net9.0`, and `net10.0`.

Production dependencies remain `Icod.TermInfo 1.17.0` and `Icod.Timing 1.0.0`. `Icod.TermInfo.Inspection` remains optional test/sample infrastructure. Active verification checks the declared dependency floor without duplicating exact versions across unrelated tests.

## Non-goals

Version 1.24 does not add:

- tile maps, cameras, viewports, scenes, damage tracking, or game state;
- image-file decoding, atlas packing, scaling policy, palette policy, or asset caches;
- batch frame-edit execution or Indexed8 partial updates;
- remote atomicity, rollback, pixel restoration, retry, or hidden replay;
- gapless intermediate frames;
- absolute screen-coordinate or pixel-within-cell placement;
- remote terminal-capacity or resource-existence queries;
- raw protocol ids or command dictionaries;
- PTY/ConPTY hosting.

## Acceptance

The release is acceptable when a fresh package consumer can plan and exercise the tile-atlas scenario without internal APIs, raw terminal sequences, protocol identities, or game/DCurses abstractions; every new observation states its limitations; the three target frameworks expose the same public surface; and the full exact-head Windows/Linux/macOS qualification is green.
