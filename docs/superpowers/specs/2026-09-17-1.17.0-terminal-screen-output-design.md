# Icod.Terminal 1.17.0 Terminal Screen Output Design

**Release:** `1.17.0`  
**Theme:** Terminal-owned dimensions, semantic screen planning, and session-bound output transactions  
**Stable compatibility floor:** `1.0.0`  
**Downstream objective:** allow `Icod.DCurses 2.0` to communicate only with `Icod.Terminal`

## Goal

`Icod.Terminal 1.17.0` adds the semantic terminal-facing contracts required by a retained-screen renderer without taking ownership of cells, windows, layout, damage, or desired-versus-physical comparison.

The dependency direction remains:

```text
Icod.DCurses -> Icod.Terminal -> Icod.TermInfo
```

`Icod.TermInfo` remains Terminal's private capability-data and expansion authority. The new public surface does not reproduce raw terminfo enums, strings, or parameter expansion.

## Ownership boundary

Terminal owns:

- Terminal-owned cell dimensions and lifecycle projections.
- An immutable semantic profile derived from the selected terminal description.
- Capability interpretation, parameter expansion, byte-cost calculation, and safe operation encoding.
- Session association and atomic output ordering for a complete screen-output transaction.
- Pre-commit cancellation, post-commit cleanup, and failure visibility.
- Typed composition of application text, hyperlinks, and raster-placeholder cells.

Higher layers retain:

- Cells, wide-character policy, virtual screens, windows, pads, panels, layout, clipping, and damage.
- Desired-versus-physical comparison and optimization policy.
- Selection among independently safe plans based on screen semantics.
- Physical-screen certainty and repaint policy after a failed transaction.

## Terminal-owned dimensions

Add `TerminalDimensions`, an immutable positive `Columns`/`Rows` value. The default value is not usable by operations that require positive dimensions.

Add `TerminalSession.GetDimensions()` as a projection over the existing provider-based `GetSize()` path. Preserve `GetSize()` and `Icod.TermInfo.TerminalSize` compatibility in 1.x.

Add `TerminalLifecycleEvent.Dimensions` while preserving `Size`. Resize and resume events populate both from the same observation.

## Terminal profile

Add one immutable `TerminalProfile` per session. It exposes identity metadata and `TerminalScreenCapabilities`, not the underlying `TerminalDescription`.

The screen-capability view includes color model/count/selectors/default restoration, supported and color-restricted text attributes, alternate-character-set availability, cursor-visibility support, and absolute cursor-addressing support.

Static profile facts do not become live capability verification. Existing `TerminalSession.Terminal`, `TerminalIdentity`, and TermInfo-based advanced configuration remain compatible.

## Semantic screen values

The screen-planning vocabulary is Terminal-owned and protocol-neutral:

- `TerminalScreenPosition`
- `TerminalScreenColor` and `TerminalScreenColorKind`
- `TerminalScreenRendition` and `TerminalTextAttributes`
- `TerminalLineGlyph`
- alert, erase, character-shift, line-shift, scroll-region, and alternate-character-set operation kinds
- opaque `TerminalScreenOperationPlan`

An operation plan exposes semantic kind, resolved terminal-byte cost, and affected-line count. It does not expose escape sequences or TermInfo capability identifiers.

## Screen planner

Each session exposes one `TerminalScreenPlanner`. It is side-effect free and bound to the session/profile that created it.

The planner provides:

- safe cursor movement using absolute, home, row/column, carriage-return, and relative candidates;
- semantic rendition normalization and safe transition/reset plans;
- indexed/direct color validation and expansion;
- alternate-character-set glyph resolution while leaving Unicode-width fallback to the caller;
- preferred/fallback alert planning;
- erase, insert/delete character, insert/delete line, forward/reverse scroll, and scroll-region plans;
- byte costs after parameter expansion and terminfo padding removal.

Unsupported operations return no plan. Planning performs no output and does not mutate session state.

## Session-bound screen-output transaction

`TerminalSession.CreateScreenOutputTransaction(...)` returns a bounded, single-use builder tied to that session and its screen planner.

The builder accepts:

- opaque screen-operation plans from the same session;
- application text;
- bounded semantic OSC 8 hyperlink text;
- one or more opaque raster-placeholder cells owned by the same session.

An option requests synchronized-output framing. Commit emits the entire transaction while holding the session output gate and flushes before releasing it.

The transaction is bounded by operation count and retained application payload bytes. Additions that exceed either bound fail before output.

## State checkpoint

Creating a transaction captures the session's serialized-output epoch. Every acquisition of the session/control output gate advances that epoch. Commit rejects a stale transaction before output if another session-owned operation acquired the gate after transaction creation.

Direct use of borrowed `TerminalSession.Output` and the historical low-level `WriteTerminalStringAsync(...)` path remains outside this guarantee. Those advanced escape hatches retain their documented caller-coordination responsibility.

## Commitment and cleanup

Before the first byte, commit validates:

- the transaction is unused and the session remains open;
- its output epoch is current;
- every plan belongs to the same session planner;
- every raster-placeholder token belongs to the same current session generation;
- hyperlink inputs and retained payload bounds remain valid.

Caller cancellation is observed before commitment. After the first byte, ordinary caller cancellation no longer intentionally truncates the logical transaction.

If hyperlink or synchronized-output state was opened, commit attempts required close frames with `CancellationToken.None`. Independent primary and cleanup failures are aggregated. Any committed failure advances the epoch and is surfaced without replay.

## Compatibility

Version 1.17 is additive:

- Existing TermInfo-bearing Terminal public APIs remain available.
- Existing output, presentation, query, input, raster, and lifecycle semantics remain unchanged when the new APIs are unused.
- The new public screen types contain no `Icod.TermInfo` type in their signatures.
- Assembly identity remains compatible with the repository's stable 1.x policy.

## Security and bounds

- No public raw CSI/OSC/APC/DCS builder is added.
- Plans cannot be manufactured publicly or used across sessions.
- Hyperlinks reuse the existing strict OSC 8 validation/encoding.
- Raster tokens reuse existing generation/ownership validation.
- No terminal brand becomes capability proof.
- No hidden replay, screen cache, cell grid, or scene graph is introduced.

## Test and release gates

The release requires:

- red-green unit tests for each public value and planning family;
- exact-byte tests behind the opaque-plan boundary;
- stale, foreign-session, cancellation, partial-failure, cleanup, and concurrency tests;
- public API snapshots identical across `net8.0`, `net9.0`, and `net10.0`;
- Windows, Linux, and macOS runtime matrices;
- package-only consumer verification;
- stable `Icod.DCurses 1.6` compatibility and a dedicated future-DCurses decoupling acceptance consumer;
- documentation, package metadata, licensing, and release-closure review.

## Explicit non-goals

Version 1.17 does not add Terminal-owned cells, windows, pads, panels, layout, clipping, Unicode-width policy, damage tracking, desired-versus-physical comparison, automatic repaint, backend selection, raw capability access, or a second input/query reader.
