# Icod.Terminal 1.23.0 Partial Frame Transfer and Rich Input Design

**Status:** Approved design for roadmap and implementation planning

**Goal:** Extend the 1.22 persistent animation contract with bounded caller-supplied partial-frame updates, complete the remaining protocol-neutral rich-input surface, and qualify both through executable samples and fresh-package consumers.

## Scope

Version 1.23.0 selects Option 2, Option 9, and Option 10:

- **Option 2 — Partial animation-frame transfer:** add a bounded semantic operation that replaces a pixel rectangle in an existing known animation frame from immutable caller-supplied pixel data. The operation reuses the current resource and frame ownership model, output serialization, acknowledgement correlation, and ambiguous-commit rules from 1.22.
- **Option 9 — Rich-input and keyboard completion:** finish the protocol-neutral input contract across the supported traditional keyboard, CSI-u/Kitty keyboard, focus, bracketed-paste, and mouse paths. Preserve one authoritative input reader, explicit reversible protocol leases, bounded frames, malformed-input recovery, and privacy-aware documentation.
- **Option 10 — Consumer and release qualification:** add or extend samples, package-only witnesses, API/XML/dependency/security checks, downstream acceptance, and the nine-job Windows/Linux/macOS matrix.

The release does not add scene/layout ownership, a second input reader, hidden frame replay, raw vendor dispatch, image codecs, PTY hosting, or a general public protocol-extension API.

## Partial-frame contract

The proposed additive API is:

```csharp
ValueTask<TerminalControlMutationResult> UpdateFrameRegionAsync(
    TerminalRasterAnimationFrame destination,
    TerminalRasterImage region,
    int destinationX,
    int destinationY,
    CancellationToken cancellationToken = default);
```

The region is immutable caller-owned RGB24/RGBA32 data. It must be nonempty, fit the destination resource bounds, and use the existing destination frame token from the same current resource and generation. The operation replaces the bounded destination rectangle and creates no frame token. Alpha blending remains the 1.22 composition operation; 1.23 does not add a second blending model.

Local validation occurs before output. The existing output gate and correlated response path serialize the mutation with playback and other frame controls. A positive acknowledgement confirms the update. A definite rejection preserves known frame ownership. A timeout, cancellation, or transport failure after commitment leaves the affected pixels uncertain; callers must recreate the resource and frames before retrying. The library does not retain a source-image or delta cache.

## Rich-input completion contract

T2304 begins with a capability and event inventory against the shipped 1.21/1.22 behavior. The implementation fills only verified gaps in the existing semantic vocabulary. It may add typed enum members or event fields only when they represent a stable protocol-neutral concept and preserve existing numeric values and compatibility.

The completion gate covers:

- traditional keyboard forms and modifier combinations that the current decoder claims to support;
- negotiated CSI-u and Kitty functional-key phase combinations, including repeat/release identity and malformed or oversized recovery;
- focus-in/focus-out and bracketed-paste boundaries, including cancellation and cleanup of their protocol leases;
- supported mouse reports, button/wheel/motion distinctions, modifiers, coordinate bounds, malformed frames, and privacy guidance;
- one authoritative reader and serialized routing for input, active queries, unsolicited reports, and lifecycle events;
- executable sample coverage and documentation that state negotiation, endpoint, and privacy requirements.

Unknown future event kinds remain nonfatal to event loops. The implementation does not claim support for a protocol form that lacks a reviewed semantic mapping.

## Ownership and boundaries

Terminal owns pixel encoding, frame identity, response correlation, ordering, lifecycle certainty, and cleanup. Callers own source pixel memory, placement, clipping, layout, damage, and playback policy. Terminal owns input decoding, lease state, event framing, and the authoritative read path; callers own application meaning, keymaps, editing policy, and privacy decisions.

## Qualification requirements

- RED fixtures precede each production addition.
- Partial-frame tests cover geometry, formats, resource/frame ownership, playback ordering, cancellation, definite rejection, malformed response, ambiguous committed failure, disposal, generation loss, and bounded work.
- Input tests cover each claimed report family across all target frameworks, lease acquisition/release, malformed and oversized recovery, response correlation, event ordering, and privacy-sensitive payload handling.
- A shared sample path runs headlessly through scripted transports. Fresh package consumers run on `net8.0`, `net9.0`, and `net10.0` without source access or protocol-private identities.
- API snapshots, XML docs, package contents, dependency boundaries, license/security checks, and the complete Windows/Linux/macOS matrix pass on one exact PR head.

## Explicit non-goals

- gapless animation scheduling, audio/timeline synchronization, or a scene graph;
- absolute screen-coordinate or pixel-within-cell placement;
- automatic terminal-side reconciliation or replay after generation loss;
- image-file decoding/transcoding in the production package;
- PTY/ConPTY process hosting;
- public raw CSI/OSC/APC dispatch or a second input reader;
- file, temporary-file, or shared-memory graphics transfer without measured evidence and a separate design.
