# Icod.Terminal 1.26.0 Terminal Compatibility Qualification Design

## Purpose

`Icod.Terminal 1.26.0` will publish a versioned compatibility matrix backed by a public-only executable acceptance sample. The release will qualify existing nongraphics terminal behavior across ten representative terminal emulators without adding protocol APIs or weakening the rule that emitted bytes, advertised capabilities, and observed terminal behavior are different kinds of evidence.

The selected primary matrix is:

1. Windows Terminal;
2. Apple Terminal;
3. iTerm2;
4. Kitty;
5. WezTerm;
6. Ghostty;
7. Alacritty;
8. GNOME Terminal/VTE;
9. Konsole;
10. XTerm.

VS Code's embedded terminal is an additional integration lane because Icod.Terminal already exposes typed OSC 633 operations. `tmux`, SSH, WSL, ConPTY, and similar layers are recorded as transports or intermediaries, not substituted for the terminal emulator identity.

## Release shape

The release adds repository qualification infrastructure, documentation, and samples. It does not add public Icod.Terminal members. Existing OSC 0/1/2, 7, 8, 9, 9;4, 22, 52, 99, 133, 633, 777, and 1337 APIs remain the operations under test. Existing CSI/DCS queries, clipboard queries, input leases, modern keyboard reporting, synchronized output, colors, lifecycle events, and semantic events are also eligible for qualification.

Graphics protocols and raster APIs remain outside this release's live matrix. Their existing tests remain regression gates, and the graphics-development hold remains in force.

## Evidence model

Every checked-in live result identifies:

- Icod.Terminal package version and source commit;
- terminal product and exact reported version;
- host operating system and version;
- direct or mediated execution, including WSL, ConPTY, SSH, or multiplexer identity and version;
- scenario identifier and revision;
- observation time in UTC;
- outcome and short evidence note.

The closed outcome vocabulary is:

```text
Pass          requested behavior was observed
Fail          execution completed but behavior contradicted the scenario
Inconclusive  permission, policy, timeout, environment, or ambiguity prevented a conclusion
NotRun        no accepted live result exists for this cell
NotApplicable the operation has no meaningful application to that terminal lane
```

`Pass` never means every form of a protocol is supported. It means the exact scenario revision passed in the recorded environment. A query timeout is `Inconclusive`, not `Fail` or proof of unsupported behavior. Documentation claims may explain expectations but cannot create a live `Pass`.

The versioned matrix at `docs/compatibility/1.26.0.md` contains the human-readable summary, terminal identities, scenario revisions, result legend, and links to accepted evidence files under `docs/compatibility/evidence/1.26.0/`. Evidence files use a bounded JSON schema and stable ordering so the checked-in matrix can be regenerated deterministically.

## Acceptance sample

The new `Icod.Terminal.Compatibility.Sample` is a public-only consumer. Its command surface is:

```text
--help
--list-scenarios
--describe <scenario>
--render-matrix <evidence-directory> <output-file>
--run <scenario> [identity options] [--output <file>] [--overwrite]
--run-all [identity options] [--output <file>] [--overwrite]
```

Headless commands perform no terminal I/O and are exercised on .NET 8, 9, and 10. Live execution requires interactive input and output. It collects terminal and environment labels from explicit operator input or command-line values; it does not infer a support result from environment variables or terminal branding.

The required identity options are `--terminal`, `--terminal-version`, `--os`, and `--os-version`. A mediated run also supplies `--transport` and `--transport-version`. `--overwrite` is valid only with `--output`; the default is to preserve every existing report.

Scenarios are grouped as follows:

| Group | Existing API coverage |
| --- | --- |
| Identity and bounded queries | session identity, dimensions, DA/DSR, cursor position, DECRQSS, XTGETTCAP, color and pointer queries |
| Titles and location | OSC 0/1/2 and OSC 7 |
| Hyperlinks and semantic regions | OSC 8, OSC 133, OSC 633, reviewed OSC 1337 metadata |
| Notifications and progress | OSC 9, OSC 9;4, OSC 777, OSC 99 and interactive reports where available |
| Clipboard | OSC 52 write/read for explicitly supplied test content |
| Input and lifecycle | text/key events, bracketed paste, focus, mouse, modern keyboard phases, resize and suspend/resume observations |
| Presentation | cursor style, synchronized output, pointer shape, palette and dynamic colors where exact restoration is available |

Each scenario states its observable success condition before it emits bytes. Automated observations and operator confirmations are recorded separately. The sample consumes input only through `TerminalSession.ReadEventAsync(...)` while a session is open.

## Side effects and restoration

`--run-all` does not silently execute scenarios that can disclose or mutate external state. Clipboard reads/writes, desktop notifications, hyperlinks, title changes, current-location publication, shell metadata, and color changes require an explicit prompt in the interactive session before their first effect. A declined scenario becomes `NotRun`; a denied terminal or desktop permission becomes `Inconclusive`.

Scoped state uses the existing leases and deterministic disposal. Operations with no truthful restoration contract state their effect before execution. The sample uses fixed, nonsecret test values and never reads other-process command lines, shell history, the current working directory, user/host identity, or clipboard content without explicit operator direction.

## Report generation

The sample writes one bounded JSON result file only when `--output` is supplied. It refuses to overwrite an existing file unless an explicit overwrite option is supplied. Reports contain no raw clipboard data, command lines, keystrokes, environment-variable dumps, or arbitrary terminal replies. Free-text notes are bounded and control characters are rejected.

The repository generator validates evidence schema, rejects duplicate terminal/scenario identities, orders rows deterministically, and renders `docs/compatibility/1.26.0.md`. CI regenerates the matrix and fails on a diff. Live terminal execution remains a maintainer action; ordinary CI runs only the headless contract, parser/generator tests, and existing runtime suite.

## Compatibility claims

The matrix distinguishes:

- library implementation: an Icod.Terminal semantic API exists;
- static advertisement: a terminal description advertises a capability;
- protocol observation: a bounded query or response was received;
- operator observation: a visible or desktop behavior was confirmed;
- transport qualification: the same scenario passed through an identified intermediary.

One kind of evidence does not silently promote another. A successful write does not prove display, a terminal name does not prove support, and a direct result does not qualify tmux, SSH, WSL, or another transport.

## Documentation and package surface

The root README and sample index link to the versioned matrix and explain how to run the acceptance sample. The fresh-package verifier builds and runs the headless commands against the produced package on all three target frameworks. No source-project reference is allowed in that witness.

The planning, sample, generator, and matrix remain dependency-free beyond the current production graph and the .NET base class library. Production dependencies remain `Icod.TermInfo 1.17.0` and `Icod.Timing 1.0.0`; optional `Icod.TermInfo.Inspection 1.17.0` remains outside the production graph.

## Error and lifecycle behavior

- Invalid command arguments fail before a terminal session is opened.
- Redirected or missing endpoints produce a controlled diagnostic and no fabricated results.
- Timeout and malformed correlated responses retain existing exception and routing semantics.
- Cancellation before a scenario commits records no false result; committed effects retain their existing certainty limits.
- Cleanup failures are reported and prevent `Pass` for a scenario that promises restoration.
- Unknown future terminal events remain nonfatal to the sample unless the active scenario requires that event.
- Partial report files are written to a temporary sibling and atomically renamed only after complete validation.

## Release gates

The implementation must pass:

- existing runtime and source-integration tests on Windows, Linux, and macOS for .NET 8, 9, and 10;
- headless sample commands and report generator tests on every target framework;
- fresh-package compilation and execution without source references;
- deterministic matrix regeneration;
- XML, API, dependency, license, security/privacy, and documentation-link checks;
- reviewed live results for each primary terminal lane or an explicit `NotRun` entry that prevents an unsupported claim.

Stable 1.26 may ship with `NotRun` cells. It may not convert absent evidence into a positive or negative compatibility claim.

## Non-goals

Version 1.26 does not add OSC 21, OSC 5522, DEC mode 2031, DEC mode 2048, new OSC 1337 operations, a generic raw escape API, automatic protocol selection from terminal branding, host-native fallbacks, terminal installation automation, remote orchestration, telemetry, or graphics qualification. Those remain separate feature decisions after this matrix exposes concrete compatibility gaps.
