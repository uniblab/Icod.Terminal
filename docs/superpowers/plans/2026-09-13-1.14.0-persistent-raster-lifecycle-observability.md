# Icod.Terminal 1.14.0 — Persistent-Raster Lifecycle Observability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose one atomic, backend-neutral, side-effect-free ownership snapshot from every persistent raster resource and placement without inventing terminal-side existence guarantees, leaking protocol identities, replaying raster data, or weakening the 1.13 ownership graph.

**Architecture:** Public wrappers expose an immutable `TerminalRasterOwnershipState` snapshot. Underlying resource/placement state stores one packed monotonic lifecycle value updated through atomic operations; wrapper disposal remains wrapper-local and overrides the underlying snapshot with `Disposed / ExplicitDisposal`. Existing invalidation, negative-response, graph-release, and session-lifecycle paths become the only writers of lifecycle transitions, while reads remain synchronous and perform no terminal/query/output work.

**Tech Stack:** C# 13; .NET `net8.0`, `net9.0`, `net10.0`; xUnit; existing `TerminalSession` persistent-raster registry/query infrastructure; PowerShell package/sample verifiers; GitHub Actions Windows/Linux/macOS matrix.

**Spec:** `docs/superpowers/specs/2026-09-13-1.14.0-persistent-raster-lifecycle-observability-design.md`

## Global Constraints

- Stable compatibility floor remains `1.0.0`.
- Public API remains backend-neutral and must expose no Kitty image id, image number, placement id, parent protocol identity, or session generation number.
- Observation is synchronous and side-effect free: no terminal writes, query registration, output-gate acquisition, capability verification, cleanup, replay, backend selection, or registry mutation.
- Public lifecycle semantics are exactly `Current`, `Stale`, `Released`, and `Disposed`.
- Public reason semantics are exactly `None`, `SessionStateLost`, `ResourceMissing`, `ParentPlacementLost`, `AncestorReleased`, `ResourceReleased`, and `ExplicitDisposal` unless T140 discovers a concrete contradiction before the API-freeze commit.
- Newly acknowledged handles begin `Current / None`.
- Lifecycle transitions are monotonic; stale/released/disposed ownership never becomes current again.
- `Current` reports Icod.Terminal's local certainty only; it is never documented as authenticated or authoritative terminal-side existence.
- Resource/placement capacities remain 256 / 4096 and relative depth remains 8.
- Existing 1.11–1.13 wire bytes and transaction semantics remain unchanged when lifecycle observation is not read.
- No automatic raster replay/re-upload or hidden source-pixel retention is introduced.
- `Icod.TermInfo.Inspection` remains optional and is not added to the production dependency graph.
- `Icod.DCurses` retains cells/windows/layout/damage/refresh ownership.
- Repository C# formatting remains 1TBS and existing coding conventions remain authoritative.

- [ ] **Step 3: Implement packed atomic storage**

Use one `int` field and `Volatile.Read`/`Interlocked.CompareExchange`. Encode status and reason into one value so reads cannot tear.

```csharp
internal sealed class TerminalPersistentRasterLifecycleState {
	private int value;

	internal TerminalPersistentRasterLifecycleState() {
		this.value = Pack(
			TerminalRasterOwnershipStatus.Current,
			TerminalRasterOwnershipLossReason.None
		);
	}

	internal TerminalRasterOwnershipState Observe() {
		int snapshot = Volatile.Read( ref this.value );
		return Unpack( snapshot );
	}
}
```

Transition helpers may change only `Current`; once stale/released, they return `false` without changing the first truthful terminal state.
