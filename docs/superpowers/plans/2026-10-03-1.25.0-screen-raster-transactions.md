# Icod.Terminal 1.25 Screen Raster Transactions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an immediate raster item to the existing Terminal screen-output transaction so a complete caller-supplied image can be ordered with cursor plans and text through verified Kitty or Sixel.

**Architecture:** Reuse ordinary `RasterGraphics` evidence and private codecs. Prepare every raster payload before acquiring the transaction's output gate, revalidate the prepared backend and epoch at commitment, then write the typed items in caller order. DCurses owns full-frame provision and visual placement.

**Tech Stack:** C# 13; .NET 8/9/10; xUnit; repository PowerShell 5.1 and cmd/sh verifiers; GitHub Actions on Windows/Linux/macOS.

**Spec:** `docs/superpowers/specs/2026-10-03-1.25.0-screen-raster-transactions-design.md`

## Global Constraints

- Preserve stable 1.0.0 compatibility and existing signatures/enum values.
- Production dependencies remain `Icod.TermInfo 1.17.0` and `Icod.Timing 1.0.0`; optional Inspection stays outside production.
- `RasterGraphics` may use ordinary Kitty or Sixel; `PersistentRasterGraphics` remains independently Kitty-only.
- No native calls, terminal-name detection, raw protocol public API, second query reader, hidden image cache, or automatic replay.
- Keep encoded raster work bounded and reject predictable failures before transaction output.
- A successful commit proves local write/flush, not physical rendering.

## Review Focus

The following five failure classes must have explicit tests in the owning tasks:

1. Persistent Kitty unsupported but ordinary Kitty verified → ordinary raster transaction still succeeds (Task 2).
2. Sixel quantization or framing fails on a later raster item → preceding text/plan items emit zero bytes (Task 2).
3. Capability generation changes after preparation → commit emits zero bytes (Task 3).
4. Post-raster text without an explicit cursor movement cannot assume a known cursor; the documented sample supplies a move (Tasks 3 and 5).
5. A write failure after raster output begins → no backend switch or retry, with cleanup and uncertainty preserved (Task 4).
