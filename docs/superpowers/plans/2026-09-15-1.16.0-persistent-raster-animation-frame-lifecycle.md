# Persistent Raster Animation and Frame Lifecycle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` or `superpowers:subagent-driven-development` to execute this plan task-by-task. All production changes follow strict RED -> GREEN -> REFACTOR cycles.

**Goal:** Add bounded, backend-neutral persistent-raster animation to `Icod.Terminal 1.16.0`: opaque frame tokens, full-frame append, positive frame timing, explicit frame selection, terminal-driven stop/loading/run playback, and a distinct sequence-certainty model, without exposing Kitty frame numbers or adding replay/layout ownership.

**Architecture:** One existing `TerminalRasterResource` remains the terminal image ownership root. Its side-effect-free `Animation` property exposes the one resource-owned `TerminalRasterAnimation` controller and an opaque root-frame token. A dedicated internal animation registry tracks known frame order and sequence certainty separately from resource ownership. Kitty `a=f` transfer and `a=a` control remain private and reuse the existing serialized output/query infrastructure.

**Tech stack:** C# 13; .NET `net8.0`, `net9.0`, `net10.0`; xUnit; PowerShell package verification; Kitty Graphics Protocol; existing persistent-raster/query/output infrastructure.

**Design authority:** `docs/superpowers/specs/2026-09-15-1.16.0-persistent-raster-animation-frame-lifecycle-design.md`

## T160 design refinements frozen by this plan

The implementation plan resolves two protocol/API-regret details that were still draft wording in the roadmap/design narrative:

1. `TerminalRasterAnimation` is resource-owned and **not** independently disposable. `TerminalRasterResource` exposes one side-effect-free `Animation` property; resource/session lifecycle remains final cleanup authority.
2. Kitty normal playback cannot represent “exactly zero additional repeats” as a finite loop policy: `v=1` is infinite and finite values begin at `v=2`. Therefore public finite `RepeatCount` means **additional repeats after the first traversal and must be at least 1**. `null` means infinite. A caller wanting a single traversal without looping uses explicit/client-driven `SelectFrameAsync(...)` policy rather than a false terminal-driven promise.

These T160 refinements supersede the earlier roadmap phrases “non-negative finite repeat count” and “animation-wrapper disposal.”

## Global constraints

- Stable compatibility floor remains `1.0.0`.
- Preserve target frameworks `net8.0;net9.0;net10.0` and C# 13.
- Preserve all released `TerminalCapability` numeric values; add `PersistentRasterAnimation = 11` only.
- Preserve production dependencies `Icod.TermInfo 1.14.0` and `Icod.Timing 1.0.0` unless a separately justified dependency-maintenance decision is made.
- One animation sequence per persistent raster resource.
- Root image is frame 1 internally; protocol frame numbers remain private.
- Maximum locally known animation frames: 4096 session-wide, including roots.
- Appended frames are full-frame only and must match the resource intrinsic dimensions.
- Positive duration must be an exact whole number of milliseconds in `1..Int32.MaxValue`.
- `TerminalRasterAnimationPlaybackOptions.RepeatCount == null` means infinite; finite repeat count is `1..Int32.MaxValue-1`, converted privately to Kitty `v = RepeatCount + 1`.
- No public Kitty image id/frame number/raw `a=f`/`a=a` keys/backend selector.
- No `a=c` composition, partial/delta frame editing, gapless frames, GIF/APNG decoding, retained source-frame replay cache, absolute placement, pixel-within-cell placement, scene/window/cell/damage/layout ownership, or PTY/ConPTY hosting.
- Ambiguous committed frame append may make animation sequence certainty unknown without falsely staling the raster resource.
- Control-operation ambiguity does not change known frame numbering and therefore does not by itself poison sequence certainty.
- No automatic retry, replay/re-upload, or backend switch.
- All concurrency/stress work is fixed and bounded.

## Frozen candidate public surface for T160

T160 RED tests freeze this exact candidate unless a RED-cycle/API-regret finding proves it unsound before GREEN:

```csharp
public enum TerminalCapability {
    // existing values 0..10 unchanged
    PersistentRasterAnimation = 11
}

public enum TerminalRasterAnimationStatus {
    Current = 0,
    SequenceUncertain = 1,
    Stale = 2,
    Released = 3,
    OwnerDisposed = 4
}

public enum TerminalRasterAnimationLossReason {
    None = 0,
    FrameSequenceAmbiguous = 1,
    SessionStateLost = 2,
    ResourceMissing = 3,
    ResourceReleased = 4,
    ExplicitResourceDisposal = 5
}

public readonly record struct TerminalRasterAnimationState(
    TerminalRasterAnimationStatus Status,
    TerminalRasterAnimationLossReason LossReason
);

public sealed class TerminalRasterAnimationPlaybackOptions {
    public int? RepeatCount { get; init; }
}

public sealed class TerminalRasterAnimationFrame {
    // no public constructor or protocol identity
}

public sealed class TerminalRasterAnimation {
    public TerminalRasterAnimationFrame RootFrame { get; }
    public TerminalRasterAnimationState State { get; }

    public ValueTask<TerminalControlResult<TerminalRasterAnimationFrame>> AddFrameAsync(
        TerminalRasterImage image,
        TimeSpan duration,
        CancellationToken cancellationToken = default
    );

    public ValueTask<TerminalControlMutationResult> SetFrameDurationAsync(
        TerminalRasterAnimationFrame frame,
        TimeSpan duration,
        CancellationToken cancellationToken = default
    );

    public ValueTask<TerminalControlMutationResult> SelectFrameAsync(
        TerminalRasterAnimationFrame frame,
        CancellationToken cancellationToken = default
    );

    public ValueTask<TerminalControlMutationResult> StopAsync(
        CancellationToken cancellationToken = default
    );

    public ValueTask<TerminalControlMutationResult> RunLoadingAsync(
        CancellationToken cancellationToken = default
    );

    public ValueTask<TerminalControlMutationResult> RunAsync(
        TerminalRasterAnimationPlaybackOptions? options = null,
        CancellationToken cancellationToken = default
    );
}

public sealed class TerminalRasterResource {
    public TerminalRasterAnimation Animation { get; }
}
```

`TerminalRasterAnimation` and `TerminalRasterAnimationFrame` expose no public constructors. Neither implements `IDisposable`/`IAsyncDisposable` in 1.16.
