# Icod.Terminal 1.26 Terminal Compatibility Qualification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a versioned, evidence-backed nongraphics terminal compatibility matrix and a public-only executable acceptance sample for ten representative terminal emulators.

**Architecture:** A new sample owns the command line, live scenarios, bounded evidence model, JSON report writing, validation, and deterministic Markdown rendering. Live scenarios call existing public `TerminalSession` APIs and share its one authoritative reader; headless commands and fixtures make the report contract fully testable in CI. Checked-in evidence generates the versioned matrix, while terminal behavior remains a separately reviewed live observation.

**Tech Stack:** C# 13; .NET 8/9/10; `System.Text.Json`; xUnit; PowerShell 5.1-compatible repository scripts; GitHub Actions on Windows/Linux/macOS.

**Spec:** `docs/superpowers/specs/2026-10-04-1.26.0-terminal-compatibility-qualification-design.md`

## Global Constraints

- Preserve the stable 1.0.0 compatibility floor and every existing public signature and enum value.
- Add no public Icod.Terminal API; the sample consumes the public 1.25 surface.
- Production dependencies remain `Icod.TermInfo 1.17.0` and `Icod.Timing 1.0.0`; use only the .NET base class library for sample/report infrastructure.
- Preserve one authoritative input/query/event reader and all existing timeout, correlation, cancellation, lifecycle, and restoration contracts.
- Do not infer support from `TERM`, terminal branding, documentation, successful output, or an unreturned query.
- Exclude raster/graphics qualification and preserve the graphics-development hold.
- Live execution is manual evidence collection; CI runs only headless commands, fixtures, package consumers, and existing automated tests.

## Review Focus

1. Query timeout or denied desktop permission must produce `Inconclusive`, never `Fail` or `Pass` (Tasks 3 and 5).
2. A direct terminal pass must not qualify a result collected through tmux, WSL, ConPTY, or SSH without an exact intermediary identity (Tasks 1 and 6).
3. Cancellation or write failure while producing a report must leave no valid-looking partial file and must not overwrite existing evidence (Task 5).
4. The sample must never use `Console.Read*` while `TerminalSession` owns input; confirmations and observations use `ReadEventAsync(...)` (Tasks 3 and 4).
5. Generated evidence must exclude clipboard payloads, key streams, command lines, environment dumps, and arbitrary terminal reply bytes (Tasks 4 and 5).
