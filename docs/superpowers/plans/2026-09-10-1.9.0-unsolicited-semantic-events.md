# Icod.Terminal 1.9.0 Unsolicited Semantic Events Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a bounded protocol-neutral unsolicited semantic-event lane to `TerminalSession.ReadEventAsync(...)`, then implement Kitty OSC 99 activation, button, close, and close-tracking-unavailable reports as the first semantic event family.

**Architecture:** Preserve the one authoritative `TerminalInputCoordinator`/`TerminalInputDecoder` path. Active query ownership takes precedence, recognized semantic reports are classified second, and ordinary application input remains the fallback; same-byte-stream input and semantic events share one bounded ordering domain.

**Tech Stack:** C# 13, .NET `net8.0`/`net9.0`/`net10.0`, xUnit, existing Icod.Terminal control-language/query infrastructure, existing Kitty OSC 99 encoder/query contracts.

**Spec:** `Icod.Terminal-1.9.0-Development-Roadmap.md` and `docs/E190-Unsolicited-Semantic-Event-Contract-and-Reference-Freeze.md`

## Global Constraints

- Stable compatibility floor remains `1.0.0`.
- Existing `TerminalEventKind` numeric values never move; any new value is appended.
- One live `TerminalSession` remains the authoritative terminal-input reader.
- No public second raw-input or semantic-event reader.
- Active query ownership wins before unsolicited semantic classification.
- One frame is never double-delivered as query response and semantic event.
- Same-byte-stream input and semantic events preserve decode order.
- Event buffering remains finite and backpressured.
- Existing noninteractive Kitty notification calls remain byte-compatible when new interactive options are unused.
- No new package dependency merely for OSC 99 interactive events.
- Current `Icod.DCurses` compatibility remains a release gate.
