# Icod.Terminal 1.13.0 Relative Persistent-Raster Placement Ownership Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add bounded immutable-parent relative persistent-raster placement ownership while preserving all published 1.12 behavior when the new API is unused.

**Architecture:** Extend the existing persistent-raster registry with an orthogonal bounded parent/child placement graph. Resource ownership remains independent. Relative placement uses explicit create/update methods, immutable parentage, signed terminal-cell offsets, maximum depth 8, the existing `TerminalRasterPlacementOptions` for common geometry, and the existing acknowledged query/input transaction path.

**Tech Stack:** C# 13; .NET `net8.0`, `net9.0`, `net10.0`; xUnit; PowerShell packaging/verification; existing Kitty Graphics persistent backend; existing Terminal query transaction manager.

**Spec:** `docs/superpowers/specs/2026-09-12-1.13.0-relative-persistent-raster-placement-design.md`

## Global Constraints

- Stable compatibility floor remains `1.0.0`.
- Published `1.12.0` public behavior and wire bytes remain unchanged when relative APIs are unused.
- Parentage is immutable for the complete relative-placement lifetime.
- Portable maximum relative depth is exactly `8`.
- Resource ownership and placement-parent lifetime are separate axes.
- Existing live ceilings remain exactly `256` resources / `4096` placements per session.
- Existing `TerminalRasterPlacementOptions` remains the only common crop/extents/z-order options type.
- No new `TerminalCapability` value in 1.13.
- No raw Kitty image/placement identity becomes public.
- No new production dependency unless separately approved.
- Every behavior change follows RED -> GREEN TDD.
- All C# follows repository 1TBS/Icod formatting conventions.
