# T59 — 0.7.0 Public API, Package, and Stable Closure

**Project:** `Icod.Terminal`  
**Release:** `0.7.0`  
**Status:** Implemented; final PR validation required before merge/tag  
**Predecessor:** T58 — integration, security, and compatibility acceptance

## 1. Purpose

T59 closes the 0.7 OSC 52 milestone without expanding the protocol surface further. The tranche freezes the reviewed public API, teaches it through repository documentation and a focused sample, proves the generated XML documentation and NuGet artifact from a package-only consumer, and moves development metadata to stable `0.7.0`.

## 2. Public API regret audit

The stable 0.7 delta is frozen in `docs/Public-API-Baseline-0.7.md`.

It contains exactly:

- `TerminalClipboardSelection`;
- binary `TerminalSession.WriteClipboardAsync(...)`;
- strict UTF-8 `TerminalSession.WriteClipboardAsync(...)`;
- byte-returning `TerminalSession.ReadClipboardAsync(...)`.

No options object, support-state enum, raw selector string, raw OSC method, implicit text-read helper, automatic retry, or cached capability flag is added.

This surface is considered low-regret because bytes remain authoritative, text encoding is deterministic, reads require explicit per-call opt-in and timeout, and terminal-side support uncertainty is not fabricated into a Boolean capability claim.

## 3. Documentation closure

The repository README is updated for stable 0.7 and documents:

- typed clipboard/primary/secondary/select targets;
- bounded binary and strict UTF-8 writes;
- explicit byte-returning reads;
- privacy and support uncertainty;
- 65,536-byte decoded payload ceiling;
- 87,400-byte OSC 52 frame ceiling;
- 98,304-byte undecoded input ceiling;
- accepted inbound BEL/ST/C1 compatibility forms;
- semantic output/query ownership behavior.

Generated XML documentation already lives on the public enum and session methods. The package verifier now asserts those exact member IDs inside the generated XML for `net8.0`, `net9.0`, and `net10.0`.

## 4. Focused sample

`samples/Icod.Terminal.Clipboard.Sample` demonstrates the intended ordinary flow:

1. open one terminal session;
2. explicitly write caller-provided text to `TerminalClipboardSelection.Clipboard`;
3. explicitly request the same selection with a short caller-visible timeout;
4. handle a terminal that ignores or disables OSC 52 reads without hanging.

The sample does not read the operating-system clipboard and does not imply that write emission proves terminal acceptance.

## 5. Package-only consumer

`tools/package-clipboard-smoke` references only the freshly produced `Icod.Terminal` NuGet package. It does not use a project reference.

For each supported target framework it verifies:

- public `TerminalClipboardSelection` availability;
- exact canonical OSC 52 write bytes;
- absence of implicit write flush;
- exact canonical OSC 52 query bytes;
- mandatory query flush;
- correlated response routing and decoded binary result.

`packaging/VerifyPackageArtifact.ps1` restores and runs that smoke for:

- `net8.0`;
- `net9.0`;
- `net10.0`.

## 7. Release gates

T59 is complete only when the latest PR head proves all of the following:

1. solution restore/build/test succeeds on Windows, Linux, and macOS;
2. the newly added clipboard sample builds for all supported TFMs as part of the solution;
3. Staging package creation succeeds;
4. exact package verification succeeds;
5. generated 0.7 XML documentation contains the reviewed public members for all TFMs;
6. the package-only OSC 52 consumer succeeds under `net8.0`, `net9.0`, and `net10.0`;
7. PR #20 remains mergeable;
8. stable metadata is exactly `0.7.0`.

After those gates are green, PR #20 may be merged to `main`. The `main` Release workflow must then succeed before tag `v0.7.0` is created or packages are published.

## 8. Post-T59 discipline

No additional 0.7 public feature should be added after this tranche. A defect discovered by final validation may be fixed without reopening scope, but any new protocol semantics belong to a later milestone.

The planned successor remains **0.8.0 — cursor-style control and CSI state integration**.
