## 1. Public API closure

No additional public generic CSI or cursor-style protocol surface is accepted for 0.8.

## 2. Stable semantic contract

The six semantic styles remain:

```text
BlinkingBlock     -> DECSCUSR 1
SteadyBlock       -> DECSCUSR 2
BlinkingUnderline -> DECSCUSR 3
SteadyUnderline   -> DECSCUSR 4
BlinkingBar       -> DECSCUSR 5
SteadyBar         -> DECSCUSR 6
```

Inbound omitted/0/1 normalize to blinking block. Positive state outside the frozen set, including xterm parameter 7, is not coerced to a style.

Cursor style remains independent of cursor visibility.

## 3. Restoration and acquisition-failure closure

Scoped restoration is accepted only because the outermost lease observes an actual prior semantic style through DECRQSS before mutation.

The stable lease contract is:

- no mutation when prior state cannot be observed successfully;
- strict-LIFO nested ownership;
- nested acquisition reuses known library-owned state;
- out-of-order release fails without physical-state mutation;
- release failure retains ownership for retry/cleanup;
- if a requested acquisition write reports failure after emission was attempted, the known prior style is written best-effort before the acquisition exception propagates;
- if that recovery also fails, both failures are reported and an outermost known baseline remains owned for disposal retry;
- cancellation before the requested style write commits performs no style mutation;
- suspend restores the observed baseline;
- resume reapplies the active innermost logical style;
- release while suspended emits no style bytes;
- disposal performs final best-effort baseline restoration;
- no guessed reset, hard-coded style, or xterm parameter 7 is used for restoration.

Focused regression coverage now includes failed acquisition output, failed immediate recovery with successful disposal retry, malformed baseline observation, cancellation during baseline observation, zero-timeout no-mutation behavior, and nested lease suspend/resume/unwind.

## 9. Release gate

T87 implementation does not itself authorize tagging.

The stable sequence is:

1. exact hardened PR head is green on Windows, Linux, and macOS;
2. Linux Staging package verification, including 0.8 package XML and package-only smoke, is green;
3. merge PR to `main`;
4. exact `main` Release distribution validation is green across the configured architecture matrix;
5. only then create tag `v0.8.0`;
6. the tag workflow rebuilds, retests, repacks, selects the exact 0.8.0 artifact, reruns package verification, and only then publishes.

Until steps 1 through 4 are satisfied, the branch is stable-versioned but not release-authorized.

## 10. T87 decision

The 0.8 feature/API design is closed. Any new cursor protocol family, synchronized-output policy, generic CSI construction, or broader state-transaction abstraction belongs to a later release.

`0.9.0` remains reserved for synchronized output and nested transactional output state.
