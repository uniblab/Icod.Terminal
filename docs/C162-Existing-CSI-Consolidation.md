# C162 — Existing CSI Consolidation

## Status

Implemented; final Staging validation pending.

C162 migrates existing hard-coded CSI construction and CSI query parsing onto the common C160/C161 grammar stack without changing released public signatures, bytes, transport ownership, or lifecycle semantics.

## Consolidated layers

Existing internal CSI now follows:

```text
output intent
    -> CsiWriter
    -> canonical seven-bit CSI bytes

input response
    -> TerminalControlFrameStructure
    -> TerminalCsiSyntax
    -> TerminalCsiParameterSemantics
    -> protocol-specific interpretation
```

## Query consolidation

DA, DSR, and CPR requests are generated by `CsiWriter` rather than stored as hand-written byte arrays.

Their response matchers parse through `TerminalCsiSyntax` while intentionally preserving the historical broad correlation rule: malformed frames with the expected CSI family/final/private-prefix shape are still claimed by the active query and rejected by the parser instead of leaking into ordinary application input.

The C161 parser remains the semantic authority for required numeric values, bounds, private prefixes, intermediate bytes, and final selectors.

## Canonical output construction

`CsiWriter` now provides reviewed helpers for:

```text
DEC private mode set/reset
Kitty keyboard flags query
Kitty keyboard push
Kitty keyboard pop
DECSCUSR cursor style
synchronized output mode 2026
```

DEC private-mode numeric parameters are emitted through one bounded decimal encoder instead of repeated string literals.

Synchronized output now delegates to the generic DEC private-mode helper for mode 2026.

The Kitty keyboard support probe builds its compound request from:

```text
CsiWriter.EncodeKittyKeyboardQueryFrame()
    +
TerminalCsiQueryProtocol.PrimaryDeviceAttributesRequest
```

so the query and its DA barrier share the canonical CSI construction path.

## Input-protocol ownership

`TerminalInputProtocolManager` uses canonical `CsiWriter` output for the hard-coded protocol portions it owns:

```text
1000  button-event mouse tracking
1002  button-motion tracking
1003  any-motion tracking
1006  SGR mouse encoding
Kitty keyboard push/pop
```

The manager continues to emit those values through its existing `WriteTerminalStringAsync(...)` transition path. C162 therefore does not alter output-gate ownership, cancellation, flush, rollback, suspend/resume, or lease semantics.

## TermInfo boundary

C162 deliberately does **not** reconstruct focus-reporting or bracketed-paste enable/disable sequences from assumed DEC private-mode numbers.

Those operations continue to consume the exact selected TermInfo extended strings:

```text
focus reporting     fe / fd
bracketed paste     BE / BD
```

The corresponding input markers remain:

```text
focus               kxIN / kxOUT
bracketed paste     PS / PE
```

This preserves the 1.5 ownership rule: when TermInfo provides the exact implementation recipe, `Icod.Terminal` consumes that recipe rather than replacing it with a hard-coded terminal-family assumption.

Likewise `XM`, `xm`, and `kmous` continue to decide whether the selected terminal advertises a supported mouse protocol; canonical CSI construction applies only after that capability decision.

## Compatibility

C162 adds no public API.

Byte-exact regression tests retain the released forms for:

```text
CSI c
CSI > c
CSI 5 n
CSI 6 n
CSI ? 1000 h/l
CSI ? 1002 h/l
CSI ? 1003 h/l
CSI ? 1006 h/l
CSI ? 2026 h/l
CSI ? u
CSI > Ps u
CSI < u
CSI Ps SP q
```

Existing session/lease/package tests remain the behavioral acceptance authority for transaction ordering and lifecycle restoration.

## Next tranche

C163 adds typed terminal/cell pixel geometry observation needed by the later Sixel and Kitty Graphics releases. It should build on the shared multi-family query/evidence architecture rather than introduce a graphics-specific input reader.
