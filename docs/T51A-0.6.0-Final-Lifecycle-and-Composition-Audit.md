# T51A — 0.6.0 Final Lifecycle and Composition Audit

**Project:** `Icod.Terminal`  
**Release line:** `0.6.0`  
**Tranche:** T51A — final lifecycle and composition audit  
**Predecessor:** T51 — package, consumer, and stable-release closure  
**Status:** Implementation complete; final PR validation pending

---

## 1. Purpose

T51A is a final pre-publication audit of the stable `0.6.0` candidate. It does not widen the public API or add a new terminal protocol.

The audit identified one ownership gap after T51 first went green: active session-owned OSC 8 hyperlink state was correctly cleaned up during ordinary lease release and session disposal, but it did not yet participate in `TerminalSession`'s suspend/resume lifecycle restoration.

That gap is release-significant because a process suspended while an OSC 8 scope remained physically active could allow shell or job-control output to inherit the application's hyperlink state.

T51A closes that gap and adds one composition regression for bounded hyperlink output inside an existing scoped hyperlink.

---

## 2. Lifecycle ownership model

`TerminalHyperlinkManager` now participates in session lifecycle handling as a core `ITerminalSessionLifecycleParticipant`.

Core participant registration is ordered before user/higher-layer registrations in the internal participant list. Because suspend preparation runs in reverse registration order and resume runs forward, this produces the intended layering:

```text
Suspend:
    higher-layer participant prepare
    ...
    OSC 8 core close
    Terminal rich-input/presentation/host-state release

Resume:
    Terminal host/presentation/rich-input re-entry
    OSC 8 core re-entry
    ...
    higher-layer participant resume
```

The public `RegisterLifecycleParticipant(...)` contract is unchanged.

---

## 3. Physical versus logical hyperlink state

A hyperlink lease stack remains logically owned across managed suspension.

For nested state:

```text
A
B   <- innermost active scope
```

T51A suspend performs exactly one canonical OSC 8 close and retains the logical stack:

```text
OSC 8 close
logical stack still A/B
```

After successful session-state re-entry, resume emits:

```text
OSC 8 begin B
```

Subsequent ordinary release remains strict LIFO:

```text
Dispose B -> OSC 8 begin A
Dispose A -> OSC 8 close
```

The manager therefore restores only library-owned state and still makes no claim about hyperlink state that existed before the session's first OSC 8 begin.

---

## 4. External resume handling

A resume notification may be observed without a preceding catchable suspend, for example after out-of-band terminal or process activity.

In that case Terminal already treats owned state as needing re-entry. T51A applies the same conservative rule to OSC 8: if a logical hyperlink stack is active, the innermost begin frame is emitted again on lifecycle resume.

This is intentionally idempotent at the semantic level and avoids assuming that terminal-side OSC 8 state survived an event the library did not control.

---

## 5. Lifecycle failures

### Suspend close failure

If the canonical OSC 8 close required before suspension fails:

- the manager retains logical ownership;
- cleanup remains required;
- the failure participates in existing lifecycle error handling;
- lifecycle rollback/re-entry may restore the innermost active hyperlink if possible.

### Resume begin failure

If hyperlink re-entry fails after the host/session baseline has begun re-entry:

- the manager keeps cleanup ownership;
- the hyperlink stack remains logically owned;
- the lifecycle operation fails;
- `TerminalSession.IsStateValid` is not set to `true`;
- final session disposal remains authoritative cleanup.

No lifecycle cleanup operation is caller-cancellable.

## 6. Bounded-inside-scoped composition

T51A freezes and tests the following ordinary consumer pattern:

```csharp
await using TerminalHyperlinkLease outer =
    await session.AcquireHyperlinkAsync(
        "https://example.com/outer",
        "outer"
    );

await session.WriteTextAsync( "A" );

await session.WriteHyperlinkAsync(
    "B",
    "https://example.com/inner",
    "inner"
);

await session.WriteTextAsync( "C" );
```

The required wire/state sequence is:

```text
begin outer
A
begin inner
B
begin outer
C
close
```

The bounded convenience method therefore composes correctly with persistent scoped ownership rather than unconditionally closing OSC 8 state.

---

## 7. Internal application-text encoding cleanup

The final audit also removes an unnecessary encoding clone from bounded hyperlink output.

`TerminalHyperlinkManager` now uses an internal `TerminalSession.EncodeApplicationText(...)` helper backed directly by the session-owned cloned application encoding. The public `ApplicationEncoding` property continues returning a defensive clone as before.

This is an implementation cleanup only; no public behavior changes.

---

## 8. Regression coverage

T51A adds deterministic injected-output/lifecycle tests for:

- active single scope close-before-suspend and begin-after-resume;
- external resume re-emitting the active hyperlink;
- nested scopes resuming the innermost state;
- inner release after resume restoring the outer state;
- suspend with no hyperlink producing no OSC 8 output;
- repeated suspend/resume cycles producing one close/begin pair per cycle;
- failed hyperlink re-entry leaving session state invalid;
- bounded hyperlink output inside an outer scope restoring the outer state.

These tests require no real terminal emulator, signals, browser, network, or filesystem access.
