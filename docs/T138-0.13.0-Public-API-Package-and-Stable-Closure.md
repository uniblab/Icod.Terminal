## 2. Public API baseline

`docs/Public-API-Baseline-0.13.md` freezes the stable 0.13 public delta:

- `TerminalColor` with normalized 16-bit RGB channels and explicit value-equality semantics;
- `TerminalPaletteColor` typed index/color pair;
- `TerminalDynamicColor` with seven selected non-Tektronix semantic identities;
- six indexed-palette mutation/query/reset methods;
- three dynamic-color mutation/query/reset methods.

The baseline also records:

- canonical outbound `rgb:rrrr/gggg/bbbb`;
- strict inbound `rgb:` and selected hash grammars;
- active-query correlation and failure semantics;
- common/core versus extended xterm portability tiers;
- terminal-policy reset versus exact restoration distinction;
- deliberately unscoped lifecycle behavior;
- downstream `Icod.DCurses` observation contract;
- explicit non-goals and exclusions.

## 3. README and sample closure

The root README now presents 0.13.0 as the stable release and documents:

- installation at `0.13.0`;
- `TerminalColor` precision;
- indexed palette mutation/observation/reset;
- dynamic-color mutation/observation/reset;
- strict color grammar;
- query semantics;
- reset-versus-restoration semantics;
- T136 no-lease lifecycle decision;
- downstream `Icod.DCurses` consumption;
- current release gates.

A focused `samples/Icod.Terminal.Color.Sample` project demonstrates observation by default. Mutation is opt-in with `--mutate` so simply running the sample does not silently alter terminal color state.

The final pre-merge audit hardened the sample further:

- it is included in `Icod.Terminal.sln`, so normal CI builds it;
- terminal output uses `TerminalSession.WriteTextAsync(...)` rather than `Console.WriteLine(...)`;
- mutation-mode waiting uses `TerminalSession.ReadEventAsync(...)` rather than `Console.ReadLine()` competing with the session-owned input path;
- timeout, malformed correlated reply, and unavailable-query failures are reported as sample output;
- cleanup attempts cursor reset and palette reset independently if mutation succeeded.

The mutation path explicitly describes OSC 104/112 as terminal-policy reset rather than exact restoration.

## 4. Package-only contract

`tools/package-color-smoke` is a fresh package-only consumer with no project reference to repository source.

It compiles against the produced NuGet package and verifies:

- 16-bit `TerminalColor` construction;
- exact 8-bit expansion semantics;
- `TerminalPaletteColor` typed pairing;
- all seven `TerminalDynamicColor` identities;
- compile-time availability/signatures for all nine 0.13 `TerminalSession` color methods.

`packaging/VerifyColorPackage.ps1`:

1. requires the exact `Icod.Terminal.<ExpectedVersion>.nupkg`;
2. opens generated XML documentation for net8.0, net9.0, and net10.0;
3. requires the new public types, key value members, **all seven `TerminalDynamicColor` enum fields**, and all nine session color methods;
4. restores the package-only consumer against the freshly produced artifact plus NuGet dependencies;
5. runs the consumer on net8.0, net9.0, and net10.0.

The verifier is wired into PR Staging package validation, distribution verification, and tagged-release validation.

## 5. Exhaustive palette-index contract

The final pre-merge audit adds exhaustive byte-domain query serialization coverage for every indexed palette value `0..255`.

```text
OSC 4 ; <decimal-index> ; ? ST
```

This complements the existing boundary, mutation, response-correlation, malformed-response, and reset tests.
