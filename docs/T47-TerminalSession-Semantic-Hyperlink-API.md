# T47 — TerminalSession Semantic Hyperlink API

**Project:** `Icod.Terminal`  
**Release line:** `0.6.0`  
**Tranche:** T47 — `TerminalSession` semantic hyperlink API  
**Development version:** `0.6.0-alpha.5`  
**Predecessor:** T46 — OSC 8 writer integration  
**Status:** Implemented; scoped ownership/nesting remains T48

---

## 1. Purpose

T47 introduces the first public OSC 8 operation while keeping OSC selectors,
parameter serialization, framing bytes, and cleanup sequences internal.

The ordinary non-scoped operation is:

```csharp
await session.WriteHyperlinkAsync(
    "project documentation",
    "https://example.com/docs",
    "docs-1"
);
```

The caller supplies application text, an absolute already URI-encoded target,
and an optional semantic hyperlink identifier.

---

## 2. Public API

T47 adds:

```csharp
public ValueTask WriteHyperlinkAsync(
    string value,
    string uri,
    string? identifier = null,
    CancellationToken cancellationToken = default
);
```

It does not expose:

- OSC selector 8;
- raw OSC framing;
- arbitrary parameter dictionaries;
- arbitrary parameter strings;
- a raw begin/end API;
- the internal URI or parameter encoder.

The scoped API remains deliberately deferred to T48 because it introduces
persistent session-owned state, nesting, and disposal semantics beyond the
bounded operation introduced here.

---

## 3. Bounded operation

`WriteHyperlinkAsync(...)` holds the existing session-owned output serialization
boundary across the entire operation:

```text
OSC 8 begin
application text
OSC 8 close
```

This prevents another session-owned semantic operation from being interleaved
inside the bounded hyperlink span.

The application text is encoded with the session's configured
`ApplicationEncoding`, matching `WriteTextAsync(...)` policy.

The OSC frames remain ASCII protocol bytes generated by the T45/T46 layers.

---

## 4. Validation-before-output

Before acquiring the output gate or emitting any byte, T47:

1. validates and canonicalizes the URI through `TerminalHyperlinkEncoder` via
   the T46 frame builder;
2. validates/canonicalizes the optional identifier;
3. constructs the complete begin frame;
4. encodes the complete application text using the session application encoding;
5. constructs the canonical close frame.

Invalid URI/id data therefore emits zero protocol or application bytes.

---

## 5. Endpoint and support semantics

Known redirected output is rejected before OSC output.

When output is an interactive terminal but OSC 8 support is unknown, the
explicit semantic operation is emitted optimistically, consistent with OSC 0/1/2
and OSC 7.

Successful completion proves emission only. It does not prove that the terminal:

- recognized OSC 8;
- rendered the text as a hyperlink;
- recognizes the URI scheme;
- permits activation;
- can reach the target.

`Icod.Terminal` does not dereference or activate the URI.

---

## 6. Cancellation

Caller cancellation is observed:

- before validation/construction;
- before waiting for session-owned output;
- after acquiring the output boundary but before the begin frame is committed.

Once the begin frame is committed, the bounded operation completes its text and
close writes without caller-driven cancellation. This avoids deliberately
leaving terminal hyperlink state open because the caller cancelled between begin
and close.

The T48 scoped API will separately define non-cancellable lease cleanup.

---

## 7. Failure and cleanup

### Begin failure

If the begin write fails, the failure propagates and no cleanup frame is emitted.
The library does not know whether a failing transport consumed a partial frame.

### Application-text failure

If application text fails after begin succeeds, T47 makes one best-effort
canonical close attempt before propagating the application failure.

If cleanup succeeds, the original application failure is rethrown preserving its
exception identity/stack information.

If cleanup also fails, T47 throws an `AggregateException` containing both the
application failure and cleanup failure.

### Close failure

If the normal final close fails, that transport failure propagates.

The bounded method itself does not maintain a persistent hyperlink ownership
stack. Persistent/retryable ownership is the responsibility of T48's scoped
lease design.

---

## 8. Flush behavior

`WriteHyperlinkAsync(...)` does not flush implicitly.

The begin, text, and close writes participate in ordinary output buffering and
the session's existing final deterministic flush policy.

---

## 9. Test evidence

`TerminalSessionHyperlinkTests` proves:

- byte-exact begin/text/end output;
- optional `id` parameter emission;
- percent-escape normalization before framing;
- session application encoding for linked text;
- invalid URI zero-output behavior;
- invalid identifier zero-output behavior;
- redirected-output rejection;
- cancellation-before-transmission zero-output behavior;
- begin-write failure propagation without fabricated cleanup;
- text-write failure followed by best-effort close;
- preservation of the original text failure when cleanup succeeds;
- aggregation when both text and cleanup fail;
- normal close failure propagation;
- no implicit flush.

---

## 10. T47 gate

T47 is complete when the repository matrix proves the public bounded semantic
operation across supported hosts/frameworks.

The next tranche is **T48 — scoped hyperlink lease and nesting**. T48 will add
persistent library-owned hyperlink state, strict-LIFO leases, outer-state
restoration, out-of-order disposal rejection, retryable cleanup semantics, and
session-disposal closure according to the T44 contract.
