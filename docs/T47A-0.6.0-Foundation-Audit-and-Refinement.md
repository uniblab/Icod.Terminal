# T47A — 0.6.0 Foundation Audit and Refinement

**Project:** `Icod.Terminal`  
**Release line:** `0.6.0`  
**Development version:** `0.6.0-alpha.6`  
**Scope:** audit/refinement of T44–T47 before scoped-state implementation  
**Status:** Implemented; T48 remains next

---

## 1. Purpose

Before introducing persistent OSC 8 hyperlink leases in T48, the T44–T47 work
was audited for correctness, contract fidelity, regression risk, and reuse.

The audit found no reason to redesign the 0.6 architecture, but identified three
areas worth correcting before stateful nesting work begins:

1. RFC 3986 authority validation needed to be structural rather than merely
   character-oriented;
2. the T46 framing refactor had introduced an unnecessary intermediate allocation
   on the pre-existing title path and removed useful writer remarks;
3. T47's bounded semantic operation needed explicit output-ordering and
   disposed-session regression evidence.

The audit also confirmed that persistent cleanup ownership after a failed OSC 8
close belongs in the single T48 hyperlink state manager rather than in a second,
parallel T47-only mechanism.

---

## 2. RFC 3986 authority hardening

`TerminalHyperlinkEncoder` now parses RFC 3986 authority structure as:

```text
[ userinfo "@" ] host [ ":" port ]
```

and validates the components independently.

The host supports:

- registered names (`reg-name`);
- bracketed IPv6 literals;
- bracketed IPvFuture literals.

The parser rejects:

- multiple `@` delimiters;
- non-decimal port text;
- multiple unbracketed colon delimiters;
- unbracketed IPv6/IPvFuture hosts;
- malformed bracket placement;
- invalid IPv6 literals;
- malformed IPvFuture syntax;
- text following a bracketed host other than an optional `:<port>`;
- scoped IPv6 zone identifiers, which are outside the frozen RFC 3986 contract.

Percent escapes remain validated without decoding and are normalized only to
uppercase hexadecimal spelling during final URI canonicalization.

This preserves the T44 decision not to route caller data through `System.Uri` or
WHATWG/browser URL normalization while making the documented RFC 3986 claim
materially stronger.

---

## 3. Expanded authority tests

The encoder fixture matrix now includes valid examples for:

- user-info;
- user-info with password-like colon data;
- decimal ports;
- IPv4-looking registered-name hosts;
- bracketed IPv6;
- bracketed IPv6 with port;
- IPvFuture.

Invalid fixtures now include:

- multiple user-info delimiters;
- alphabetic ports;
- multiple unbracketed port/host colons;
- invalid IP literals;
- unterminated bracketed hosts;
- unbracketed IPv6;
- scoped IPv6 zone identifiers;
- malformed IPvFuture forms.

---

## 4. OSC title allocation regression removed

T46's shared framing helpers remain for OSC 7 and OSC 8, but OSC 0/1/2 title
encoding again writes UTF-8 directly into the final frame allocation after the
exact encoded byte count is known.

This restores the pre-T46 single-allocation title behavior instead of allocating
both an intermediate payload array and a final frame.

The internal cancellation/no-partial-frame remarks removed during the T46
refactor have also been restored and extended to the OSC 8 writer methods.

---

## 5. T47 ordering and lifecycle evidence

`TerminalSessionHyperlinkOrderingTests` now explicitly proves that:

- `WriteHyperlinkAsync(...)` waits behind an in-progress application write;
- title and OSC 7 location operations wait until the complete hyperlink
  begin/text/end bounded operation has left the session-owned output boundary;
- the hyperlink operation waits behind an already-held control-output lease;
- a disposed session rejects a new hyperlink operation without output.

These tests complement the existing T47 byte/failure tests and make the public
serialization contract explicit before T48 introduces long-lived scoped state.

---

## 6. T48 unification decision

T47 intentionally remains a bounded convenience operation for this refinement
pass.

T48 SHALL introduce the one authoritative persistent hyperlink state manager and
lease stack. As part of that implementation, `WriteHyperlinkAsync(...)` SHOULD be
refactored to use the same ownership machinery so that a failed final close can
remain represented as session-owned state and be retried by later cleanup or
session disposal.

This avoids creating a temporary second persistent manager merely to replace it
in the immediately following tranche.

---

## 7. Gate

The T44–T47 foundation is ready to proceed to T48 when the refreshed PR matrix is
green with these audit corrections.
