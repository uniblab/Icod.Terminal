# T167A — 0.16.0 Pre-Merge Polish

**Release:** `Icod.Terminal 0.16.0`  
**Status:** Implemented; exact-head validation pending

This addendum records the final pre-merge audit improvements made after the initial T167 stable closure. It adds no public API and does not broaden the OSC 9 protocol scope.

## Validation-order alignment

The frozen T160 contract requires validation/encoding before taking or committing terminal output where practical.

`SendNotificationAsync(...)` and `PublishWindowsCurrentDirectoryCompatibilityAsync(...)` now encode and validate their complete bounded frames before waiting on the shared `TerminalSession` output gate. Valid calls still serialize through the same output domain. After the gate is acquired, the already-validated complete frame is emitted in one `CancellationToken.None` write.

Regression tests hold the control-output lease and prove malformed/control-bearing and oversize inputs fail synchronously instead of queuing behind unrelated terminal output.

## Exhaustive control rejection

Writer tests now iterate the complete forbidden set for both text-bearing OSC 9 forms:

- U+0000 through U+001F;
- U+007F;
- U+0080 through U+009F.

This gives explicit automated coverage for all 65 forbidden code points rather than representative samples only.

## UTF-8 byte-boundary proof

The 4,096-byte notification and 32,768-byte OSC 9;9 payload limits are now tested with multibyte UTF-8 content at the exact boundary and one encoded byte beyond it.

This locks the contract to encoded UTF-8 byte count rather than `.NET string.Length` or UTF-16 code-unit count.

## Focused notification sample

A new `samples/Icod.Terminal.Notification.Sample` project demonstrates only the public `SendNotificationAsync(...)` API using explicit command-line text. It includes a visible privacy/disclosure warning and does not attempt terminal-brand detection or capability probing.

`packaging/VerifyNotificationSample.ps1` restores and builds the focused sample on `net8.0`, `net9.0`, and `net10.0`. That verifier is part of PR Staging validation, distribution/main Release validation, and tagged release validation.

`samples/README.md` now documents the notification sample and the `windows-osc9` mode of `Icod.Terminal.Location.Sample`, including OSC 7 precedence and the deliberate absence of automatic dual publication.

## Shipped-package exclusion audit

The fresh NuGet-only `tools/package-safe-osc9-smoke` consumer still binds both intended public methods and now additionally reflects over the shipped `TerminalSession` type.

It requires:

- `SendNotificationAsync(...)` present;
- `PublishWindowsCurrentDirectoryCompatibilityAsync(...)` present;
- no public method name containing `Osc9`;
- no known generic/raw or hazardous OSC 9 method names such as `WriteOsc9Async`, `ExecuteGuiMacroAsync`, `RunProcessAsync`, environment disclosure, wait-for-key, message-box, sleep, or emulation-mutation entry points.

This carries the T165 public-surface safety invariant into the actual packed artifact on all supported target frameworks.

## Release conclusion

0.16.0 remains a two-method public delta. The pre-merge polish strengthens proof, documentation, and validation without adding protocol features or weakening the deliberate OSC 9 exclusion set.
