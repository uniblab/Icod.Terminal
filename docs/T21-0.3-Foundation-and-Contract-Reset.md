# T21 — 0.3 Foundation and Contract Reset

**Project:** `Icod.Terminal`
**Release line:** `0.3.0`
**Development version:** `0.3.0-alpha.1`
**Tranche:** T21 — foundation and contract reset
**Reference base:** public `0.2.0` release on `main`
**Status:** Complete

---

## 1. Purpose

T21 opens the `0.3.0` development line without changing production terminal
behavior.

The tranche converts the high-level "query/response routing" theme into an
implementation contract strong enough for T22 and T23 to restructure input
routing without inventing policy while code is already in motion.

T21 intentionally adds:

- no concrete active terminal query;
- no second terminal reader;
- no public arbitrary response matcher;
- no automatic terminal probing;
- no new runtime dependency.

## 3. Frozen Query Architecture

### 3.1 Single-reader invariant

Exactly one session-owned path consumes bytes from `ITerminalInput`.

A future query implementation does not create its own input loop and does not
race `TerminalSession.ReadEventAsync` for bytes.

T22 may refactor the internal ownership of the existing decoder, but externally
the session continues to behave as one ordered terminal input stream.

### 3.2 Expectation-driven response interpretation

A response-shaped byte sequence is not a response merely because its syntax
resembles one.

The router may claim an ambiguous frame only while a compatible issued
transaction is outstanding.

This is essential for cursor-position reports. Xterm documents that the normal
CPR response form can overlap modified F3 key sequences. Therefore an
unprompted `CSI ... R` sequence cannot simply be reclassified globally as CPR.

When no matching transaction exists, the established 0.2 decoder semantics
remain authoritative.

### 3.3 Ambiguity-sensitive queries are serialized

Terminal protocols such as CPR provide no transaction identifier.

For such protocols, the session may queue several callers but emits only one
ambiguous request at a time.

The serialization slot covers the complete wire lifetime, including bounded
late-response ownership after caller cancellation or timeout.

### 3.4 Cancellation does not revoke emitted bytes

The architectural contract is:

> Once query bytes have been emitted, caller cancellation does not revoke the
> transaction. The caller may stop waiting immediately, but the session retains
> bounded internal ownership of the outstanding response until it is consumed,
> expires, or the session is terminated. Query families lacking transaction
> identifiers remain serialized across this drain period so late responses
> cannot be misattributed to later requests or ordinary application input.

The caller-facing contract is:

> Terminal queries SHALL follow normal asynchronous caller semantics. Before a
> request is emitted, cancellation prevents transmission. Once a request has
> been emitted, caller cancellation or timeout does not retract the wire request.
> `Icod.Terminal` SHALL retain bounded internal ownership sufficient to recognize
> and discard a late response before permitting an ambiguous subsequent query.
> This cleanup is an implementation detail and SHALL NOT require a second input
> reader or additional work by the caller.

A cancelled or timed-out caller therefore does not automatically release the
wire serialization slot.

### 3.5 Public cancellation and timeout semantics

The future public query API uses ordinary async/await semantics.

Cancellation requested through the caller's `CancellationToken`:

- prevents transmission if observed before request emission;
- completes the caller operation as cancelled;
- uses standard `OperationCanceledException`/cancelled-task semantics.

A caller-visible query timeout:

- is distinct from cancellation;
- completes the caller operation with `TimeoutException`;
- does not retract an already emitted request.

A protocol-defined negative response is neither cancellation nor timeout. It is
a real terminal response and belongs in the typed result contract for that
protocol.

T21 deliberately does not create a generic public `TerminalQueryResult<T>`.
Concrete tranches will expose the smallest typed public contracts justified by
their protocols.

### 3.6 Late-response ownership is bounded and internal

After a caller stops waiting for an emitted ambiguity-sensitive query, the
session retains only enough internal state to recognize and safely consume the
corresponding late response.

That ownership:

- is finite;
- uses monotonic timing;
- cannot remain live indefinitely;
- does not surface as a public drain/quarantine object;
- does not require caller cleanup;
- blocks a later ambiguous request only for its bounded lifetime.

T23 will select and test the concrete default durations. T21 freezes the bounded
semantics, not a numeric compatibility constant.

### 3.7 Ordinary input remains ordinary input

A pending query does not suspend the application input model.

Text, keys, mouse, focus, bracketed paste, and lifecycle events which are not
claimed as the expected response continue through the normal session event path.

If internal demultiplexing requires temporary retention, that retention must
have explicit bounded backpressure. Silent unbounded accumulation is forbidden.

### 3.8 Active probing is explicit

Opening `TerminalSession` does not automatically send DA, DSR, CPR, DECRQSS,
XTGETTCAP, or another active interrogation.

Queries are explicit application/library operations.

This keeps session opening suitable for unusual terminals, redirected setups,
tests, and consumers which do not want unsolicited protocol traffic.

### 3.9 Session-owned control traffic is coordinated

Query request bytes are session-owned control output.

They must not be interleaved byte-for-byte with another
`Icod.Terminal`-generated presentation or input-protocol transition.

T22/T23 may introduce an internal shared control-output gate if necessary.
T21 does not require ordinary application output to be serialized behind every
query.

### 3.10 `Icod.TermInfo` remains immutable capability authority

Live query replies are session observations.

XTGETTCAP or another active probe does not rewrite, replace, or mutate the
session's `TerminalDescription`.

Where a query protocol is not a terminfo capability, `Icod.Terminal` may emit
the protocol's standardized/private request bytes directly. That is protocol
implementation, not a second capability database.

### 3.11 Public protocol extensibility remains deferred

The 0.3 router is allowed to have reusable internal framing and matcher
abstractions.

Those abstractions are not made public merely because they exist.

General public protocol registration remains a later roadmap concern after the
library has implementation experience with CSI, DECRQSS, and XTGETTCAP.

## 4. Resource Policy

Every new query-routing resource must be bounded.

T22/T23 must establish finite limits for:

- incomplete CSI frames;
- incomplete DCS frames;
- numeric parameter count and magnitude;
- DCS payload length;
- queued/pending query count;
- input retained for demultiplexing/backpressure;
- caller-visible timeout policy;
- late-response ownership;
- capability-name/value sizes for protocols such as XTGETTCAP.

T21 does not publish specific numeric limits because no query implementation
exists yet. The first implementation tranches must choose measured defaults and
hard ceilings, and tests must prove those limits.

Numeric defaults remain implementation policy unless later evidence shows that a
specific knob belongs in the public session configuration contract.

---

## 5. Lifecycle Contract

### 5.1 Disposal

Session disposal terminates queued and active query work.

No query transaction survives disposal, and no query cleanup requires the caller
to keep an object alive after session teardown.

### 5.2 Suspend and resume

A pre-suspend request is not allowed to become a successful current query result
after resume merely because its bytes eventually arrive.

T23 must implement bounded suspend/re-entry cleanup so a stale pre-suspend
response cannot:

- become ordinary application input accidentally;
- satisfy a later ambiguity-sensitive query;
- remain retained indefinitely.

The exact implementation remains a T23 concern.

## 6. Protocol Reference Hierarchy

T21 establishes the following authority order for implementation and fixtures.

### 6.1 ECMA-48

**ECMA-48, Fifth Edition, June 1991 — Control functions for coded character
sets**

Reference:

`https://ecma-international.org/publications-and-standards/standards/ecma-48/`

Use ECMA-48 as the primary source for standardized CSI/DCS grammar and the
standard DA, DSR, and CPR control functions.

### 6.2 Digital VT420 documentation

**Installing and Using the VT420 Video Terminal — Programming Summary**

Reference:

`https://vt100.net/docs/vt420-uu/chapter9.html`

Use the DEC documentation as the protocol authority for DECRQSS/DECRPSS syntax
and semantics before applying xterm compatibility behavior.

### 6.3 XTerm control-sequence documentation

**XTerm Control Sequences**

Reference:

`https://invisible-island.net/xterm/ctlseqs/ctlseqs.html`

Use the current xterm documentation for:

- xterm-family DA/DSR/CPR behavior;
- the documented CPR/modified-F3 ambiguity;
- DECRQSS behavior implemented by xterm;
- XTGETTCAP syntax and hexadecimal capability-name encoding.

### 6.4 `Icod.TermInfo`

`Icod.TermInfo` remains authoritative for immutable capability/profile data
already modeled by the Icod stack.

The query implementation does not copy a capability database into
`Icod.Terminal`.

## 7. Test Fixture Direction

T22-T26 should use small literal protocol fixtures traceable to the references
above.

Fixture families should include:

- standard DA/DSR/CPR examples;
- CPR-shaped modified-F3 input;
- DEC-private DSR/CPR forms where supported;
- valid and invalid DECRQSS replies;
- valid, negative, malformed, and oversized XTGETTCAP replies;
- 7-bit ESC-prefixed and deliberately selected 8-bit C1 forms;
- arbitrary fragmentation across every byte boundary;
- ordinary input before, between, and after response frames.

No ordinary unit test needs a physical VT terminal or an interactive CI runner.

## 8. Compatibility

T21 changes package-development metadata and documentation only.

It adds no production behavior and no public API member.

A 0.2 consumer using:

- terminal sessions;
- semantic input modes;
- keyboard/text input;
- mouse/focus/paste;
- lifecycle events;
- presentation leases;
- input-protocol leases;

continues to use the same production implementation in `0.3.0-alpha.1`.
