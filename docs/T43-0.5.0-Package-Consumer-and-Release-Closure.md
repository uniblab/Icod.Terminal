## 1. Purpose

T43 closes the `0.5.0` development line after T37–T42 established, implemented,
and audited the OSC 7 current-location publication contract.

This tranche does not add another terminal protocol or widen the public API. It
promotes the reviewed `0.5.0-alpha.7` contract to stable package metadata and
extends package-only consumer validation so the OSC 7 public surface is compiled
and exercised from the produced NuGet package itself on every supported target
framework.

A final release audit after the first green stable candidate identified two
validation gaps and two documentation inconsistencies. Those corrections are
part of T43 closure rather than new protocol scope.

## 4. Final release-audit hardening

The final audit tightens implementation behavior to match the already-frozen
T37/T42 contract.

### 4.1 Control characters in native paths

Native path text containing C0, DEL, or C1 control characters is rejected before
URI construction. These characters are not converted to `%00`, `%1B`, `%85`, or
other percent-encoded forms.

This restores exact agreement with the T37 rule that terminal-control-capable
characters are rejected before URI construction rather than normalized into an
apparently harmless representation.

Internal encoder tests and public `TerminalSession` tests both prove that such
inputs fail with zero terminal writes.

### 4.2 Scoped IPv6 authorities

The 0.5 authority contract supports ordinary ASCII DNS names, IPv4 literals, and
bracketed unscoped IPv6 literals. It does not define URI zone identifiers.

The encoder therefore rejects literal `%` authority text, including:

```text
[fe80::1%eth0]
[fe80::1%25eth0]
```

This avoids accidentally freezing parser- or platform-specific zone-id behavior
before a later release deliberately defines it.

### 4.3 Documentation consistency

The package README is updated to identify `0.5.0` as the stable release and to
show the stable `0.5.0` installation command. The samples README now lists the
0.5 package-location smoke consumer alongside the general and 0.4 title package
smokes.

## 5. Package-only OSC 7 consumer

T43 adds a dedicated fresh package consumer under:

```text
tools/package-location-smoke/
```

The project references `Icod.Terminal` only as a NuGet package whose version is
injected by the package-validation script. It does not reference the repository
library project.

The consumer opens an injected interactive `TerminalSession` and exercises the
stable public API with:

- POSIX path + explicit authority;
- Windows drive path;
- Windows UNC path;
- spaces;
- non-ASCII Unicode;
- literal percent-escape-looking native path data.

It verifies exact concatenated OSC 7 bytes and proves that publication does not
flush output implicitly.

## 10. Final stable validation sequence

Stable `0.5.0` is accepted only after the following sequence succeeds:

1. post-audit T43 PR validation passes on Windows, Linux, and macOS;
2. Linux Staging packaging creates the stable `Icod.Terminal 0.5.0` artifacts;
3. exact package verification passes;
4. the general, title, and OSC 7 fresh package consumers all pass for `net8.0`,
   `net9.0`, and `net10.0`;
5. PR #16 is merged from the dedicated `0.5.0` branch into `main` only after the
   final candidate is green;
6. the ordinary `main` Release validation passes for the merged commit;
7. the eventual `v0.5.0` tag points to a commit contained in `main`;
8. the tag-controlled release workflow rebuilds, retests, re-verifies, publishes,
   and creates release assets.

The stable package SHALL NOT be published manually from the working branch.

## 12. T43 completion gate

T43 implementation is complete when the stable package candidate contains the
T37–T42 implementation plus the final safety/documentation audit corrections,
and fresh package consumers prove both the existing API surface and the new OSC
7 surface through the produced NuGet package.

`Icod.Terminal 0.5.0` itself is release-complete only after PR, `main`, and tag
validation plus package publication succeed.

After stable publication, the next planned release line is `0.6.0`, whose
protocol focus is OSC 8 hyperlinks, structured OSC parameters, and scoped
begin/end output state built on the URI foundation proven by 0.5.
