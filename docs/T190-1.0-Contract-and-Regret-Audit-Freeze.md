# T190 — 1.0 Contract and Regret-Audit Freeze

**Release:** `Icod.Terminal 1.0.0-rc1`  
**Base:** published `0.18.0` merged to `main` at `c0f0ff482c8bb0d358c4fcb38e454d717b1b6f1c`  
**Baseline validation:** workflow #908  
**Correction validation:** workflow #911  
**Status:** Complete

## 1. Why T190 exists

`0.18.0` established a heavily tested behavioral baseline. `1.0.0-rc1` has a different responsibility: decide which parts of that pre-1.0 surface are suitable to support as a durable 1.x contract and make those decisions discoverable without reconstructing eighteen release histories.

T190 therefore precedes all permanent rc1 documentation and applies a deliberately high bar to public-contract corrections.

No public API is renamed, removed, broadened, or added during rc1 merely because a different design is aesthetically preferable. A change requires a concrete long-term support reason.

## 2. Decision classes

Every audit observation is classified as one of:

### A — freeze as-is

The API/behavior is coherent, testable, documented or straightforward to document, and supportable throughout 1.x.

### B — documentation defect

The runtime contract is acceptable, but XML documentation, README/sample guidance, package metadata, or permanent documentation is incomplete, stale, contradictory, or overly release-specific.

Prefer documentation correction over API change.

### C — test/acceptance defect

The contract is supportable but an important invariant lacks direct regression/package/downstream proof.

Prefer tests or acceptance expansion without surface change.

### D — final pre-1.0 API correction

The existing public surface is materially misleading, duplicate, unsafe, impossible to support compatibly, or located at the wrong abstraction layer.

Any D-class change must document:

- the concrete regret if left unchanged;
- compatibility impact;
- migration path;
- why documentation alone is insufficient;
- why deferring to 2.0 would be worse than correcting before 1.0.

### E — defer beyond 1.0

A desirable feature or cleanup is not necessary to support the existing contract safely and coherently. It is not rc1 work.

## 4. Frozen architectural boundaries

The audit confirms these 1.0 boundaries:

- `Icod.TermInfo` owns immutable terminal capability data and expansion;
- `Icod.Terminal` owns live endpoint/session state, input, queries, lifecycle, semantic terminal output, and reversible terminal state;
- `Icod.DCurses` owns virtual-screen/cell/window/refresh policy;
- future `Icod.Pty` remains adjacent and optional rather than a dependency of `Icod.Terminal`;
- application command policy remains above the terminal substrate.

## 5. Frozen safety principles

The following are permanent presumptions for the 1.0 contract:

- no generic raw escape-sequence writer as the normal API;
- no arbitrary OSC/vendor command dispatcher;
- no blind activation of terminal state that cannot be observed or restored truthfully;
- exact captured-state restoration where ownership claims require it;
- semantic APIs above native flag manipulation for ordinary consumers;
- bounded incremental parsing;
- one authoritative session-owned input reader/query-correlation path;
- pre-commit cancellation emits nothing where the contract promises atomic framing;
- post-commit operations do not invent compensating traffic unless the owning contract defines rollback;
- state uncertainty is surfaced rather than silently converted into believed success;
- platform differences remain observable rather than fabricated.

## 6. Compatibility policy frozen by T190

T190 closes with these presumptions for T195 to formalize:

- `net8.0`, `net9.0`, and `net10.0` remain supported for 1.0;
- vendor end-of-support alone is not sufficient reason to remove a TFM during rc1;
- current public enum numeric values become the 1.x baseline after comprehensive T194 verification;
- public API removed or renamed during rc1 requires migration guidance;
- behavior explicitly frozen in 0.18 does not change silently;
- package-only consumers and real DCurses acceptance remain mandatory release evidence.

## 7. Documentation authority policy

Historical documents remain valuable evidence, but rc1 ends the need to search tranche notes for current truth.

Permanent documents created by T191–T195 become the primary supported-contract authorities. Versioned roadmaps and `Txxx` records remain historical/design records and must not contradict permanent documentation.

Known B-class cleanup includes:

- `Icod.Terminal.csproj` package release notes still describing 0.16.0;
- the original `Icod.Terminal-Development-Roadmap.md` presenting a much earlier development state;
- `samples/README.md` remaining heavily organized around historical release numbers;
- release-specific XML prose that should become durable 1.0 wording.

## 8. D-class correction accepted by T190

T190 found exactly one public member that fails the 1.x supportability test:

```text
TerminalSession.Input
```

`ITerminalInput` remains public as a caller-supplied transport interface, and the custom `OpenAsync(...)` injection overload remains public. The live session no longer returns that transport publicly because a competing raw reader can steal bytes from the decoder/query-router and make the session's single-reader guarantees impossible to uphold.

The correction is covered by `TerminalSessionPublicSurfaceFreezeTests` and passed Windows/Linux/macOS, real DCurses acceptance, exact package validation, and retained 0.8–0.18 package gates at workflow #911.

No additional D-class correction was justified by the completed T190 scan.

## 9. Deferred C-class freeze work

T190 found that enum-value compatibility tests are selective rather than comprehensive. T194 therefore owns an exact 1.0 public-surface and public-enum numeric baseline.

The authoritative values to freeze are the **current rc1 values**, not superseded early-pre-1.0 layouts that evolved intentionally before later compatibility policy was established.

## 10. Closure

T190 exit criteria are satisfied:

3. the sole D-class correction has written rationale, migration impact, and direct regression coverage;
4. permanent-document targets are confirmed;
5. stale repository/package/sample authorities have cleanup tranches;
6. no feature expansion entered rc1;
7. baseline workflow #908 and corrected exact-head workflow #911 are green.
