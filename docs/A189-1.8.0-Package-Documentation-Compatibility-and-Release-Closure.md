## Release behavior being qualified

The single public raster operation now routes through two internal protocol backends:

```text
RasterGraphics
    -> verified ApcKittyGraphics
    -> verified DcsSixel
```

The release-facing documentation must describe the qualified implementation rather than the original roadmap intention:

- Kitty Graphics is an APC dialect beneath the existing semantic raster operation;
- direct raw transfer (`t=d`) is used;
- RGB24 and RGBA32 are transmitted directly;
- Indexed8 expands deterministically to RGB24 or RGBA32 as required by palette alpha;
- Base64 payload chunks are bounded to 4096 bytes;
- the complete logical Kitty transfer is serialized as one committed session transaction even though it contains multiple APC frames;
- caller cancellation is honored before commitment and cannot intentionally truncate a committed transfer;
- partial transport failure is surfaced without replay or backend switching;
- Kitty support is established by a correlated protocol query plus Primary DA barrier, not terminal identity;
- verified Kitty is preferred and verified Sixel remains fallback;
- fractional alpha is preserved through Kitty and remains controlled unsupported through Sixel;
- source raster dimensions remain intrinsic; 1.8 adds no placement/scaling/cursor-normalization API;
- correlated malformed or oversized Kitty responses remain bounded transaction-owned input rather than leaking into application input.


The dependency floor remains:

```text

```

The fresh NuGet-only raster consumer remains intentionally protocol-neutral. It proves that a consumer can compile and run against the same public `TerminalRasterImage` / `DisplayRasterAsync(...)` surface used by both 1.8 backends, that raster storage remains snapshot-owned, and that protocol-specific escape hatches are absent from the package.

The package smoke exclusion set must cover both sides of the implementation:

- no raw/public DCS or Sixel writer;
- no raw/public APC or Kitty Graphics writer;
- no public protocol-specific raster display selector;
- no public mutable pixel/palette backing storage.

Normal runtime tests provide the internal multi-backend routing, probe, transaction, and hardening witnesses that a NuGet-only public-surface smoke project cannot access.

## Security closure

The permanent security authority must include the 1.8-specific conclusions:

- terminal APC/Kitty replies are untrusted input;
- correlation establishes bounded ownership, not trust;
- matching response identifiers do not bypass grammar or size validation;
- malformed/aborted correlated responses fail the probe;
- oversized correlated responses are drained through bounded string resynchronization;
- an identified but unterminated response is malformed rather than silent uncertainty;
- unrelated control traffic does not satisfy the active probe;
- direct transport avoids hidden filesystem/temp-file/shared-memory side effects;
- graphics output is validated before commitment where possible;
- no automatic retry occurs after partial committed output;
- image-file decoding/transcoding remains out of scope.

## Compatibility closure

The permanent compatibility authority must explicitly record that 1.8 is a behavioral/backend expansion beneath the unchanged 1.7 public raster API.

The release continues to preserve:

- stable `1.0.0` compatibility floor;
- all public 1.0–1.7 members and enum numeric values;
- one-reader query ownership;

- truthful capability uncertainty;
