# T12D — 0.1.0 Release Closure

**Project:** `Icod.Terminal`
**Release:** `0.1.0`
**Tranche:** T12D — release closure
**Release branch:** `main`
**Publication tag:** `v0.1.0`
**Status:** Complete — `v0.1.0` published successfully

---

## 1. Purpose

T12D closes the consumer-driven `0.1.0` foundation without adding new terminal
behavior. The implementation, public API review, ProcPs acceptance work, and
package-only consumer validation are already complete. This tranche converts
the final prerelease package into the first non-prerelease release and makes
publication an explicit tag-controlled operation.

No mouse, focus, bracketed-paste, query/router, PTY, or other post-0.1 feature
is part of this closure.

---

## 2. Final version identity

The release commit declares:

```xml
<Version>0.1.0</Version>
<AssemblyVersion>0.1.0.0</AssemblyVersion>
<PackageVersion>0.1.0</PackageVersion>
```

`Version` and `PackageVersion` must remain identical. The assembly identity
remains `0.1.0.0` as established throughout the 0.1 development line.

---

## 3. Release contents

`0.1.0` establishes the reusable live-terminal substrate required by the first
production consumers. The release includes:

- deterministic `TerminalSession` ownership and restoration;
- endpoint observation and low-level terminal-control contracts;
- canonical, cbreak, raw, and echo input-mode policy;
- terminal identity and `Icod.TermInfo` profile integration;
- current terminal dimensions and lifecycle/resize handling;
- incremental Unicode and terminal-key input decoding;
- reversible full-screen, cursor, and keypad presentation leases;
- suspend/resume lifecycle-participant integration used by `Icod.DCurses`;
- package-only consumption for both `net8.0` and `net10.0`;
- Windows, Linux, and macOS validation.

The runtime package dependencies remain exactly:

```text
Icod.TermInfo 1.0.0
Icod.Timing   1.0.0
```

---

## 4. Publication policy

Ordinary pushes to `main` perform Release validation only. They do not publish
NuGet or GitHub Packages artifacts.

After this release commit has passed the normal `main` validation matrix, create
and push the annotated release tag:

```text
git tag -a v0.1.0 -m "Icod.Terminal 0.1.0"
git push origin v0.1.0
```

The tag workflow must then:

1. require the tagged commit to be contained in `main`;
2. require tag `v0.1.0` to match both project version properties;
3. rerun clean/restore/build/test/pack and package verification on Windows,
   Linux, and macOS;
4. publish `Icod.Terminal 0.1.0` to NuGet.org;
5. publish the package to GitHub Packages;
6. create SHA-256 checksums for the NuGet and symbol packages;
7. create the GitHub Release and attach the `.nupkg`, `.snupkg`, and checksum
   file.

The `v0.1.0` tag workflow completed successfully. It validated the release on
Windows, Linux, and macOS, published the package to NuGet.org and GitHub
Packages, and created the GitHub Release with the package, symbol package, and
SHA-256 checksum file.

## 5. Closure

T12D is complete. `0.1.0` is the released baseline for the live-terminal
foundation, and the repository may advance to the `0.2.0` rich-input line
without reopening the `0.1.0` feature scope.
