### 4.1 Final interactive-sample review

Before the merge to `main`, the repository adds one final consumer-facing
artifact: `samples/Icod.Terminal.RichInput.Sample`.

The sample makes the 0.2 contract directly observable on a real terminal without
adding production API or a second decoder. It:

- requests bracketed paste, focus reporting, and button mouse tracking through
  one reversible `TerminalInputProtocolLease`;
- treats an unavailable compound protocol request as a controlled result;
- consumes every event through `TerminalSession.ReadEventAsync`;
- prints normalized text, key, mouse, focus, paste, and lifecycle events;
- identifies mouse coordinates as zero-based;
- preserves paste Begin/Data/End framing rather than accumulating an unbounded
  paste string;
- exits on `q`, `Q`, Escape, end-of-input, interrupt, or termination;
- releases the protocol lease before session disposal.

The existing `Icod.Terminal.Sample` remains the intentionally minimal
session/identity/size example. The rich-input sample complements it rather than
replacing it.

This sample is included in `Icod.Terminal.sln`, so the final PR and `main`
validation matrices compile it for `net8.0`, `net9.0`, and `net10.0`.

## 5. Final stable validation

After this patch is committed to branch `0.2.0`:

1. run the normal local Debug/Staging/Release build and test sequence;
2. require the PR Staging matrix to pass on Windows, Ubuntu, and macOS;
3. merge the stable release commit to `main`;
4. require the ordinary `main` Release validation to pass;
5. verify that `main` contains the exact stable release commit;
6. create the annotated `v0.2.0` tag only then.

No package is manually pushed from the development branch.

---

## 6. Publication

From a checkout whose `main` points at the validated stable release commit:

```text
git tag -a v0.2.0 -m "Icod.Terminal 0.2.0"
git push origin v0.2.0
```

The tag-controlled release workflow must:

- confirm that the tagged commit is contained in `main`;
- confirm tag/version/package-version agreement;
- rebuild and retest on Windows, Ubuntu, and macOS;
- regenerate and verify the Release package;
- publish the canonical package to NuGet.org;
- publish the same package to GitHub Packages;
- create SHA-256 checksums;
- create the GitHub Release and attach the package, symbol package, and
  checksums.

## 7. Release gate

`Icod.Terminal 0.2.0` is accepted only when the `v0.2.0` workflow completes
successfully.

At that point:

- T13-T20 are complete;
- `0.2.0` is the stable rich-input release;
- downstream `Icod.DCurses` may replace its prerelease Terminal dependency with
  stable `Icod.Terminal 0.2.0`;
- the next Terminal development milestone may begin from the published stable
