---

## 1. Purpose

T36 closes the `0.4.0` development line after T29–T35 established and audited
the OSC 0 / OSC 1 / OSC 2 title-operation contract.

This tranche does not add another terminal protocol. It converts the reviewed
`0.4.0-alpha.7` contract into the stable `0.4.0` package candidate and extends
the package-only consumer gate so the new public title API is exercised from the
produced NuGet package itself on every supported target framework.

A final pre-release audit also adds three closure improvements without changing
the production protocol design:

- package validation now requires XML documentation for all three public 0.4
  title methods on every supported target framework;
- a focused interactive `Icod.Terminal.Title.Sample` demonstrates the semantic
  OSC 0/1/2 API and explicitly documents that prior title state is not queried or
  restored;
- a parameterized public semantic contract test suite applies the common
  payload-size, injection, and output-failure rules independently through OSC 0,
  OSC 1, and OSC 2.

## 3. Stable 0.4 contract

Stable 0.4 includes:

- semantic `TerminalSession.SetTitleAsync(...)` mapped to OSC 0;
- semantic `TerminalSession.SetIconNameAsync(...)` mapped to OSC 1;
- semantic `TerminalSession.SetWindowTitleAsync(...)` mapped to OSC 2;
- canonical 7-bit `ESC ]` OSC introduction;
- canonical `ESC \\` String Terminator emission;
- strict UTF-8 title payloads;
- rejection of C0, DEL, and C1 control characters;
- rejection of malformed UTF-16 input;
- a 4096-byte encoded title-payload ceiling;
- validation-before-write behavior;
- no public raw OSC-selector escape hatch;
- terminal-endpoint policy which avoids emitting title OSC to a known redirected
  output endpoint;
- emission-oriented success semantics without fabricated terminal-side support
  or state ownership;
- session-owned ordering between semantic title operations, ordinary
  `WriteTextAsync(...)`, active queries, presentation transitions, and rich-input
  protocol transitions;
- no implicit flush for title operations;
- rejection of new high-level application/title output once session disposal
  begins;
- deterministic final flush/restoration during session disposal.

The T35 reviewed API baseline remains authoritative:

- [`Public-API-Baseline-0.4.md`](Public-API-Baseline-0.4.md)

## 4. Package-only OSC title consumer

T36 adds a dedicated package-only consumer under:

```text
tools/package-title-smoke/
```

The consumer references `Icod.Terminal` only through the generated NuGet
package. It opens an injected interactive session and calls all three public
semantic title methods:

```csharp
await session.SetTitleAsync( "both" );
await session.SetIconNameAsync( "icon" );
await session.SetWindowTitleAsync( "window" );
```

It verifies the exact emitted bytes:

```text
ESC ] 0 ; both   ESC \
ESC ] 1 ; icon   ESC \
ESC ] 2 ; window ESC \
```

and verifies that the title operations do not flush implicitly.

This gives the stable release gate direct package-level evidence that the public
0.4 API is present, callable, and wired to the intended selectors.

This extends the established package verifier rather than relying only on source

## 6. Public semantic contract matrix

The final audit adds
`TerminalSessionTitleContractTests` as a compact parameterized suite over all
three public operations.

For OSC 0, OSC 1, and OSC 2 independently it verifies:

- exactly 4096 encoded ASCII payload bytes are accepted;
- 4097 encoded bytes are rejected before output;
- representative ESC/OSC injection text is rejected before output;
- a transport `IOException` is propagated without translation.

These tests complement, rather than duplicate, the byte-exact `OscWriterTests`
and the selector-specific T31/T32/T33 suites.

## 7. Interactive 0.4 sample

A focused sample is added under:

```text
samples/Icod.Terminal.Title.Sample/
```

It demonstrates all three stable semantic methods on a live terminal and is
included in `Icod.Terminal.sln` so ordinary Debug/Staging/Release builds compile
it on all supported target frameworks.

The sample documentation intentionally emphasizes the title-state ownership
boundary:

- the previous title is not queried;
- successful calls prove emission, not emulator application;
- `DisposeAsync()` does not pretend to restore unknown prior title state.

The sample remains a repository consumer and is not included in the NuGet
package payload.

## 8. Multi-target fresh-consumer gate

`packaging/VerifyPackageArtifact.ps1` restores and runs two independent fresh
package consumers from an isolated NuGet package cache:

1. the established general package smoke consumer;
2. the dedicated OSC 0/1/2 title smoke consumer.

Both consumers run against:

```text
net8.0
net9.0
net10.0
```

The package source order remains the freshly packed artifact directory followed
by NuGet.org for transitive dependencies. There is no project reference back to
the repository source tree.

The package validation path requires:

- exactly one matching `.nupkg`;
- the matching `.snupkg`;
- expected package metadata and README/icon assets;
- exactly the supported managed assembly payloads;
- dependency closure for `Icod.TermInfo 1.4.1` and `Icod.Timing 1.0.0`;
- portable symbols;
- Source Link metadata;
- generated XML documentation, including the complete public 0.4 title trio;
- stable assembly identity agreement across all target frameworks.

## 10. Final stable validation sequence

The stable `0.4.0` release is not accepted merely because this commit exists.
The final sequence is:

1. require the final T36 PR validation matrix to pass on Windows, Linux, and
   macOS;
2. require the Linux package-validation job to pack `Icod.Terminal 0.4.0`, verify
   the generated 0.4 XML API members, and run both fresh consumers for `net8.0`,
   `net9.0`, and `net10.0`;
3. require the solution build to compile the new title sample on all supported
   target frameworks;
4. merge the accepted PR to branch `0.4.0` / the intended integration path;
5. require the ordinary Release validation for the merged commit to pass;
6. ensure the eventual `v0.4.0` tag points at a commit contained in `main`;
7. allow the tag-controlled release workflow to rebuild, retest, verify, and
   publish the package.

Do not publish the stable package manually from the feature branch.
