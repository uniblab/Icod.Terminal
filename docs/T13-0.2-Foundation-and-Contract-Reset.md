# T13 — 0.2 Foundation and Contract Reset

**Project:** `Icod.Terminal`
**Development line:** `0.2.0`
**Development version:** `0.2.0-alpha.1`
**Tranche:** T13 — foundation and contract reset
**Reference branch:** `0.2.0`
**Status:** Implementation prepared; validation gate pending

---

## 1. Purpose

T13 opens the `0.2.0` development line without changing live terminal runtime
behavior.

The `0.1.0` foundation is released and remains the behavioral baseline. T13
performs the repository, versioning, documentation, and package-validation
reset needed before the rich-input public contract begins in T14.

---

## 2. Version identity

T13 establishes:

```xml
<Version>0.2.0-alpha.1</Version>
<AssemblyVersion>0.2.0.0</AssemblyVersion>
<PackageVersion>0.2.0-alpha.1</PackageVersion>
```

`Version` and `PackageVersion` remain identical.

The assembly identity advances to `0.2.0.0` with the new minor development
line rather than retaining a validation assumption tied to the released
`0.1.0` assembly.

---

## 3. Framework and dependency baseline

The `0.2.0` line supports:

```text
net8.0
net9.0
net10.0
```

The runtime dependency baseline remains:

```text
Icod.TermInfo 1.0.0
Icod.Timing   1.0.0
```

No dependency update is required merely to open the 0.2 development line.

---

## 4. Package-verifier reset

The package verifier previously carried the `0.1.0.0` assembly version as a
hard-coded constant. That made a correct `0.2.0.0` assembly look invalid even
when the project metadata and packed assemblies agreed.

T13 changes the verifier so that it:

1. reads `Version`, `PackageVersion`, and `AssemblyVersion` from
   `Icod.Terminal.csproj`;
2. requires `Version` and `PackageVersion` to remain present and identical;
3. requires `AssemblyVersion` to be present and parse as a valid assembly
   version;
4. verifies every packaged target-framework assembly against that declared
   assembly version.

The verifier therefore continues to catch package-identity drift while no
longer embedding a release-line-specific assembly number in source code.

---

## 5. Runtime scope

T13 intentionally adds no mouse, focus, bracketed-paste, richer-key, or other
rich-input runtime behavior.

Those contracts begin in T14 after the 0.2 version and validation foundation
is established.

This preserves a clean distinction between:

- T13 — repository/version/package-validation reset;
- T14 — rich-input event and decoder-policy contract;
- later tranches — protocol enablement and decoding implementations.

---

## 6. Validation gate

T13 is complete only when the `0.2.0-alpha.1` state passes:

```text
clean
restore
build
test
pack
package verification
fresh package consumer
```

for the supported repository configurations and CI hosts, including package
payload and fresh-consumer coverage for `net8.0`, `net9.0`, and `net10.0`.

Until that validation succeeds, T13 remains the current tranche and T14 does
not begin.

---

## 7. Exit state

After the gate passes, the repository will have:

- a clean `0.2.0-alpha.1` development identity;
- assembly identity `0.2.0.0`;
- three-framework package validation;
- no hard-coded `0.1.0.0` package-verifier assumption;
- documentation that records `0.1.0` as released and T13 as the active 0.2
  foundation.

The next tranche is T14 — Rich Input Event Model and Decoder Policy.
